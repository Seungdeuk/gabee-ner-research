# R11 문형 틀(frame) 작성 명세 (학습·Validation·Development 공통, 역할별 지시는 작업 요청에 있음)

가족 메신저(가족 단톡·1:1 대화)에서 개인정보(사람 이름)를 가리는 한국어 NER 모델용 **문장 틀**을 만든다. 틀은 슬롯이 든 한국어 문장이며 별도 생성기가 슬롯에 이름·별명·호칭·단어를 채워 문장을 만든다. 모든 문장은 합성이다. 실제 가족 대화·실제 개인정보를 쓰지 않는다.

**작업 제한(중요)**: 이 명세 파일과 지정된 출력 파일 외의 어떤 파일·폴더도 열거나 읽지 마라(저장소의 다른 데이터, 평가셋, 기존 틀 파일, `sealed` 폴더, 다른 R11 틀 파일 포함). 출력은 지정된 경로에 JSON 파일 하나로 쓴다. 인터넷·외부 도구를 쓰지 않는다. 다른 작성자가 같은 일을 따로 하고 있으니 서로 겹치지 않게 **자신의 담당 어휘·장면 지시를 지켜라.**

## 출력 형식

JSON 배열, 항목마다 아래 필드(UTF-8). `id` 는 담당 접두어 + 3자리 번호이고 파일 안에서 고유하다.

```json
{"id": "r11xx-001", "scenario": "일정·약속", "text": "내일 모임 총무는 {N1:bare}", "tags": ["B1"]}
```

대조쌍 파일만 `pair_id`(예: `p-001`)와 `role`(`person` 또는 `noun`)이 더 있다. 한 쌍은 항목 2개이고 `tags` 에 `minimal`(같은 뼈대 최소 대조쌍) 또는 `free`(다른 뼈대 쌍)를 쓴다.

- 같은 파일 안에서 `text` 가 중복되면 안 된다. **문장 구조·말투·목적·길이가 서로 달라야** 한다. 단어 하나만 다른 같은 구조를 반복하지 마라.
- 슬롯 바깥의 모든 글자는 일반 한국어 어휘여야 한다. 틀 안에 구체적인 사람 이름·유명인·상호·실제 지명을 쓰지 마라(이름·지명은 슬롯으로만).

## 슬롯(대소문자 정확히)

| 슬롯 | 채워지는 것 | 라벨 |
|---|---|---|
| `{N1:k}` `{N2:k}` `{N3:k}` | 사람 이름(2~4글자, 성 있거나 없음) | PERSON |
| `{AL1:k}` `{AL2:k}` | 사람을 가리키는 별명·애칭(2~3글자) | PERSON_ALIAS |
| `{NK1:k}` | 이름 + 가족 호칭(이름 엄마, 이름 할머니 등). 이름 부분만 라벨 | PERSON(이름만) |
| `{K1:k}` `{K2:k}` | 가족 호칭 단독(엄마, 아빠, 할머니, 이모, 삼촌 등) | 라벨 없음 |
| `{W1:k}` | 일반 명사(자연물·사물·계절 등) | 라벨 없음 |
| `{NW1:k}` | 일반 명사와 같은 글자의 **사람 이름**(사람으로 쓰인 문맥에서만) | PERSON |
| `{WN1:k}` | 위와 같은 글자의 **일반 명사**(명사로 쓰인 문맥에서만) | 라벨 없음 |
| `{L1}` `{L2}` | 지명·랜드마크(조사는 틀에 직접 적는다) | 라벨 없음 |
| `{O1}` `{O2}` | 병원·학교·학원·회사 등 기관 이름(조사는 틀에 직접 적는다) | 라벨 없음 |

`:k` 는 슬롯 바로 뒤에 붙는 조사 종류다. 생성기가 받침에 맞춰 붙인다.

- `sub`(이/가), `top`(은/는), `obj`(을/를), `com`(랑·하고·와), `dat`(한테·에게), `voc`(아/야 호격), `pos`(의)
- `bare`: 조사 없음. 슬롯 바로 뒤가 공백·쉼표·문장부호·문장 끝(또는 이모티콘)이어야 한다.
- `lit`: 조사를 붙이지 않고 틀에 직접 쓴 글자가 바로 이어진다(예: `{N1:lit}씨는`, `{N1:lit}라는 아이`, `{N1:lit}{N2:sub}`).

같은 슬롯 이름(`{N1:..}`)을 한 문장에 두 번 쓰지 마라. 두 사람이면 `N1`, `N2`.

## 정책(r9-1.1)

- 이름은 이름 부분만 PERSON. 가족 호칭은 라벨 없음. 이름 뒤 호칭은 `{NK1:k}`, 호칭만 있으면 `{K1:k}`(보호할 이름이 없으면 음성).
- PERSON_ALIAS 는 실제 별명·애칭 자체만. `이름+호칭`을 별명 슬롯으로 쓰지 마라. 조사·호칭·따옴표는 슬롯 밖.
- **1글자 이름이 연상되는 문장 금지.** 이름 슬롯은 2글자 이상.

## 대조쌍(`pair_*`) 작성 규칙

한 쌍 = 같은 단어가 **사람 이름으로 쓰인 문장(`person`, `{NW1:k}`)** 과 **일반 명사로 쓰인 문장(`noun`, `{WN1:k}`)**. 생성기가 한 쌍의 두 문장에 같은 단어를 채운다.

- **`minimal`**: 두 문장이 거의 같은 뼈대이고 사람/명사를 가르는 **문맥 단서만** 다르다(예: 사람 문장은 "{NW1:sub} 도착했대"처럼 사람 행동, 명사 문장은 "{WN1:sub} 정말 좋더라"처럼 사물·상태에 대한 서술). 단서가 문장 안에 분명히 있어야 한다.
- **`free`**: 두 문장의 뼈대·말투·길이가 서로 다르다.
- 명사 문장(`noun`)은 **어떤 일반 명사가 들어가도** 말이 되도록 쓴다(구체적 사물·자연·계절·음식·추상 명사 모두). 사람 문장(`person`)은 어떤 이름이 들어가도 말이 된다. 사람/명사 판별 단서를 단어 자체에 기대지 말고 문맥에 둔다.
- 명사 문장에 사람 이름 슬롯(`N1`, `N2`)을 **함께** 넣는 쌍이 많을수록 좋다(요청에 비율이 있다). 이때 `N2` 같은 일반 이름은 가려져야 하고 명사형 단어는 가려지지 않는다.
- 사람 문장 쪽이 항상 같은 말투·위치(예: 문두 주어)가 되지 않게 한다. 사람 문장의 슬롯 위치를 문두·문중·문말로 고루 둔다.

## 품질

- 말투: 가족 메신저의 자연스러운 한국어. 반말 중심에 존댓말 일부(약 25%). 길이 10~110자. 질문·명령·평서·감탄, 화자 관점, 연결어, 슬롯 위치를 다양하게. 짧은 한마디(10~25자)와 긴 문장(60~110자)을 섞는다.
- 시나리오는 가족 생활(일정·약속, 학교·학원, 안부·심부름, 정산·돈·구매, 사진·영상 공유, 병원·건강, 이동·방문, 음식·집안일, 잡담)에서 고루.
- 욕설, 성적·폭력적 내용, 정치, 실제 개인 비방 금지.
- 슬롯에 어떤 단어가 들어가도 문장이 말이 되어야 한다.
