# GaBee 한국어 NER(가명화) PERSON 고도화 연구 — R12 / R12b 기록

한국어 가족 대화에서 사람 이름(PERSON)을 가려내는 NER 모델의 노출을 줄이려는 두 차례 연구(R12, R12b)의 기록입니다.
**두 연구 모두 채택하지 않았고(NOT_ADOPTED), 운영 모델은 바뀌지 않았습니다.** 이 저장소는 서비스 코드가 아니라 연구 문서와 분석·검증 스크립트만 담고 있습니다.

> 표기: 자동 검증 기반 · 사람 검수 미실시 · 합성 데이터 평가. 독립 평가셋 평가는 하지 않았으므로 "5% 달성 여부"는 **UNVERIFIED**입니다.

## 한눈에 보기

| 항목 | R12 | R12b |
|---|---|---|
| 아이디어 | 같은 낱말이 사람 이름과 일반 명사로 모두 쓰이는 대조 문장을 학습에 추가 | R12 실패 원인(조사·띄어쓰기 단서 편향)을 고쳐 문장 구조를 다양화한 대조쌍 |
| 어디서 멈췄나 | 개발 게이트: 5개 시드 전원 탈락, 확정 시드 없음 | **학습 전** 데이터 품질 게이트 미통과 → 학습하지 않음 |
| 독립 평가 | 미실시 (UNVERIFIED) | 미실시 (UNVERIFIED) |
| 최종 판정 | NOT_ADOPTED | NOT_ADOPTED |

- 기준 모델: R11 (Seed 21, KoELECTRA-small, ONNX). 봉인 평가셋 2,350문장에서의 사전 등록 판정은 `KEEP_S0`(운영 모델 유지)이며 바꾸지 않았습니다.
- 사전 등록한 기준은 결과를 본 뒤 한 번도 완화하지 않았습니다.

## R12 요약

- 목적: PERSON 노출(완전·부분)을 줄이면서 일반 명사 오탐을 늘리지 않기.
- 개발 게이트(R11 대비): 정밀도 −2.0pp 이내, 일반 명사 오탐률 +3.0pp 이내, 일반 문장 오탐률 +1.5pp 이내, 노출 < R11, KLUE F1 −1.0pp 이내, ONNX 토큰 일치 ≥ 99.9% 및 크기·지연·메모리 ≤ 1.3배.
- 결과: 5개 시드 모두 게이트 탈락. 개발셋 분포가 다른 곳에서는 개선이 이어지지 않았고 일반 명사 오탐이 늘었습니다.
- 상세: `docs/NER_R12_REPORT.md`, 사전 등록 `docs/NER_R12_PREREGISTRATION.md`.

## R12b 요약

R12가 왜 실패했는지부터 다시 분석했고(`docs/NER_R12B_PREREGISTRATION.md` §1), 사전 등록한 **학습 전 데이터 품질 게이트**를 두었습니다.
낱말을 가리고 앞뒤 문맥만 보는 단서 분류기(naive Bayes)가 정답(사람/명사)을 맞히면, 모델이 의미가 아니라 문체·조사 단서를 배울 수 있다고 보고 학습을 막는 장치입니다.

| 검사 | 기준 | 조립 직후 | 허용된 수정 후 | 판정 |
|---|---:|---:|---:|---|
| 학습 쌍 5-겹 CV (단어 단위 분할) | ≤ 70% | 79.43% | 73.56% | 실패 |
| r12b_dev | ≤ 72% | 80.00% | 80.00% | 실패 |
| r12_dev | ≤ 72% | 79.32% | 80.59% | 실패 |
| r11_dev | ≤ 72% | 57.37% | 55.00% | 통과 |
| 한쪽 라벨에 쏠린 단서가 덮는 비율 | ≤ 25% | 21.3% | 2.3% | 통과 |

- 허용된 수정: 단서가 쏠린 대조쌍을 쌍 단위로 최대 25%(153쌍) 제거. 원본은 별도 보존.
- 결과: CV가 70% 아래로 내려가지 않았고, 사용자가 기준을 완화하지 않고 중단하기로 결정했습니다. 학습·개발 평가·독립 평가는 실행하지 않았습니다.
- 원인(관측 기반, 개별 실험으로 확정하지는 못함): 사람 문장에 쏠린 문맥 단어, 조사 형태(예: 주격 이/가) 불균형, 같은 계열 작성자의 문체 유사성. 실제 문맥 의미와 작성 틀의 영향은 분리하지 못했습니다.
- 상세: `docs/NER_R12B_REPORT.md` (§4.1 게이트 표, §4.2 원인, §4.3 공통점).

## R12와 R12b의 공통점

- 같은 방식으로 쓴 학습·개발셋에서는 작성 방식 단서만으로도 점수가 높게 나옵니다(약 80%).
- 작성 방식이 다른 셋에서는 크게 떨어집니다(r11_dev: R12 65.5%, R12b 55.0%).
- 낱말·이름·문장 겹침을 0으로 통제해도 문장 틀과 문체가 같으면 일반화 평가가 되지 않습니다.
- R12는 모델 성능으로, R12b는 학습 전 데이터 진단으로 같은 징후가 확인됐습니다.

## 구성

```
docs/      사전 등록, 최종 보고, 독립 평가셋 제작 지시서 (R12, R12b)
scripts/   풀 배정, 배치 생성·검증, 조립, 단서 분류기 진단·품질 게이트·단서 제거,
           학습 러너·게이트·개발 평가 (R12b의 run/gate/evaluate 는 한 번도 실행하지 않음)
```

## 이 저장소에 없는 것

- 학습·검증·개발 데이터와 모델·ONNX 산출물: 합성 문장과 이름 풀이 포함되어 공개하지 않았습니다(로컬 보존).
- 봉인된 R11 평가셋과 서비스 코드.
- 스크립트는 로컬 작업 폴더(`ner-runs/`)와 학습 환경을 전제로 하므로 이 저장소만으로는 재현되지 않습니다. 경로의 사용자 이름은 `<user>`로 바꿨습니다.
