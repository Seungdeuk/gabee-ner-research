# GaBee 한국어 NER(가명화) 연구 기록 — R1 ~ R12b

한국어 가족 대화에서 사람 이름(PERSON)을 가려내는 NER 모델의 노출(마스킹되지 않고 남는 이름)을 줄이려고 2026-11-12부터 2026-11-24까지 한 연구의 전체 기록입니다.
서비스 코드는 포함하지 않고, 연구 문서·분석/학습/평가 스크립트·합성 평가셋만 담았습니다.

> 표기: 자동 검증 기반 · 사람 검수 미실시 · 합성 데이터 평가. 이 저장소의 수치는 합성 평가셋 기준이며 실제 운영 데이터로 확인한 값이 아닙니다.

## 결론

- **운영 모델은 연구 기간 내내 바뀌지 않았습니다.** 기존 서비스 모델(S0, `koelectra-small-v2b`)을 유지합니다.
- 개발셋에서는 개선이 반복해서 나왔지만, 독립(봉인) 평가셋에서는 사전 등록한 교체 기준을 넘지 못했습니다(R8, R11) 또는 교체를 막는 악화가 함께 나왔습니다(R9). R10은 후보가 없었고 R12, R12b는 채택하지 않았습니다.
- 사용자 목표(전체 노출 < 5%, 비PERSON 오탐 ≤ 5%, Exact F1 ≥ 90%)는 달성하지 못했습니다. R12와 R12b는 독립 평가를 하지 않았으므로 달성 여부는 **UNVERIFIED**입니다.
- 반복해서 확인된 원인 후보: 학습·개발셋의 문장 틀과 문체 단서가 정답과 얽혀 있어서, 개발셋 개선이 다른 방식으로 쓴 평가셋으로 이어지지 않았습니다(R8, R12, R12b).

### R11 봉인 평가 결과 (S0 vs R11 Seed 21, 2,350문장, 1회)

| 지표 | S0 | R11 | 차이 | 사전 등록 기준 |
|---|---:|---:|---:|---|
| Exact Recall | 75.22 | 84.12 | +8.90%p | +10 이상 → FAIL (P1) |
| 전체 노출률 | 17.07 | 10.23 | −6.84%p | −8 이하 → FAIL (P2) |
| Exact F1 | 80.98 | 87.37 | +6.39%p | +8 이상 → FAIL (P3) |

P4~P9는 통과했지만 P1~P3가 미충족이라 판정은 `KEEP_S0`이고, 이 판정은 바꾸지 않았습니다. R11은 노출을 줄였으나 사전 등록한 교체 기준에는 못 미쳤습니다.

## R12 / R12b 상세

R12b는 낱말을 가리고 앞뒤 문맥만 보는 단서 분류기(naive Bayes)가 정답(사람/명사)을 맞히면 모델이 의미가 아니라 문체·조사 단서를 배울 수 있다고 보고, 학습 전에 막는 사전 등록 게이트를 두었습니다.

| 검사 | 기준 | 조립 직후 | 허용된 수정 후 | 판정 |
|---|---:|---:|---:|---|
| 학습 쌍 5-겹 CV (단어 단위 분할) | ≤ 70% | 79.43% | 73.56% | 실패 |
| r12b_dev | ≤ 72% | 80.00% | 80.00% | 실패 |
| r12_dev | ≤ 72% | 79.32% | 80.59% | 실패 |
| r11_dev | ≤ 72% | 57.37% | 55.00% | 통과 |
| 한쪽 라벨에 쏠린 단서가 덮는 비율 | ≤ 25% | 21.3% | 2.3% | 통과 |

- 허용된 수정: 단서가 쏠린 대조쌍을 쌍 단위로 최대 25%(153쌍) 제거(원본 보존).
- 기준은 완화하지 않았고 학습·개발 평가·독립 평가는 실행하지 않았습니다.
- 원인(관측 기반): 사람 문장에 쏠린 문맥 단어, 조사 형태(주격 이/가) 불균형, 같은 계열 작성자의 문체 유사성. 실제 문맥 의미와 작성 틀의 영향은 분리하지 못했습니다.
- R12와 R12b의 공통점: 같은 방식으로 쓴 셋에서는 약 80%를 단서만으로 맞히고, 작성 방식이 다른 r11_dev에서는 R12 65.5%, R12b 55.0%로 떨어집니다. 낱말·이름·문장 겹침을 0으로 통제해도 문장 틀과 문체가 같으면 일반화 평가가 되지 않았습니다.

## 이 저장소에 없는 것

- 서비스(앱·API) 코드, 학습 데이터, 모델·ONNX 산출물(합성 문장과 이름 풀 포함, 로컬 보존).
- 봉인된 R9·R11 독립 평가셋 본문.
- 스크립트는 로컬 작업 폴더(`ner-runs/`)·학습 환경·서비스 코드 경로(`app.shared.privacy` 등)를 전제로 하므로 이 저장소만으로는 재현되지 않습니다. 경로의 사용자 이름은 `<user>`로, 운영 GCP 프로젝트 ID는 `<GCP_PROJECT>`로 바꿨습니다.
- 이 기록은 연구 결과이며 운영 교체 승인이 아닙니다. R11 운영 교체 문서(런북, 위험 수용 결정서)는 서명 전 초안입니다.
