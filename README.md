# GaBee 한국어 NER 가명화 연구 — 사전 등록·봉인 평가로 검증한 이름 노출 감소

가족 비서 앱 GaBee는 가족 대화를 외부 LLM(Claude)에 보내기 전에 사람 이름을 가명으로 바꾸고, 답을 받은 뒤 원래 이름으로 되돌립니다.
이 저장소는 그 가명화에 쓰는 한국어 NER 모델(KoELECTRA-small, ONNX CPU 추론)이 **가리지 못하고 남기는 이름(노출)** 을 줄이려고 2026-11-12부터 11-24까지 진행한 연구(R1~R12b)의 전체 기록입니다.
연구 문서, 데이터 생성·학습·평가 스크립트, 합성 평가셋을 담았고 서비스 코드는 포함하지 않습니다.

> 표기: 자동 검증 기반 · 사람 검수 미실시 · 합성 데이터 평가. 모든 수치는 합성 평가셋 기준이며 실제 사용자 데이터로 확인한 값이 아닙니다.

## 한눈에 보기

| 항목 | 내용 |
|---|---|
| 문제 | 한국어 가족 대화에서 사람 이름(PERSON) 탐지. 별명·줄임말·조사 결합, 그리고 "하늘·나래·한결"처럼 **일반명사와 형태가 같은 이름**이 핵심 난제 |
| 제약 | 운영 서버 CPU 추론(1 vCPU / 2GiB), 모델 크기·지연 증가 30% 이내, 라벨·토크나이저 호환 |
| 모델 | `monologg/koelectra-small-v3-discriminator` 토큰 분류 파인튜닝 → ONNX Runtime CPU |
| 최종 후보 | R11 B-new Seed 21 (학습 9,915행, 이름·일반명사 대조쌍 800행 포함) |
| 독립 평가 | 봉인 합성 평가셋 2,350문장, 서비스 모델(S0)과 후보를 같은 스크립트로 **1회만** 측정 |

| 판정 | 개선은 확인됐지만 사전 등록한 최소 개선 폭(Recall +10%p 등)에 못 미쳐 연구 판정은 `KEEP_S0`. 운영 교체는 이 판정을 바꾸지 않고 별도 위험 수용 절차로 분리 |

## 1. 문제 정의

가명화는 "이름을 하나라도 놓치면 그 이름이 외부 LLM으로 그대로 나간다"는 구조라서, 일반적인 F1보다 **노출률**(정답 이름 중 가려지지 않고 남은 비율)을 최우선 지표로 삼았습니다.
반대로 일반 단어를 이름으로 잘못 가리면(오탐) 문장 의미가 망가져 답변 품질이 떨어지므로 비PERSON 오탐률도 함께 봤습니다.

- 목표(연구 시작 때 지정): 전체 노출률 < 5%, 비PERSON 오탐률 ≤ 5%, Exact F1 ≥ 90%. 충돌하면 노출률 우선.
- 기준선: 서비스 모델 S0 (`koelectra-small-v2b`, KLUE 10% 혼합, ONNX SHA256 `46210943…`).

## 2. 평가 설계 — 개발셋 점수에 속지 않기 위한 장치

초기 라운드(R1~R8)에서 개발셋 점수는 계속 오르는데 새로 만든 평가셋에서는 효과가 사라지는 현상을 겪었습니다(R8: 개발셋 노출 6.53% → 2.89%, 봉인 평가셋 new180에서는 13.6% → 14.6%).
그래서 R9부터는 평가 절차 자체를 다시 설계했습니다.

| 장치 | 내용 | 근거 문서 |
|---|---|---|
| 사전 등록 | 학습 전에 비교 군, 시드, 하이퍼파라미터, 후보 선정 규칙, 교체 기준(P1~P9)을 문서로 고정하고 해시로 잠금. 결과를 본 뒤 기준을 바꾸지 않음 | `docs/NER_R9_PREREGISTRATION.md`, `docs/NER_R11_PREREGISTRATION.md` |
| 봉인 평가셋 | 독립 평가셋은 SHA256 매니페스트로 봉인하고 학습·튜닝·오류 보강에 쓰지 않음. 측정은 모델당 1회, `EVALUATED.lock`으로 재실행 방지 | `docs/NER_R11_EVALSET_SEAL_PROCEDURE.md`, `scripts/seal_r11_evalset.py` |
| 작성자 분리 | 학습 데이터와 독립 평가셋을 서로 다른 작성 주체(LLM)·지시서로 만들어 문체 공유를 줄임 | `docs/NER_R9_GPT_EVALSET_INSTRUCTIONS.md`, `docs/NER_R11_EVALSET_PRODUCER_INSTRUCTIONS.md` |
| 대조군 | 데이터 내용 효과와 학습량 효과를 분리하려고 행 수·에폭당 스텝·KLUE 비중을 맞춘 통제군(C10)을 함께 학습 | `docs/NER_R10_PREREGISTRATION.md` |
| 유형별 분모 | 오류 유형 16종(이름+조사, 별명, 긴 이름, 일반명사형 이름 D1P와 짝 문장 D1 등)마다 최소 정답 수를 정해 평균에 묻히는 악화를 확인 | `docs/NER_R11_EVALSET_SPEC.md` |
| 신뢰구간 판정 | 교체 기준은 평균 차이와 부트스트랩 신뢰구간 하한·상한을 함께 봄 | `docs/NER_R11_OPS_RISK_ACCEPTANCE.md` |

## 3. 데이터·학습

- **오류 분석 → 데이터 설계.** 서비스 모델의 실패를 유형별로 나눠(완전 미탐, 부분 탐지, 경계 절단, 일반명사 오탐) 각 유형을 겨냥한 합성 문장을 만들었습니다(`scripts/analyze_errors.py`, `scripts/analyze_miss_decomposition.py`).
- **이름·일반명사 대조쌍.** 같은 낱말이 한 문장에서는 이름, 짝 문장에서는 일반명사로 쓰이는 400쌍(800행)을 넣어 문맥으로 구분하도록 학습했습니다.
- **R11 학습 데이터 9,915행** = 기존 R9F 7,815행 + 신규 2,100행(대조쌍 800 + R10 데이터 900 + 기존 유형 보호 400). KLUE 469행(4.73%)을 유지해 일반 NER 성능 하락을 막았습니다.
- **고정 조건.** max_len 128, batch 32, lr 5e-5, 최대 8에폭, 조기 종료 patience 2, 시드 7·13·21·42·99 5회 반복.
- **누수 방지.** 학습 데이터에 평가셋의 문장·이름이 섞이지 않았는지 학습 전에 자동 검사하고, 학습 직전 데이터·평가 코드·기준 파일 해시를 다시 확인했습니다.

## 4. 결과

### 봉인 독립 평가 (S0 vs R11 Seed 21, 2,350문장, 1회)

| 지표 | S0 | R11 | 차이 | 사전 등록 기준 | 판정 |
|---|---:|---:|---:|---|---|
| Exact Recall | 75.22 | 84.12 | +8.90%p | +10 이상 | FAIL (P1) |
| 전체 노출률 | 17.07 | 10.23 | −6.84%p | −8 이하 | FAIL (P2) |
| Exact F1 | 80.98 | 87.37 | +6.39%p | +8 이상 | FAIL (P3) |

- 세부: 완전 노출 14.69 → 9.32, 부분 노출 2.39 → 0.92, 일반명사 오탐(D1) 16.7 → 3.3, 대조쌍 정확도 43.0 → 57.3. 별명·긴 이름·새 이름·기관/장소 혼합 유형의 노출률은 모두 감소(신뢰구간 상한 < 0).
- P4~P9(회귀 유형 악화 금지 등)는 통과했지만 P1~P3 미달로 최종 판정은 `KEEP_S0`이고, 이 판정은 이후에도 바꾸지 않았습니다.

### 서비스 적용 호환성 (개발 환경)

| 검사 | 결과 |
|---|---|
| KLUE 검증 F1 (일반 NER 성능 유지) | 74.12 → 73.78 (−0.34%p, 허용 −1%p 이내) |

| 가명화 왕복 | 소통·일정·주간 뉴스에서 가명화 → 복원 정상, 동시 120건 혼입 0 |

## 5. 한계와 배운 점

1. **개발셋 개선은 독립 평가로 이어지지 않을 수 있다.** R8에서 개발셋 노출이 절반 이하로 줄었지만 봉인 평가셋에서는 그대로였습니다. 이 경험이 사전 등록·봉인·작성자 분리 절차를 만든 이유입니다.
2. **일반명사형 이름은 모델만으로 풀기 어렵다.** D1P 노출률은 S0 43% → R11 40%로 거의 그대로였고, 학습한 모델 15개에서 D1P 노출과 일반명사 오탐의 순위상관이 ρ = −0.82로, 한쪽을 줄이면 다른 쪽이 늘었습니다(`docs/NER_R10_ERROR_ANALYSIS_AND_R11_PROPOSAL.md`). 그래서 등록된 가족 이름 사전과 이전 대화 문맥을 함께 쓰는 다층 방어를 후속안으로 제안했습니다(미구현).
3. **학습 전에 데이터의 지름길 단서를 검사해야 한다.** R12·R12b에서는 이름 자리를 가리고 앞뒤 문맥만 보는 단서 분류기(naive Bayes)가 같은 방식으로 쓴 문장에서 약 80%를 맞혔습니다. 모델이 의미가 아니라 문체·조사 형태를 배울 수 있다는 뜻이라, R12b는 이 비율이 기준(≤ 70~72%)을 넘으면 학습하지 않는 사전 등록 게이트를 두었고 실제로 학습 전에 중단했습니다.

| R12b 데이터 게이트 | 기준 | 조립 직후 | 허용된 수정 후 | 판정 |
|---|---:|---:|---:|---|
| 학습 쌍 5-겹 CV (단어 단위 분할) | ≤ 70% | 79.43% | 73.56% | 실패 |
| r12b_dev | ≤ 72% | 80.00% | 80.00% | 실패 |
| r12_dev | ≤ 72% | 79.32% | 80.59% | 실패 |
| r11_dev (작성 방식이 다른 셋) | ≤ 72% | 57.37% | 55.00% | 통과 |
| 한쪽 라벨에 쏠린 단서가 덮는 비율 | ≤ 25% | 21.3% | 2.3% | 통과 |

## 8. 이 저장소에 없는 것

- 서비스(앱·API) 코드, 학습 데이터 본문, 모델·ONNX 파일(로컬 보존).

- 스크립트는 로컬 작업 폴더(`ner-runs/`)·학습 환경·서비스 코드 경로(`app.shared.privacy` 등)를 전제로 해서 이 저장소만으로는 재현되지 않습니다. 경로의 사용자 이름은 `<user>`, 운영 GCP 프로젝트 ID는 `<GCP_PROJECT>`로 바꿨습니다.
- 이 기록은 연구 결과이며 운영 교체 승인이 아닙니다. R11 운영 교체 문서(런북, 위험 수용 결정서)는 서명 전 초안입니다.
