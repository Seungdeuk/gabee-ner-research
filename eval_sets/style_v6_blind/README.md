## 중요 — 블라인드 유지 규칙

- **이 파일의 정답을 모델 선택이나 추가 학습에 쓰지 않는다.** 평가 결과를 보고 데이터를 다시 만들거나 이름을 바꾸지 않는다(한 번 쓰면 더 이상 "블라인드"가 아니다).
- 평가는 모델(서비스 모델 1개 + R1 5시드)당 **정확히 1회**만 한다.
- 평가 후에도 이 파일은 수정하지 않는다. 다음 세대(v7 등) 최종 평가가 필요하면 새 폴더를 만든다.

### 예외: 사후 추가 분석(2026-11-14, 사용자 승인)

위 "정확히 1회" 규칙에 대한 **유일한 예외**다. 서비스 모델과 R1 시드7은 이미 각 1회(완전미탐률 측정,
`eval_style_set.py`)로 평가를 마쳤다. 이력서·포트폴리오용 **entity-level exact-match P/R/F1**이
필요하다는 요청에 따라, 같은 두 모델(가중치·설정 변경 없음)을 blind_v6.jsonl에 대해 **추가로 1회씩만** 더
추론해 `eval_blind_v6_exact_prf.py`로 다른 채점 기준(exact-match)을 측정했다 — 모델/규칙 재선정·튜닝에는
쓰지 않았고, 결과를 보고 데이터나 코드를 고치지도 않았다. 자세한 조건과 결과는
`docs/security/NER_VALIDATION.md` 40절, 원본 수치는 `exact_prf_postselection_analysis.json`.

### 예외 #2: 완전미탐·경계불일치 원인 진단(2026-11-16, 사용자 승인)

위 예외 #1과 같은 조건(가중치·설정 변경 없음, 결과로 모델·규칙 재선정 안 함)으로, R1 시드7을 blind_v6에
**한 번 더(세 번째)** 추론했다 — 완전미탐 40건·경계불일치 24건 각각이 "후보 미생성/다른 라벨 오분류/점수
임계값 탈락/후처리 제거" 중 무엇인지 사례별로 확인하기 위함(이력서 면접 설명용). 스크립트는
`eval_blind_v6_miss_diagnosis.py`(신규, 기존 스크립트 미변경), 결과는 `r1_s7_miss_diagnosis.json`, 분석은
`docs/security/NER_VALIDATION.md` 41절.

**이 두 번째 예외를 끝으로, blind_v6에 대한 추가 추론은 더 이상 하지 않는다.** 앞으로 또 필요하면 새 held-out
셋(v7)을 만든다.

## 한계

- 전부 합성이다. 실제 가족 대화의 다양성·오탈자·문맥을 다 담지 못한다.
- "일반_메신저"·"낯선_이름"은 사람이 쓴 템플릿 10~5개뿐이라 실제 표현의 다양성을 대표하지 못한다.
- "애칭_줄임말"·"ORGLOC_*"은 이번 세션에서 찾은 특정 실패 유형을 겨냥한 스트레스 테스트라, 실제 가족 채팅에서 이 유형이 얼마나 자주 나오는지는 알 수 없다(과대/과소 대표 가능성 둘 다 있음).
- "조사_경계건강검진"은 실패를 찾는 범주가 아니라 "이미 잘 되던 것이 안 깨졌는지" 확인하는 용도다 — 여기서 미탐이 나오면 R1이 R2·R1b-A 같은 경계 붕괴를 이미 갖고 있다는 뜻으로 심각하게 봐야 한다.
