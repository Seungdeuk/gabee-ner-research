# 문체별 개인정보 평가셋 v4 (저장소 안, 전부 합성)

로드맵 1~4단계(공통 비교 → 오류분석 → 재학습 → 통합 평가)에서 반복 참고하는 devset이다. **5단계(최종 독립 테스트)에는 쓰지 않는다** — 그 단계는 아직 아무도 보지 않은 완전히 새 평가셋을 따로 만든다.

저장소 밖 `gabee-ner-evalset-v3`(488문장)는 2026-11-03에 KLUE10%·AIHub10% 두 모델을 이미 1회 평가해 "소비됨"으로 간주하기로 했다. 그래서 v3와 같은 생성 방식을 저장소 **안**(`apps/api/app/shared/privacy/eval/style_v4/`)에 다시 구현해, v3보다 더 넓은 제외 집합(학습 풀 + `baseline_v2` 전체 분할 + v3 자체)으로 완전히 새 이름·새 문장을 만들었다. 데이터는 모두 합성이며 실제 개인정보가 없다.

생성 실행 시 `build_evalset.py`가 출력하는 통계 json(`sentences`, `by_category`, `excluded_names`, `sha256_12`)이 실제 숫자의 근거다. 2026-11-12 실행 결과: 문장 488개(위 표와 정확히 일치), 제외한 이름 808개, 제외 후 쓸 수 있는 처음 보는 이름 1,435개, `evalset_v4.jsonl` sha256 앞 12자 `0a201c830865`.

## 겹치지 않게 한 방법

- **이름**: 성은 학습과 같은 풀이지만, 이름(given)은 `exclusions.collect_excluded_names`가 모은 제외 집합(학습 풀 `ml/ner/data/synth.py`의 GIVEN1/GIVEN2 + `baseline_v2` train/val/test 전체의 PERSON 이름 + 옛 v3의 PERSON 이름)에 없는 것만 쓴다.
- **문장 틀**: `synth.py`의 TEMPLATES/AUG_TEMPLATES류 + `baseline_v2` 전체 + 옛 v3의 문장에서 이름(또는 주소) span을 지운 "뼈대"와 하나라도 같으면 `assert_no_overlap`이 `SystemExit`을 올려 생성이 멈춘다.
- 겹침이 전혀 없으면 생성이 끝까지 돌고 `evalset_v4.jsonl`이 만들어진다.

## 평가 방법

`apps/api/scripts/eval_style_set.py` — 서비스 가명화 경로(`detect_with_ner`, 규칙 우선 병합)로 예측하고, 정답 구간마다 같은 종류의 예측이 글자를 덮은 정도로 전부(full)/일부 노출(partial)/누출(none)로 센다. 100자 기준 CPU 지연(median/P95 ms)도 같이 낸다. 외부 호출은 없다.
