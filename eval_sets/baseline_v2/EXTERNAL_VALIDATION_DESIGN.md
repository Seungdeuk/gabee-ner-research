# 외부 검증 세트 설계 초안 (구현은 다음 단계)

## 왜 필요한가
Baseline v2 는 사람이 쓴 틀 5~10개를 범주마다 값만 바꿔 늘린 세트다. 분할을 틀 단위로 나눠도 (1) 문장 표현이 우리 틀의 어휘·어순에 묶여 있고, (2) 한 틀의 변형 4개는 거의 같은 문장이며(900문장 ≈ 독립 틀 약 190개), (3) 규칙 작성자가 같은 팀이라 "규칙이 놓칠 만한 것"을 의도적으로 모은 편향이 있다. 이 세트는 **템플릿과 독립적으로 작성된** 문장으로 일반화 성능을 재는 별도 검증용이다. 학습·튜닝에 쓰지 않는다(봉인).

## 구성 목표
- 규모: 400~600문장, 개인정보 포함 약 70 %, 음성 약 30 %.
- 문체: 가족 대화체(반말·줄임말·초성/이모티콘·오탈자·띄어쓰기 오류·말줄임), 메신저식 짧은 문장, 음성 메모를 받아쓴 긴 문장.
- 값: OCR 오류(명함·영수증·통장 사진 텍스트에서 흔한 O/0, l/1, 공백 삽입), 한글 숫자, 새 주소·이름 조합(기존 풀에 없는 성·이름·도로명·동), 호칭 없는 이름, 이름+가족호칭, 별명, 기관명.
- 음성: 개인정보 모양의 번호(주문·운송장·버전·날짜·금액), 지명, 일반 가족 호칭, 사람 이름 같은 일반 단어.
- 라벨은 `LABELING_GUIDE.md` 그대로(세분 라벨 + `mask_default`, `context_sensitive`). 스키마·`template_id` 필드를 같이 쓰되 `template_id` 는 작성자·시나리오 번호로 쓴다(누출 검사 재사용).

## 출처 후보와 장단점
| 방식 | 내용 | 장점 | 단점/주의 |
|---|---|---|---|
| A. 사람이 직접 쓴 문장 | 작성 가이드(아래)를 주고 팀원 3인 이상이 각자 시나리오 카드로 작성 | 템플릿 독립성이 가장 큼, 실제 말투 | 시간 소요, 작성자 편향 |
| B. 별도 시드·별도 틀 | 현 생성기와 분리된 새 틀·새 풀을 **규칙·현 틀을 본 적 없는 사람**이 작성 | 빠름, 값 분포 통제 | 여전히 합성 틀(보조 검증) |
| C. LLM 보조 초안 + 사람 검수 | 시나리오 카드로 문장 초안을 만들게 한 뒤 사람이 고치고 라벨. 개인정보는 합성 값만 프롬프트에 넣는다 | 다양성 | 프로젝트 규칙상 실제 Claude 호출·개인 데이터 외부 전송 금지 여부를 먼저 합의해야 함. 승인 전에는 쓰지 않는다 |
| D. 공개 말뭉치 변형 | 공개 한국어 대화 말뭉치의 문장에 합성 개인정보를 삽입 | 실제 문체 | 라이선스·삽입 위치 부자연스러움 |
권장: A 를 핵심(약 300문장)으로, B 를 보조(약 100~200문장)로. C 는 정책 합의 후.

## 사람 작성 가이드 (요지)
1. 시나리오 카드(예: "택배 기사에게 우리 집 위치를 알려준다", "학원 상담 중 아이 이름과 연락처를 말한다")를 받아 **자기 말투로** 1~3문장을 쓴다. 제공된 예시 문장을 베끼지 않는다.
2. 값은 합성만: 주민번호는 2030년 이후 출생(성별 3/4), 카드는 공개 시험 PAN 또는 Luhn 실패 값, 전화는 010-0000-NNNN, 이메일은 `example.*`(`FIXTURE_SAFETY.md`). 실제 지인·자기 정보 금지.
3. 문장마다 의도적으로 한 가지 이상의 어려움(오탈자, 띄어쓰기 오류, 한글 숫자, OCR 오류, 약식 주소, 별명, 호칭 없는 이름)을 섞되 과장하지 않는다. 일부는 개인정보 없는 문장으로.
4. 작성 후 **둘이 독립적으로 라벨**하고 불일치 구간을 합의한다(구간 일치율·κ 를 기록).
5. 작성 사실(작성자 코드, 시나리오 번호)만 남기고 이름은 남기지 않는다.

## 품질·운영
- 분리: 작성자는 규칙(`detectors.py`)·현재 틀을 읽지 않는다. 평가 중 오류를 보고 규칙을 고치면 그 세트는 개발 세트가 되므로, 외부 세트는 **분기마다 한 번만** 평가하고 결과를 근거로 규칙을 고친 뒤에는 새 세트를 추가한다.
- 중복·누출: 본문 정규화 중복, 문장 틀 중복, 기존 baseline_v2 와의 문장 유사도(문자 n-gram) 상한을 검사.
- 안전: 공개 저장소에는 안전 픽스처 규칙을 따른 세트만 올린다(`check_fixture_safety` 적용).
- 보고: 세분 라벨별 P/R/F1(exact/overlap), 태그별, 라벨러 간 일치율, baseline_v2 와의 격차(템플릿 편중 정도) 를 함께 낸다.
