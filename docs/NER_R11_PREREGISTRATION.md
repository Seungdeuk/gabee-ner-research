## 0. 표기 규칙 (보고서·결과표 공통)

모든 표와 보고서는 영문 코드와 한글 유형명을 함께 쓴다.

| 코드 | 한글 유형명 | 방향 |
|---|---|---|
| D1P | 이름·일반명사 중의성에 따른 PERSON 미탐(사람 문장에서 놓침) | 낮을수록 좋음(노출률) |
| D1 | 이름·일반명사 중의성에 따른 오탐(명사 문장에서 PERSON 을 냄) | 낮을수록 좋음(오탐률) |
| B1 | 이름 뒷부분 누락·부분 노출 | 낮을수록 좋음(노출률) |
| C2 | 이름 구간 경계 오류(인접 이름 병합·분리) | 노출률·Exact F1 |
| NEWNAME | 신규 이름(참조 집합에 없는 이름 부분) | 노출률 |
| LONGNAME | 긴 이름(PERSON 구간 4글자 이상, 호칭 제외) | 노출률 |
| Exact Recall | PERSON 구간 **정확 일치 재현율**(R11 최우선 지표) | 높을수록 좋음 |
| 가림률 | 정답 구간이 완전히 가려진 비율 = 1 − 전체 노출률(경계 일치 불필요) | 높을수록 좋음 |

용어: **전체 노출** = 정답 PERSON 구간 중 하나도 가려지지 않은 비율 + 일부만 가려진 비율, **완전 노출** = 전혀 가려지지 않음, **부분 노출** = 일부만 가려짐(R9 개발 평가 정의 그대로). **Exact Recall 과 노출률은 다른 지표이다**(§7-1): Recall 은 경계까지 정확히 일치해야 맞고, 노출률은 글자가 가려졌는지만 본다. **쌍 문맥 정확률** = 같은 단어의 사람 문장은 PERSON 구간이 정확히 가려지고 명사 문장은 PERSON 이 없는 쌍의 비율(R10 분석의 "문맥 정답" 사분면).

## 2. R11 검증 가설과 판정 규칙

**가장 중요한 목표**: D1P 노출을 줄이면서 D1 오탐이 늘어나는 트레이드오프를 완화한다. 동시에 R9F 의 낮은 전체 노출률과 기존 이름·신규 이름·긴 이름 탐지를 유지한다.

판정은 5시드의 점추정과 시드 분포로 하며, 신뢰구간(단어·쌍 군집 부트스트랩 1,000회, 시드 고정)을 병기한다. 구간이 0 을 포함하는 차이는 개선이라고 쓰지 않는다. 결과를 본 뒤 임계값을 바꾸지 않는다. **B 군의 효과는 "통합 데이터 구성 전략"의 효과로만 해석하며, 대조쌍 다양성·R10 데이터 축소·보호 재사용 중 어느 하나의 인과 효과로 단정하지 않는다.**

| 가설 | 비교(§3-3) | 지지 조건(모두 충족) | 미지지·불확정일 때 |
|---|---|---|---|
| H1 통합 데이터 구성 전략 | C10(A) vs B-old | 쌍 문맥 정확률 B-old 5시드 평균이 C10 보다 +5.0%p 이상, D1P 노출 평균 C10 이하, D1 오탐 평균 C10 +3.0%p 이하 | "통합 구성의 효과 미확인" |
| H-SEL 선정 기준 | B-old vs B-new | B-new 의 쌍 문맥 정확률 평균이 B-old 이상이고 5시드 중 B-old 보다 나빠진 시드가 1개 이하(같은 에폭을 고른 시드는 차이 0 으로 세고 그 수를 보고) | "선정 기준 변경 효과 미확인" |
| H-SWA 가중치 평균 | B-new vs C-SWA(시드별 쌍) | D1P 노출 5시드 표준편차가 B-new 대비 30% 이상 감소, 시드별 D1P 노출이 B-new 보다 나빠진 시드 1개 이하, 경계 확률 구간(0.1~0.9) 비율이 B-new 이하, Exact Recall 5시드 표준편차가 B-new 이하 | "가중치 평균의 안정화 효과 미확인" |
| H-VOL 학습량 | A(C10) vs R9F | R9dev 매크로 노출 C10 이 R9F +0.5%p 이하면 "학습량 효과 없음", 초과면 "학습량 증가가 R9dev 회귀와 함께 관찰됨" | 구간 포함 시 불확정 |

H-VOL 은 R10 에서 C10 한 군에서 본 관찰이므로 인과로 쓰지 않고 "함께 관찰됨"으로 쓴다.

### 3-4. C 군 구현 가능성과 사전 고정 규칙

**확인된 사실**(코드 확인): 현재 `ml/ner/train/train_ner.py` 는 검증 점수가 개선될 때(`score > best`)만 `best/` 에 저장하고 에폭별 저장은 없다. 마지막 3에폭 평균에는 **에폭별 저장 기능이 필요하다.** 필요한 변경은 학습 스크립트(`ml/`, 공용 서비스 코드 아님)에 저장 옵션(`--save-every-epoch`)을 더하는 것뿐이며 학습 계산(손실·옵티마이저·스케줄·난수)은 바꾸지 않는다. **구현·검증 완료(2026-11-20, 사용자 승인)**: 옵션은 기본 꺼짐이며 `ml/ner/tests/test_train_save_every_epoch.py` 4개 시험(켜도 `best/` 가중치 해시·에폭별 손실·검증 점수·종료 에폭 동일, 꺼진 경로는 에폭 저장 없음, 에폭 저장본 SHA256 기록, `best/` == `epoch_{best_epoch}/`, `--no-save-model` 시 무시)이 통과했다. 이 시험은 작은 무작위 BERT 로 CPU 에서 확인한 것이며 GPU·fp16 경로의 비트 단위 동일성은 확인하지 못했다(저장은 읽기 전용이라 영향이 없다고 판단하나 B 첫 런에서 `best/` 와 `epoch_{best_epoch}/` 해시 일치로 다시 확인한다).

| 항목 | 확인·고정 |
|---|---|
| 추가 학습 필요 여부 | 없음. B 런이 에폭별 가중치를 저장하면 B-old·B-new·C-SWA 모두 저장본에서 파생 |
| 보존 방법 | 에폭별 `epoch_k/model.safetensors` 보존(fp32, 1개 약 53.7MB 실측), 삭제 없이 SHA256 기록. 시드당 최대 8개 ≈ 0.43GB, 5시드 최대 ≈ 2.2GB + 평균 모델 5개 ≈ 0.27GB. C 드라이브 여유 약 10.4GB(2026-11-20 실측), 학습 전 재확인 |
| 저장 기능 정합성 점검(추가 학습 없음) | 같은 런에서 기존 방식 `best/` 와 `epoch_{best_epoch}/` 의 가중치 SHA256 이 같아야 한다. 다르면 보고 |
| 평균 규칙 | θ_avg = (θ_{e−2}+θ_{e−1}+θ_e)/3, e = 그 런의 마지막 학습 에폭. 분류 헤드 포함 모든 학습 파라미터를 fp32 로 균일 산술평균, 정수형 버퍼(`position_ids`)는 마지막 에폭 값 복사, LayerNorm 모델이라 통계 재보정 없음. 학습 에폭이 3 미만이면 있는 전 에폭을 평균하고 표시(R10 은 4~7에폭) |
| 동일 런 공유 | B-old·B-new·C-SWA 는 같은 5개 런·데이터·시드·토크나이저를 공유(런 ID 기록) |
| 금지 | EMA, 쌍 일관성 손실, 온도 보정, 학습률 변경 등 다른 안정화 기법 추가·병행 금지. 평균 창·균일 가중을 결과 후에 바꾸지 않음 |
| ONNX | C-SWA 가 후보가 될 때만 평균 모델을 변환하고 토큰 일치율 확인 |

체크포인트를 확보할 수 없으면(저장 기능 미승인, 디스크 부족, 저장본 불일치) 실험을 확대하거나 다른 방법으로 대체하지 않고 보고한다. 이 경우 C-SWA 는 수행하지 않고 B 만 평가한다.

**데이터가 수정되면**: 매니페스트 해시를 갱신하고, 기존 모델(S0·R9F·C10·R10-full)의 `r11_dev` 기준선과 상대 게이트(G1~G11)·Recall 게이트(R11-R1~R4, R11-S)를 같은 공식으로 다시 계산해 커밋하고 사용자 확인을 받은 뒤 B 학습으로 진행한다(B 결과를 보기 전).

| 4-gram 유사도(≥0.7) | 학습↔Validation·Development 0, 세트 내부 0(학습 내부는 R10 기준 3% 이하) |

### 5-3. 쌍 문맥 정확률 200쌍의 통계적 불확실성과 표본 수 제안

쌍 문맥 정확률은 한 쌍이 맞거나 틀리는 이항 지표다(1쌍 = 쌍 수의 역수). 정확률 p 일 때 95% 신뢰구간 반폭(이항 근사, 단어 군집 무시)과 단일 모델 한 시드 기준 검출 가능한 최소 차이(MDE, 검정력 80%·α 5%, 같은 쌍에서 쌍 비교 상관 ρ=0.5 가정):

| 쌍 수 | p=0.15 | p=0.20 | p=0.30 | 두 모델 차이 MDE(독립) | MDE(ρ=0.5) |
|---|---|---|---|---|---|
| 150(R10) | ±5.7 | ±6.4 | ±7.3 | 약 13 | 약 9 |
| **200** | ±4.9 | ±5.5 | ±6.4 | 11.2 | 7.9 |
| 300 | ±4.0 | ±4.5 | ±5.2 | 9.1 | 6.5 |
| **400** | ±3.5 | ±3.9 | ±4.5 | 7.9 | 5.6 |
| 600 | ±2.9 | ±3.2 | ±3.7 | 6.5 | 4.6 |

해석: (a) 200쌍에서는 p≈0.2 모델의 정확률 자체가 ±5.5%p 불확실하고, 게이트 임계값 +5.0%p(R9F 평균 대비)는 한 모델 한 시드의 검출 한계(약 8%p)보다 작다. 즉 **200쌍에서는 +5.0%p 게이트가 잡음과 구별되지 않는다.** (b) R10 에서 R10-full 이 R9F 보다 +5.6%p 높았던 것도 149쌍에서는 유의하다고 할 수 없다. (c) 단어 군집(같은 단어의 두 문장은 독립이 아님)을 고려하면 실제 구간은 위 값보다 넓다.

**제안(사전 등록 반영)**: Development 의 대조쌍을 **400쌍(800행)** 으로 늘린다(MDE 약 5.6%p, +5.0%p 임계값과 비슷한 수준). Validation 은 에폭 선정 용도라 정밀도 요구가 낮아 **300쌍**으로 둔다. 독립 테스트는 사양에 **D1P/D1 쌍 300쌍 이상**을 요구한다. 늘려도 R9F 대비 +5.0%p 게이트는 한 시드 점추정으로는 경계 영역이 남으므로, 보고서는 점추정과 군집 부트스트랩 구간을 병기하고 임계값 ±(구간 반폭) 안에 있는 시드를 "경계(불확실)"로 표시한다(통과·탈락 판정은 점추정으로 하며 변경하지 않는다). 쌍 수를 더 늘리는 것은 생성 비용 대비 효과가 작아 제안하지 않는다(600쌍으로 늘려도 MDE 4.6%p).

### 5-4. 데이터 품질·격리 조건

규격 검증기 오류 0, 세트 내부·세트 간 중복 0, 한 글자 이름·호칭 포함 PERSON 구간 0, R9 봉인셋·`r10_dev` 문장·예약 구간 이름 제외, 외부 유료 API 없음. 틀은 LLM 작성이므로 문체 균질성 한계를 명시한다. 독립 테스트의 NEWNAME·LONGNAME 층 크기가 150 미만이면 해당 지표는 보고 전용으로 표기한다.

`r11_dev` 구성(목표 행): D1P/D1 대조쌍 400쌍(800행), B1 150, C2 120, NEWNAME 150, LONGNAME 120, 기존 이름(참조 집합에 있는 이름·정상 문맥) 100, 오탐 음성 4집합(ORG/LOC 문장, 가족호칭만, 이름처럼 보이는 어구 D2, 일반 음성) 집합당 120행 이상(1문장 ≤0.9%p). 합계 1,920행.

### 5-5. 기준선 측정 순서와 상대 기준값 고정 시점

① `r11_val`·`r11_dev` 제작·검증·SHA256 기록 → ② 같은 날 **B 학습 시작 전에**, S0·R9F×5·C10×5·R10-full×5 를 `r11_dev`·R9dev·KLUE val 에서 추론(학습 아님)해 `r11_reference_baselines.json` 으로 저장·**커밋(이 커밋 시점이 상대 기준값 고정 시점)** → ③ B 학습. 이후 B·B-old·B-new·C-SWA 결과를 본 뒤 상대 기준값과 임계값을 바꾸지 않는다. **Recall 게이트의 수치(δ_R9F, σ_R, ε_P)는 같은 시점에 §7-2b 의 공식으로 계산해 `r11_recall_gate_fixed.json` 으로 저장·커밋하고 사용자가 확인한 뒤 B 학습을 시작한다**(B 결과를 보기 전). 같은 파일에 R10-full 시드 13 의 R10 게이트 실패 이력을 그대로 기록한다.

## 6. 체크포인트 선정 기준 (R10 의 `baseline_val` 단독 규칙 대체)

1. B 의 각 런의 모든 학습 에폭 체크포인트를 `r11_val` 로 평가한다.
2. **B-new 선정 지표 = 쌍 문맥 정확률**(§7-1 정의와 같음) 하나.
3. 동률(같은 쌍 수) → `r11_val` 정답 PERSON **Exact Recall** 높은 쪽 → 사람 문장 전체 노출률 낮은 쪽 → `baseline_val` 겹침 F1 높은 쪽 → 더 이른 에폭.
4. 안전 자격: 사람 문장 전체 노출률이 그 런의 최저 에폭보다 1.0%p 넘게 나쁜 에폭은 제외.
5. **B-old** 는 R10 스크립트 규칙(`baseline_val` 겹침 F1 최고, 동률이면 가장 이른 에폭 = `score > best` 첫 최고점)으로 고른 같은 런의 에폭이며 분석 전용이다(교체·후보 자격 없음).
6. **C-SWA** 는 선정 없이 §3-4 규칙으로 고정한다. `r11_dev` 는 어떤 에폭 선정에도 쓰지 않는다.
7. `baseline_val` 은 참고 지표이며 B-old 와 B-new 의 선택 에폭을 모두 표에 남긴다(같은 에폭 비율 포함).

### 6-2. 두 가지 선정의 목적 구분 (섞지 않는다)

| | 체크포인트(에폭) 선정 | 최종 모델(후보) 선정 |
|---|---|---|
| 목적 | **한 런 안에서** 단어 단위 편향이 아니라 문맥으로 D1P(미탐)와 D1(오탐)을 함께 구별하는 에폭을 고름 | **시드·군 사이에서** 사람 이름을 최대한 놓치지 않으면서(Exact Recall 최우선) 오탐·노출 위험이 허용 범위인 모델을 고름 |
| 주 지표 | 쌍 문맥 정확률(`r11_val` 300쌍) | 종합: Exact Recall·공식 Exact F1·전체 노출률(§7-4, `r11_dev`) |
| 세트 | Validation `r11_val` | Development `r11_dev` |
| 대상 | B 의 에폭 4~7개 | B-new·C-SWA 의 시드 10개 모델 |
| 안전 장치 | 노출 1.0%p 초과 악화 에폭 제외 | 게이트 G1~G12 + Recall 게이트 R11-R1~R4 + 군 수준 R11-S |
| Recall 의 역할 | 동률 해소용(첫 동률 기준) | 핵심 지표 3개 중 하나(단독 1순위 아님), 하한은 R11-R1~R3 게이트 |
| 금지 | `r11_dev` 로 에폭을 고르지 않음 | `r11_val` 을 후보 선정에 쓰지 않음 |

## 7. 사전 등록 안전성 게이트 (시드별 단일 모델, `r11_dev`, 같은 평가 코드)

### 7-1. 지표 정의와 평균·표준편차 산출

| 지표 | 정의 | 평가셋 |
|---|---|---|
| 노출률 | 정답 PERSON 구간 단위. **완전 노출** = 구간의 가려진 글자 0, **부분 노출** = 일부만 가려짐, **전체 노출** = 완전+부분 = 1 − 완전 가림 비율. 1글자 이름 행 제외 | 유형별(D1P·B1·C2·NEWNAME·LONGNAME·기존 이름) 및 전체 |
| 오탐률 | 정답 PERSON 이 없는 문장 중 최종 PERSON 을 낸 문장 비율. D1 오탐률 = D1 명사 문장 + 명사만 문장 | 오탐 음성 4집합, D1 |
| **쌍 문맥 정확률** | 같은 단어의 쌍 중 **사람 문장의 정답 구간이 완전히 가려지고(경계 초과 허용) 명사 문장에서 PERSON 이 나오지 않은 쌍**의 비율 = (정확한 쌍 수)/(전체 쌍 수) | `r11_dev` 400쌍, 선정은 `r11_val` 300쌍 |
| **PERSON Exact Span Recall(최우선)** | TP = 예측 구간(PERSON·PERSON_ALIAS)의 시작·끝이 정답 구간과 **정확히 같은** 수, FN = 정확 일치하지 못한 정답 구간 수(완전 미탐, 부분 가림, 경계가 다른 가림 모두 포함). **Recall = TP/(TP+FN)**, 1글자 이름 행 제외 | `r11_dev` 전체·유형별(D1P·B1·C2·NEWNAME·LONGNAME·기존 이름), KLUE val |
| PERSON Exact Span Precision | **공식 Precision = TP/(TP+FP)**, FP 는 정답 있는 문장의 불일치 예측만 센다(공식 채점). 보조로 **전체 Precision**(정답 없는 문장의 FP 도 포함) 병기 | 위와 같음 |
| PERSON Exact Span F1 | 2PR/(P+R), 공식 Precision 기준, 전체 Precision 기준 병기 | 위와 같음 |
| KLUE F1 | KLUE val 5,000행 PERSON Exact F1, 한 글자 정답은 미탐으로 포함, 공식 채점 방식(R10 KLUE 분석과 동일, 본문 열람 안 함) | KLUE val |
| **Recall 과 노출률의 관계** | 정답 구간 하나는 ① 정확 일치(Recall 맞음, 노출 0), ② 경계가 다르지만 완전히 가려짐(Recall 틀림, 노출 0, "경계만 틀림"), ③ 일부만 가려짐(둘 다 틀림, 부분 노출), ④ 전혀 안 가려짐(둘 다 틀림, 완전 노출) 중 하나. **Recall = 1 − (완전 노출 + 부분 노출 + 경계만 틀림)**, 가림률 = 1 − 전체 노출률이므로 가림률 − Recall = 경계만 틀린 비율. 두 지표를 따로 보고하고 "경계만 틀림" 비율을 별도 열로 낸다(과대 마스킹은 노출은 아니지만 Recall 에서는 손실로 센다) | `r11_dev` |
| **Recall 5시드 통계** | 시드별 Recall, 평균, 모집단 표준편차(분모 5, 표본 표준편차 병기), 최악값(최소), 범위, 단어·이름 군집 부트스트랩 95% 구간(1,000회, 시드 고정) | 모든 군 |
| 표적 매크로 노출률 | 한 모델에서 D1P·B1·C2·NEWNAME·LONGNAME **5개 유형 각각의 전체 노출률의 단순 평균**(유형 구간 수로 가중하지 않음) | `r11_dev` |
| 5시드 평균 | 5개 시드 값의 산술평균(탈락 시드 포함, 제외 없음) | - |
| 5시드 표준편차 | **모집단 표준편차(분모 5)**, 병기로 표본 표준편차(분모 4) 보고. R10 분석(2.0·5.6·10.5)이 모집단 표준편차였으므로 같은 정의 | - |
| 최악값 | 5시드 중 가장 나쁜 값 | - |

**분모와 평가 대상 정의(r11-1.2)**

| 지표 | 분자 | 분모 | 평가 대상 문장 |
|---|---|---|---|
| Exact Recall | 정확 일치한 정답 PERSON 구간 | 정답 PERSON 구간 전체(1글자 이름 행 제외) | 정답 PERSON 이 있는 모든 `r11_dev` 문장(대조쌍의 사람 문장 포함, 명사 문장·음성 문장은 정답 구간이 없어 분모에 기여하지 않음) |
| 공식 Precision | 정확 일치한 예측 구간 | 정답 PERSON 이 있는 문장에서 낸 예측 구간 수 | 정답 PERSON 이 있는 문장만(R9·R10 공식 채점과 같음) |
| 전체 Precision | 같음 | **모든 문장**(음성 문장·명사 문장 포함)에서 낸 PERSON 예측 구간 수 | `r11_dev` 전체. R11-R4 ① 에는 **전체 Precision** 을 쓴다(Recall 을 위해 음성 문장에서 낸 오탐이 가려지지 않게) |
| 비PERSON 오탐률 | PERSON 예측이 하나라도 있는 문장 수 | 정답 PERSON 이 없는 문장 수 | 오탐 음성 4집합(각 120행 이상) 매크로(집합별 비율의 단순 평균). D1 오탐률의 분모는 D1 명사 문장 + 명사만 문장 |

**Exact Recall 과 가림률의 차이와 검증 항등식**: 정답 구간은 서로 배타적인 4가지(① 정확 일치 ② 경계만 틀림(완전 가림이지만 경계가 다름) ③ 부분 노출 ④ 완전 노출) 중 정확히 하나로 분류한다. 가림률 = ① + ②, Recall = ①, 전체 노출률 = ③ + ④ = 1 − 가림률. 따라서 **경계만 틀림(②) = 가림률 − Recall** 이다. 평가 코드는 구간별 분류에서 ②를 독립적으로 세고 `② == 가림률 − Recall` (구간 수 정수 비교)이 모든 모델·유형에서 성립하는지 단위 시험과 보고서 생성 시 검증하며, 성립하지 않으면 보고서를 생성하지 않는다.

### 7-2b. Recall 안전성 게이트 R11-R1~R4 (추가, 기존 G1~G12 는 그대로 유지·완화 없음)

Recall 기준은 **기존 게이트에 더해 모두 추가로** 충족해야 한다(AND). 허용 폭은 아래 **공식**으로 정하고, 수치는 §5-5 기준선 측정 뒤 B 학습 전에 계산·커밋한다. 공식은 지금 고정하며 기준선 값(S0·R9F 5시드 Recall)만 나중에 대입한다.

| 게이트 | 대상 | 기준 |
|---|---|---|
| **R11-R1 R9F 대비 비열화** | `r11_dev` 전체 PERSON Exact Recall | Recall_model ≥ mean(R9F 5시드 Recall) − δ_R9F. **δ_R9F = clamp(R9F 5시드 Recall 모집단 SD, 0.5%p, 1.5%p)**(R9F 자신의 시드 잡음 수준이며 상한 1.5%p) |
| **R11-R2 S0 대비 개선** | 전체 PERSON Exact Recall | Recall_model > Recall_S0 (소수 둘째 자리 반올림 후 엄격히 큼). 개선폭의 신뢰구간은 병기 |
| **R11-R3 취약 유형 Recall** | D1P·B1·C2·NEWNAME·LONGNAME 유형별 Exact Recall | 각 유형 Recall_model ≥ Recall_S0 − 0.0%p(S0 보다 낮지 않음) 이고 ≥ mean(R9F) − δ_R9F |
| **R11-R4 Recall 개선의 오탐 대가** | 비PERSON 오탐·전체 Precision | **기준 모델은 S0**(같은 `r11_dev`, 같은 평가 코드): ΔRecall = Recall_model − Recall_S0, ΔFP = (오탐 음성 4집합 매크로 오탐률_model) − (같은 값_S0). ① 전체 Precision ≥ Precision_S0 − ε_P, **ε_P = 3.0%p**(기본값, 기준선 측정 뒤 변경하려면 사용자 확인·커밋 전에만 가능) ② **ΔFP ≤ 0.5 × ΔRecall + 1.0%p** (Recall 이 많이 늘지 않았는데 오탐만 늘어난 모델 배제; R9F 는 기준 모델이 아니며 R9F 대비 비교는 R11-R1 에서만 쓴다). 기존 G1(+2.0%p)·G6(+3.0%p)은 그대로 적용 |

R11-R4 ②의 계수(0.5, 1.0%p)와 ε_P=3.0%p 는 임의 선택이며 근거는 기존 G1 한도(+2.0%p)와 Recall 개선의 균형이다(R10 관찰에서 도출한 값이 아님). 모든 수치는 기준선 측정 뒤 `r11_recall_gate_fixed.json` 에 기록하고 이후 변경하지 않는다. **"모든 단어를 PERSON 으로 판단"하는 퇴화 모델 방지**: Recall 이 높아도 G1(오탐 집합)·G6(D1 오탐)·R11-R4 가 막는다.

### 7-2c. 신뢰구간과 게이트 판정의 관계, 보고 규칙 (r11-1.2)

- **게이트 판정은 점추정으로 한다**(소수 둘째 자리 반올림, 경계값은 통과). 신뢰구간(단어·이름 군집 부트스트랩 95%, 1,000회, 시드 고정)은 판정을 바꾸지 않으며 모든 게이트 값 옆에 병기한다.
- **경계 표시**: 점추정이 임계값에서 구간 반폭 이내이면 "경계(불확실)"로 표시한다. 통과·탈락 결정은 바뀌지 않는다. 구간이 임계값을 완전히 가로지르면 보고서에 "통과/탈락 판정은 점추정이며 통계적으로 확정된 것이 아님"을 명시한다.
- **보고 규칙**: ① 두 모델·두 군의 차이는 95% 구간이 0 을 포함하면 "통계적으로 확정된 개선(악화)"이라 쓰지 않고 "점추정 차이, 불확정"으로 쓴다. ② 5시드 평균 차이는 시드 분포(표준편차·범위)를 함께 쓰고, 시드 간 분포가 겹치면 "시드 변동 범위 안"이라고 쓴다. ③ 차이가 구간 반폭보다 작으면 개선·악화라고 단정하는 표현("개선했다", "악화시켰다")을 쓰지 않는다. ④ 단일 시드가 게이트를 통과한 것은 모델 일반의 안전을 뜻하지 않는다. ⑤ 게이트를 결과에 맞춰 완화·재해석하지 않으며, 탈락은 탈락으로 기록한다.

| 항목 | 규칙 |

| 시드 통과(eligible) | 한 모델이 R11-G1~G12 **와 Recall 게이트 R11-R1~R4 를 모두** 통과 |

### 7-4. 후보 선정: 종합 성능 중심 규칙 (r11-1.3, B 학습 결과 전 사전 등록)

**변경 기록**: r11-1.0 은 표적 매크로 노출률, r11-1.1 은 Exact Recall 을 1순위로 했으나 최종 결정(2026-11-20)에 따라 **Recall·Precision·F1·실제 노출률을 함께 보는 종합 규칙**으로 바꾼다. 게이트는 바꾸지 않는다. 학습 전 변경이며 R9·R10 이력에는 영향이 없다. **수치 가중치·점수식은 쓰지 않는다**(아래 규칙은 순위와 우열 비교만 쓰고 가중치가 없다).

**후보 집합**: R11-S 를 통과한 군의 eligible 시드(G1~G12 와 R11-R1~R4 전부 통과). B-new 군과 C-SWA 군의 모델을 한 집합으로 본다. **게이트·R11-S 를 통과하지 못한 모델은 어떤 지표가 높아도 후보가 아니다**(Recall 을 높이려고 이름이 아닌 단어까지 PERSON 으로 내는 모델은 G1·G6·R11-R4 가 막는다).

**비교 지표(모두 `r11_dev` 전체, 같은 모집단·TP/FP/FN 정의, §7-1)**: 핵심 3개 = ① 공식 Exact Recall(높을수록) ② 공식 Exact F1(높을수록) ③ 전체 PERSON 노출률(낮을수록). 값은 **소수 첫째 자리 %로 반올림한 값**으로 비교한다(0.1%p 미만 차이는 같은 값). 공식 Precision 은 F1 에 포함되고 R11-R4 의 하한과 아래 동률 처리에 쓰며, **전체 Precision(음성 문장 FP 포함)은 별도 보고**한다.

**1단계: 열세 후보 제거(우위 제거)**: 후보 A 가 후보 B 를 지배한다 = A 가 핵심 3개 지표 모두에서 B 보다 나쁘지 않고(반올림값 기준) 적어도 하나에서 B 보다 좋다. 지배당한 후보를 제외한다. 모든 후보 쌍을 처음 후보 집합 전체에 대해 한 번에 평가한다(순환 지배로 전부 제외되면 제외하지 않음). "주요 지표에서 모두 열세인 후보"가 먼저 사라진다.

**2단계: 순위합**: 남은 후보에 대해 핵심 3개 지표별 순위(1 = 최선, 반올림값이 같으면 같은 순위, 다음 순위는 건너뜀)를 매기고 **순위의 합이 가장 작은 후보**를 고른다. 세 지표에 같은 비중을 둔다는 것 외에 가중치는 없다.

**3단계: 결정적 동률 처리(순위합이 같은 후보만, 순서대로 한 단계에서 한 명이 되면 종료)**: (a) 세 순위 중 가장 나쁜 순위가 더 좋은 쪽(minimax) → (b) 표적 5유형 매크로 노출률이 낮은 쪽(반올림값) → (c) 비PERSON 오탐 매크로가 낮은 쪽 → (d) 공식 Exact Precision 이 높은 쪽 → (e) 소속 군의 Exact Recall·D1P 노출률 표준편차의 합이 작은 쪽(시드 안정성) → (f) ONNX CPU 문장당 지연이 짧은 쪽 → (g) 시드 번호가 작은 쪽.

**적격 후보가 없으면** 독립 테스트를 열지 않는다. 단일 시드 선정의 낙관 편향(R9: 개발 3.56% vs 독립 11.29%)과 소표본(Recall 신뢰구간 약 ±2.2%p)을 보고에 명시하고, 후보 간 차이가 구간 안이면 "확정된 우열"이라 쓰지 않는다(§7-2c).

**선정 규칙 변경 이력**: r11-1.0(표적 매크로 노출 1순위) → r11-1.1(Exact Recall 1순위) → r11-1.3(종합: 우위 제거 → 순위합 → 동률 처리). 어떤 버전도 B 학습 결과를 본 뒤에 바꾸지 않는다.

## 9. 최종 모델 비교 기준 (R11 결과를 보기 전에 고정)

### 9-1. 두 개의 분리된 판정

| 구분 | 대상 | 성격 |
|---|---|---|
| **(가) 교체 적격 판정** | **R11 후보(개발 게이트 통과 모델) 한 개**를 S0 와 비교 | 사전 등록 교체 기준(§9-3). 합격해야 운영 교체를 권고 |
| **(나) 연구 비교** | S0, R9F 시드 13, **R10-full 시드 13**, R11 후보를 **같은 독립 테스트에서 같은 코드로** 측정 | 기술 통계와 짝지은 비교만. **R9F·R10-full 에는 교체 적격 판정을 하지 않는다** |

- R9F·R10-full 의 기존 게이트 실패 이력(R9F: 조건 5 D1P +4.0%p 악화, R10-full 시드 13: R10 G1·G6 등 실패 및 G11 실패)은 **그대로 유지**하며 R11 평가가 이를 무효화하지 않는다. R9F·R10-full 은 **자동으로 운영 교체 후보 자격을 갖지 않는다.**
- **R10-full 비교용 시드는 13 으로 사전 고정**한다. 선택 근거는 R9F(시드 13)와의 시드 정렬이며 R10 결과를 보고 고른 것이 아니다. R10-full 시드 13 의 R10 개발 평가 결과는 `r11_reference_baselines.json` 에 기록한다.
- **독립 테스트에 포함할 모델**: S0, R9F 시드 13, R10-full 시드 13, R11 후보. **R11 후보가 없으면 독립 테스트를 실행하지 않는다**(R9F·R10-full 만을 위한 독립 평가도 하지 않는다).
- 서로 다른 세트의 수치는 같은 결과표에 넣지 않는다. R9 봉인 세트 값(11.29%), R9dev(3.56%), `r10_dev`, `r11_dev`, 독립 테스트는 단계 열에 구분해 따로 표기한다.

### 9-2. 독립 테스트에서 비교할 지표(모든 모델 동일)

대표·스트레스 세트 따로: **Exact Recall(최우선)**·Exact P/F1, 전체·완전·부분 PERSON 노출률, 유형별(D1P·D1·B1·C2·NEWNAME·LONGNAME·ORG/LOC 혼합) 노출·오탐률, 쌍 문맥 정확률(300쌍 이상), 비PERSON 오탐률, 과잉 병합, 짝지은 개선·악화 건수, 군집 부트스트랩 95% 구간, CPU 지연·모델 크기. 평균 내지 않음.

### 9-3. 교체 적격 기준 ((가), R11 결과 전 명시)

독립 테스트에서 `NER_R10_PREREGISTRATION.md` §7 의 교체 권고 조건 1~11(전체 노출 감소, 비PERSON 오탐, Exact F1, 과잉 병합, 스트레스 유형 악화 한도, D1P, B1·C2, 부분 노출, NEWNAME, 스트레스 오탐, CPU·크기)을 **완화 없이 모두 충족**하고, **추가 조건 12: 대표·스트레스 각각 Exact Recall 차이(후보−S0)의 점추정 ≥ 0.0%p 이고 95% 구간 하한 ≥ −1.0%p**, 후보가 속한 군이 개발 단계 R11-S(④⑤ 포함)를 통과해야 한다. 개발 평가 후 모델·후처리·시드를 바꾸지 않는다. 최종 결정은 사용자가 한다.

적격 모델이 하나뿐이면 그 모델이 권고 대상. 여럿(예: B-new 와 C-SWA)은 이미 §7-4 로 후보 한 개로 줄어든 상태이므로 여기서 다시 선택하지 않는다. 우선순위(점수식 없이): ① **종합 성능**(대표·스트레스에서 Exact Recall·공식 Exact F1·전체 노출률, 완전·부분 노출과 D1P·B1·C2 최악 유형 함께 보고, 구간이 겹치면 동률, 한 지표로만 우열을 정하지 않음) ② 유형별 안전성(어떤 유형도 S0 대비 +2.0%p 넘게 악화되지 않음) ③ 비PERSON 오탐·과잉 병합 ④ 모델 안정성(5시드 표준편차·최악값) ⑤ 서비스 적용 가능성(CPU 지연·크기, 공유 모델이 다른 에이전트에 미치는 영향, 소통 전용 분리 필요 여부; 방안 B 는 `NER_R10_MODEL_SEPARATION_DESIGN.md`, 구현은 별도 승인). Exact F1 단독 최고 모델은 선택하지 않는다. **적격 모델이 없으면 S0(v2b)를 유지하는 것이 정당한 결론이며 독립 테스트는 실행하지 않는다.** 한 글자 PERSON 이름은 범위 제외이며 노출 위험이 해결됐다는 뜻이 아니다.

## 12. 알려진 한계

- 개발셋 쌍 400개로 늘려도 단일 시드 정확률의 신뢰구간은 ±3.9%p(p=0.2)이고, 5시드·단일 시드 선정은 낙관 편향이 있다(R9 개발 3.56% vs 독립 11.29%).
- B 는 통합 데이터 구성 전략이며 요소별 기여를 분리하지 않는다(H4·H5 도 확증하지 않음). C10 재사용으로 학습 환경이 R10 과 R11 로 갈린다(같은 코드·레시피).
- B-new 의 에폭 후보는 `baseline_val` 조기 종료가 정한 범위이고 포화로 같은 에폭이 선택될 가능성이 있다.
- 가중치 평균 창에는 `baseline_val` 악화 구간이 포함될 수 있어 효과가 없거나 반대일 수 있다.
- 합성 데이터·같은 계열 LLM 틀로 문체 균질성이 높고 가족 메신저 분포의 대표성을 주장하지 않는다.
- `merge_ner` 점수 임계값(0.5)은 바꾸지 않는다(공용 코드 변경 범위 밖).
- KLUE 라이선스(법무 검토)와 기반 모델 라이선스 확인은 미해결이다.
- 독립 테스트 사양의 제작·봉인 상태와 쌍 300쌍 이상 요구의 사양 반영은 사용자 확인이 필요하다.
- Exact Recall 은 경계가 다르게 완전히 가려진 경우(과대 마스킹)도 손실로 세므로 개인정보 노출 위험과 다르다. 두 지표를 분리 보고하며, Recall 을 1순위로 두어도 노출·오탐 게이트가 필수 조건으로 남는다. Recall 신뢰구간은 `r11_dev` PERSON 구간 약 1,000개 가정 시 p≈0.85 에서 ±2.2%p 정도이며(제작 후 실제 구간 수 기록) δ_R9F 하한(0.5%p)보다 넓다. R11-R1 은 점추정 판정이라 구간 안의 시드는 "경계"로 표시한다.
- Recall 게이트 계수(R11-R4: 0.5, 1.0%p, ε_P 3.0%p)는 임의 선택이며 R10 관찰값에서 도출하지 않았다.

**G7 기준선 판정 재확인**(`R11-G7`: 쌍 문맥 정확률 ≥ R9F 5시드 평균 + 5.0%p = 18.5% + 5.0 = 23.5%, `r11_dev` 400쌍, 점추정 소수 둘째 자리 반올림 비교, 경계 통과). 모델별 원시 값(맞은 쌍/400쌍): S0 48(12.00%), R9F 시드 7·13·21·42·99 = 83·70·81·56·80(20.75·17.50·20.25·14.00·20.00%), C10 76·48·85·90·86(19.00·12.00·21.25·22.50·21.50%), R10-full 70·84·109·109·107(17.50·21.00·27.25·27.25·26.75%). **통과는 R10-full 시드 21·42·99 뿐**이다. R10-full 5시드 평균 23.95% 는 기준 23.5% 를 넘지만 개별 시드는 3/5 만 통과한다(게이트는 시드별 판정이므로 평균 통과가 시드 통과를 뜻하지 않는다). 이전 보고의 "기존 15개 모델 모두 G7 미달"은 **판정 코드가 아니라 제 요약 문장의 오류**였고(코드 출력은 시드 21·42·99 가 G7 을 통과로 표시), 코드·고정 임계값은 그대로다. 반올림 전후 판정 차이는 없다(경계 근처 값 없음: 최근접 개별 값 21.00%·22.50% 대 기준 23.50%). 평가셋·코드 일치: 기준선 JSON 3개의 `r11_dev` 해시가 모두 현재 파일과 같고(`325383a7c49c…`), 평가 코드(`r11_eval_lib.py`·`evaluate_r11_dev.py`)는 평가 시작 전 마지막 수정이었으며 평가 후 변경 없음(파일 시각 20:47·20:53, 평가 20:58~21:23), 결과의 git head 는 `4ebd5844`(미커밋 파일 포함 시점).

**후보 선정 1단계(우위 제거) 검증**: 사용자 정의(A 가 Recall≥, F1≥, 노출≤ 이고 하나 이상 엄격 우수이면 B 제거)와 같은 규칙임을 독립 구현으로 대조했다. 단위 시험(`test_select_r11_pareto.py` 6개)은 우수 후보가 거꾸로 제거되지 않음, 입력 순서에 무관, 한 지표 단독 최고는 제거되지 않음, 상충 후보는 둘 다 유지, 동일 지표는 서로 제거하지 않음, 반올림 경계를 확인한다(합성 400 세트 속성 시험 포함). **반올림 구현을 명확히**: 비교 값은 비율×100 을 소수 첫째 자리에서 **0.5 올림**(부동소수 오차를 먼저 9자리로 정리)하고, 게이트 비교는 둘째 자리 같은 방식이다(이전 코드는 파이썬 기본 반올림이라 0.5 경계에서 달랐을 수 있다. 실질 변경 아님).
**0.1%p 반올림의 영향(합성 후보 5,000세트 모의, `analysis_select_rounding.py`)**: 반올림 없이 비교했을 때와 선정 결과가 달라지는 비율 1.7%, 우위 제거 집합이 달라지는 비율 4.2%, 0.5%p 로 거칠게 반올림하면 각각 5.8%·13.2%. 순위합 동률로 3단계 동률 처리가 필요한 비율은 3.8%. 즉 0.1%p 반올림은 노이즈 수준 차이를 같은 값으로 묶는 효과이며 선정 결과를 크게 바꾸지 않는다. **동일 비중 순위합의 해석**: 순위합은 세 지표(Recall, F1, 전체 노출)에 같은 비중을 두는 서수 규칙이라 **차이의 크기를 반영하지 않는다**(Recall 이 0.1%p 앞서도 5%p 앞서도 1순위 하나로 센다). 이를 보완하려고 우위 제거로 명백한 열세를 먼저 걸러내고, 동률은 minimax 순위 → 취약 유형 노출 → 오탐 → Precision → 시드 안정성 → 지연 순으로 결정적으로 처리한다. 가중치 합산이나 점수식은 쓰지 않으며, 후보 간 차이가 신뢰구간 안이면 확정된 우열이라 쓰지 않는다(§7-2c).

**G12 판정 구현**(`g12_parity.py`, `g12_latency.py`, `g12_r11.py`, 시험 7개): 조건은 사전 등록 그대로(ONNX 토큰 일치 ≥99.9%, CPU 문장당 지연·모델 파일 크기·RSS 가 S0 +30% 이하). **판정 통계(명확화)**: 지연은 반복 사이 중앙값 p50 의 후보/S0 비로 판정하고 p95·평균 비는 보고한다. 일치 비교: 같은 가중치의 PyTorch(CPU fp32)와 ONNX(CPU fp32), 고정 문장 1,000개(`r11_val` 600 + `baseline_val` 180 + `synth_val` 앞 220, 문장 목록 해시 기록), 문장별(배치 1) 토큰 argmax. 지연 측정 환경 고정: ONNX Runtime CPU, 스레드 2, 문장 하나씩, 워밍업 30문장(측정 제외), 측정 300문장(`r11_val` 시드 고정 추출, 모든 모델 같은 목록) 5회 반복, 문장마다 서비스 NER 캐시 비움, 프로세스당 모델 하나, S0·후보·후보·S0·S0·후보 순서로 교차 6회, 측정 전 CPU 사용률·가용 RAM·ORT 버전 기록. 실패(한 항목이라도 위반)는 후보 적격 판정에서 제외된다(`select_r11.py` 는 G12 가 true 일 때만 eligible). 서비스 공용 NER 코드·운영 ONNX 는 읽기만 했고 수정하지 않았다.

**사람 검수 진행 상태(2026-11-20)**: 표본 519개(학습 120·Validation 90·Development 309)는 이전과 같다. 화면 순서만 바꿔 자동 검사에서 의심된 **22행을 맨 앞("우선")** 에 두고, 그 22행만 담은 별도 파일 `review_priority_packet.html` 도 만들었다(`data_r11/review/`, 저장소 밖, 외부 전송 없음). 확인 항목: D1P·D1·B1·C2 라벨과 쌍의 문맥 구분, BIO 라벨과 실제 PERSON 구간 경계, 조사 결합, 별명 충돌, 부자연스러운 표현. **사람 검수는 아직 수행되지 않았고 결과 파일이 없다.** 집계기(`r11_review_ingest.py`)는 우선 파일과 전체 파일을 함께 받으며, 판정이 없는 표본 항목은 **자동으로 통과 처리하지 않고 미판정으로 센다**(빈 결과를 넣으면 `needs_action`, 합성 판정으로 전부 정상이면 `pass`, 오류를 넣으면 `needs_action` 이 되는 것을 확인). 오류가 확정되면 영향을 받는 데이터와 수정 범위를 보고하고, 기준선·해시 재계산 전에 사용자 확인을 받는다.

**독립 평가셋 2,350문장 안**: 사양 개정본 §15 의 수량 검증표에서 모든 필수 조건(D1P/D1 300쌍·필드, LONGNAME 120, ORGLOC_MIX 100, B1 240, C2 200, 신규 이름 310+150, 회귀 대표 1,600, 데이터 분리, 봉인·1회 평가)을 충족하는 것을 확인했고, 유형 합이 맞지 않던 PERSON 포함/기타/없음 열을 정정했다(1,800 / 50 / 500). 최종 사양으로 제안한다. 생성·봉인은 하지 않았다.
