# R11 사람 검수 미완료 상태의 자동 검증 기반 품질 관리 전환안 (제안, 사용자 승인 전 · 사전 등록 r11-2.0 안)

2026-11-20 작성. **상태 갱신: 사용자가 조건부 승인(2026-11-20)했고 연구용 전환 조건은 `NER_R11_PREREGISTRATION_v2_0.md`(r11-2.0)에 반영했다.** 사람 검수 519건과 선택 22행 부분 검수는 하지 않기로 했으며, 이 제안서의 §5 항목 가운데 r11-2.0 에 옮겨 적은 것만 효력이 있다. 정식 검증·운영 교체 자격은 없다.

## 0. 보존되는 사실 (변경하지 않음)

- 사전 등록 r11-1.4 §4-4 는 B 학습 전에 **사람 표본 검수(519개) 통과**를 요구한다. **이 요건은 충족되지 않았다.** 판정 파일이 없고 519개 전부 미판정이며, 미판정은 통과가 아니다. 제가 판정을 만들거나 대신 입력한 적이 없다.
- 사람 검수를 대체하는 것이 아니라, 검수가 없는 상태에서 연구를 **무엇까지** 진행할 수 있는지와 **무엇은 못 하는지**를 구분하는 안이다.
- 데이터 원문은 외부 LLM·서비스로 보내지 않았고 모든 검사는 로컬 코드로 했다(`r11_auto_qa.py`, 결과에는 원문·이름·단어가 없다).

## 3. 학습·평가에 미치는 영향

### 3-1. Development 의심 행 제외 시 기준선 모델 지표와 게이트 판정 변화 (정확 계산, 데이터 수정 없음, `r11_flagged_sensitivity.json`)

기준선 15개 모델을 의심 행에만 다시 추론해 개수를 빼서 지표를 다시 계산하고, 고정 임계값으로 게이트를 다시 판정했다.

| 시나리오 | 제외 행 | 지표 최대 변화(모든 모델) | 게이트 판정이 뒤집힌 모델 |
|---|---:|---|---|
| 의심 Development 행 전부 | 12 | Recall 0.16%p, 전체 노출 0.10%p, 쌍 정확률 0.35%p, 표적 매크로 0.20%p, F1 0.21%p | 4개 모델(S0 G8, R9F 시드 13 G5, R10-full 시드 13 R3, R9F 시드 99 R3) |
| 확정 S·F 4행(C2 4행)만 | 4 | Recall 0.17%p, 노출 0.12%p, F1 0.15%p | 3개 모델(S0 G8, R10-full 시드 13 R3, R9F 시드 99 R3) |

해석: 지표 변화는 0.4%p 미만으로 작지만, **고정 임계값에 가까운 모델은 몇 행 차이로 판정이 뒤집힌다**(C2 Recall 하한 R11-R3 와 R10-full 시드 13: 46.2% 대 45.8%). 이는 이 의심 행들만의 문제가 아니라 Development 의 작은 유형 표본(C2 120행)에서 임계값 근처 판정이 갖는 일반적인 민감도다. 따라서 **B 학습 결과 보고 때 게이트 값이 임계값에서 가까운 경우 "경계"로 표시**하고(§7-2c, 이미 사전 등록), 아래 §5 의 제외 민감도 시나리오를 항상 병기한다. 데이터를 지금 수정하면 기준선·상대 게이트를 전부 재계산해야 하는데 확정 라벨 오류가 없으므로 **수정을 권고하지 않는다**.

## 5. 전환안 (사전 등록 r11-2.0 안, 승인 시에만 적용)

1. **표기**: 이 라운드의 모든 성능표·보고서에 "자동 검증 기반 연구용 · 사람 의미 검수 미완료(519 미판정)"를 병기한다.
2. **학습 허용 조건 변경**: §4-4 의 "사람 검수 통과" 대신 "자동 검증에서 확정 구조 오류 0, 확정 표면 오류·의미 경고 문서화, 데이터 변경 없음 또는 변경 시 기준선·게이트 재고정"으로 연구용 학습을 허용한다. **교체·정식 검증 자격에는 이 대체를 적용하지 않는다.**
3. **교체 자격 조건**: 운영 교체 권고는 (가) 사람 의미 검수 완료·통과(기존 §4-4 기준) **그리고** (나) 독립 테스트 통과가 모두 있을 때만 가능하다. 어느 하나라도 없으면 결론은 "S0 유지 + 연구 결과 보고"다.
4. **후속 사람 검수**(선택, 학습 전·후 모두 가능, 모델 예측과 무관한 데이터 검수라 편향이 없다): 완료하면 상태를 "의미 검수 완료"로 올릴 수 있다. 검수에서 Development 오류가 나오면 **해당 행을 지우지 않고 제외 목록으로 두고** 제외 후 게이트를 다시 판정해 병기하며, 판정이 뒤집히면 해당 후보는 "경계 판정(교체 불가)"으로 둔다.
5. **제외 민감도 병기**: B 결과 보고에 의심 12행(Development)을 제외한 지표·게이트 판정을 항상 함께 낸다(`r11_flagged_sensitivity.py`). 게이트 판단은 원 데이터 기준이다.
6. **최소 부담 대안(선택)**: 우선 22행(14단위)만 사람이 보는 방법(약 10~15분). 완료해도 "519 전수 검수"가 아니므로 상태는 "부분 검수(22행, 의심 사례 한정)"로만 기록하며 정식 검증 자격을 만들지 않는다.
7. **변경하지 않는 것**: R11-G1~G12, R11-R1~R4, R11-S, 종합 성능 선정 규칙(r11-1.3), G12, 고정 기준선·Recall 게이트 수치.

## 6. 마지막 B군 학습 5회 진행 조건 (연구용, 승인 후)

| 조건 | 현재 |
|---|---|
| 자동 품질 검사에서 중대한 구조 오류 없음 | **충족**(S 0건) |
| 해결되지 않은 경고와 품질 한계 문서화 | **충족**(§2·§4, 결과 보고서에 그대로 표시) |
| 데이터 변경이 있다면 기준선·게이트 재고정 | 변경 없음(권고도 하지 않음) → 재고정 불필요 |
| 새 사전 등록 절차 확정 | **미충족**: 이 제안서(r11-2.0 안)의 사용자 승인과 커밋·태그 필요 |
| 학습 데이터·평가 코드·모델 해시 고정 | 데이터·코드 고정은 `r11_pretrain_check.py --write-pin` 로 승인 뒤 수행. 모델 해시는 학습 실행기가 기록 |
| G1~G12, R1~R4, R11-S 유지 | 유지 |
| 학습 직전 점검(RAM·디스크·GPU, A군 해시, 9,915행 해시) | 통과(최근 실행, 학습 직전 다시 실행) |
| 첫 GPU 실행에서 `best/`==`epoch_best/` 일치 | 실행기가 자동 확인(불일치 시 중단) |

위 "새 사전 등록 절차 확정" 하나만 남아 있고, 승인 후 `r11_pretrain_check.py` 는 (1) 사람 검수 verdict 대신 자동 검증 통과와 문서화된 품질 한계를 확인하도록 갱신한다(이 갱신도 승인 범위 안에서만).

## 7. 검수 미실시 상태에서 최종 모델 선정 시 발생할 수 있는 위험

1. **쌍 문맥 정확률(G7)·D1P/D1 게이트의 타당성**: 쌍 단서가 약한 쌍(Development 9쌍 등)이나 어색한 쌍이 있으면 "문맥 구분" 점수가 모델의 능력이 아니라 데이터의 모호함을 반영할 수 있다. 모든 모델에 같이 작용하지만 상대 비교를 흐릴 수 있다.
2. **외래어·부자연스러운 단어를 이름으로 쓴 쌍**: 실제 사용자 대화 분포와 어긋난 신호를 학습하거나 평가한다.
3. **게이트 경계 판정의 민감도**: §3-1 처럼 몇 행 차이로 경계 모델의 통과·탈락이 바뀔 수 있다.
4. **일반화 격차**: 개발 평가 결과가 독립 평가에서 크게 나빠질 수 있다(R9: 개발 3.56% 대 독립 11.29%). 사람 검수가 없으면 개발셋 자체의 품질 한계를 확인하지 못한다.
5. **합성 데이터의 균질성**: 같은 계열 LLM 틀과 일부 스크립트 결합 틀로 실제 가족 메신저 분포를 대표하지 않는다.
6. **결론의 지위**: 위 이유로 R11 결과는 "연구용"이며 운영 교체 근거가 되지 못한다. 적격 후보가 있어도 사람 검수와 독립 테스트가 없으면 교체를 권고하지 않는다.

## 8. 필요한 결정

1. 이 전환안(r11-2.0 안)을 승인할지, 수정할지.
2. 선택 사항: 우선 22행(14단위) 부분 검수를 할지(약 10~15분, 정식 자격은 생기지 않음).
3. 승인 시: 새 버전 커밋·태그 후 `r11_pretrain_check.py` 갱신·코드 고정, 그다음 B 5회 학습 최종 승인.
