# [ChatGPT 전달용] GaBee 한국어 개인정보(이름) 탐지 독립 평가셋 R11 작성 지시서 (정책 r9-1.1, 사양 r11-1.0)

> **이 문서만 읽고 작업하세요.** 이 문서 밖의 어떤 학습 데이터·평가 데이터·모델 결과도 참조하지 마세요. 저장소·파일을 열람하지 말고, 이 대화에서 아래 지시만 따릅니다. 이 지시서에는 의도적으로 학습 쪽 예시 문장·이름·단어가 없습니다.
> 정책: `이름+가족호칭`은 **이름 부분만 PERSON**, 호칭은 태그 밖. `PERSON_ALIAS` 는 실제 별명 자체만. 호칭만 있는 문장은 음성. 1글자 이름은 쓰지 않습니다.

당신은 한국어 **가족 메신저 대화**에서 개인정보(특히 사람 이름)를 탐지하는 모델을 평가할 **독립 평가셋**을 만듭니다. 당신이 쓴 문장은 모델 학습·튜닝·후보 선정에 쓰이지 않으며 최종 평가에서 **한 번만** 열립니다. 모든 문장은 합성이어야 합니다(실제 가족 대화·실제 개인정보·유명인·실제 인물 비방·욕설·성적/폭력적 내용·정치 금지).

## 1. 만들 것

| 파일 | 문장 수 | 사람 이름 포함 | 기타 개인정보만 | 개인정보 없음 |
|---|---:|---:|---:|---:|
| `r11_representative_v1.jsonl` (가족 메신저 대표) | 1,600 | 950 | 250 | 400 |
| `r11_stress_v1.jsonl` (취약 유형 스트레스) | 2,350 | 1,800 | 50 | 500 |

배치 200문장씩 나눠 만들고, 배치마다 주제·말투·이름을 바꾸세요. 비슷한 문장을 반복해 수를 채우면 안 됩니다. **쌍(D1P/D1), LONGNAME, ORGLOC_MIX 는 최종 수량의 10%를 더 만들어 제출하세요**(검증·검수에서 탈락한 문장을 채우기 위한 예비분이며 봉인 전에 사용자가 정확한 수량으로 맞춥니다).

## 2. 문장 표기: 인라인 태그

정답 구간을 `[[라벨|값]]` 으로 감싸 쓰세요. 오프셋은 직접 계산하지 마세요(변환 스크립트가 계산합니다).

```
[[PERSON|값]]이(가) 방금 학원 끝났대
[[PERSON_ALIAS|별명]]한테 간식 좀 챙겨 줘
[[PERSON|값1]]이랑 [[PERSON|값2]]은 같은 반이야
[[PERSON|값]]아 집에 가는 길에 [[LOCATION|지명]]에서 내려
```

- 보호 대상 라벨: `PERSON`(이름), `PERSON_ALIAS`(별명·애칭 자체만), `ADDRESS`, `PHONE`, `EMAIL`, `ACCOUNT`. 전화·이메일·계좌·주소는 가상 값(이메일은 example.com 류).
- 보호 대상이 아닌 `[[LOCATION|…]]`, `[[ORGANIZATION|…]]` 은 지명·기관명이 있을 때 표시(정답에는 포함되지 않음, 변환기가 `context_entities` 로 보냅니다).
- 구간은 값 자체만: 조사(이/가/은/는/을/를/한테/랑/아/야 …), 호칭(씨·님·선생님), 따옴표, 공백은 태그 밖.
- 호칭만 있는 `엄마`, `아빠`, `할머니`, `이모` 는 태그하지 않습니다. 이름 뒤에 가족 호칭이 붙으면 이름만 태그합니다. 날짜·금액·주문번호는 태그하지 않습니다.
- 별명이 일반 명사와 같은 문자열이면 실제 사람을 가리키는 문맥에서만 `PERSON_ALIAS`.
- **한 문장에 보호 대상이 여러 개면 전부 태그하세요.** 개인정보가 없는 문장에 숨은 개인정보가 있으면 안 됩니다.

## 3. 쓰면 안 되는 것

- **1글자 이름이 들어간 문장**(1글자 이름일 수 있는 글자가 이름으로 쓰인 문장, 모호한 문장 포함). 어쩔 수 없이 들어갔다면 그 줄에 `"exclude": true, "exclude_reason": "one_char_name"`.
- 반려동물 이름, 사람 별명인지 구분이 안 되는 사례, 당신도 라벨을 확정하지 못하는 모호 사례.
- 이 문서의 예시 표기를 평가셋에 그대로 넣는 것, 실제 인물 이름, 실제 가족 대화 원문.

## 4. 입력 파일(JSONL, 한 줄 = 한 문장) 필드

```json
{"id": "R11R-0001", "category": "일정", "marked": "[[PERSON|값]]이(가) 방금 학원 끝났대",
 "style": "반말대화", "scenario": "학원 픽업", "batch": "B01", "split_set": "representative"}
```

- `id` 세트 안 고유(`R11R-0001`.., 스트레스 `R11S-0001`..), `marked` 태그 문장, `category` 문장 유형.
- 스트레스 세트는 `primary_stress_type`(문장당 1개)과 `stress_types`(해당 유형 모두, 배열)를 반드시 넣고 `split_set` 은 `stress`.
- **대조쌍 문장(D1P/D1)은 `pair_id`, `role`(`person` 또는 `noun`), `pair_word` 세 필드를 모두 넣고, 그 밖의 문장에는 이 필드를 넣지 마세요.**
- **ORGLOC_MIX 문장은 `mix_kind` 를 반드시 넣으세요**: `name_looks_place`(사람 이름이 지명·기관명처럼 보임), `place_looks_name`(지명·기관명이 사람 이름처럼 보임), `plain`(그 밖).
- 틀을 반복해 쓰면 `template_id`(없으면 생략). 변환기(`tag_to_r11_jsonl.py`)와 검증기(`validate_r11_evalset.py`)는 사용자가 제공하며, 보고서의 오류 코드·건수·문장 id 로 고치세요.

## 5. 대표 평가셋(`representative`, 1,600문장)

실제 가족 메신저에서 나올 법한 다양한 상황을 고루 담으세요. 어려운 문장만 모으지 마세요.

- 시나리오(대략 비율): 일정·약속 15%, 학교·학원·가정통신문 20%, 가족 안부·심부름 15%, 정산·돈·구매 12%, 사진·영상 공유 8%, 병원·건강 8%, 여행·이동·집 방문 8%, 잡담·감정 표현 14%.
- 말투(대략): 짧은 반말·불완전 문장 55%, 존댓말 대화 10%, 안내문·공지 문어체 15%, 메모·일정 정리 10%, 아주 짧은 단답 10%. 메신저 표현(`ㅋㅋ`, `ㅠㅠ`, 이모티콘, 줄임말, 띄어쓰기 오류, 조사 생략) 포함. 길이 8~150자, 60자 이상 10% 이상.
- 사람 이름 포함 문장 950개: 2글자 이름(성 없음) 25~35%(반드시 35% 이하), 3글자 45~55%, 4~5글자(복성·긴 이름·별명) 8% 이상, 실제 별명 8% 이상, 다인물 문장 15% 이상. 이름은 평범한 이름과 드문 이름을 섞고(과도하게 희귀한 이름만 쓰지 마세요: 대표 세트는 **일상에서 흔한 이름도 충분히** 포함해야 합니다), 서로 다른 PERSON 값 비율 60% 이상, 같은 이름 최대 4회.
- 기타 개인정보만(250): 주소·전화·이메일·계좌를 각각 비슷하게(사람 이름 없이).
- 개인정보 없는 문장(400): **가족 호칭만 나오고 이름이 없는 자연스러운 메시지 30~50개 필수 포함**, 일상 대화, 날짜·금액·주문번호, 지명·기관명, 이름처럼 보이지만 이름이 아닌 일반어.

## 6. 스트레스 평가셋(`stress`, 2,350문장) 유형별 작성 방법

각 문장의 `primary_stress_type` 은 아래 코드 중 하나입니다. 문장 수는 **정확한 목표**입니다(예비분 제외).

| 코드 | 한글 유형명 | 문장 수 | 작성 방법 |
|---|---|---:|---|
| A1 | 성 없는 2글자 낯선 이름 | 150 | 성 없는 2글자 이름이나 낯선(조합이 새로운) 이름. 조사 있음·없음·호격·붙여쓰기 섞음. PERSON 값은 2글자 |
| A3 | 사람 이름이 지명·기관명처럼 보이는 문맥(사람으로 쓰임) | 100 | 이름이 도시·역·학교·병원·회사 이름과 비슷, 문맥상 사람 |
| B1 | 이름 뒷부분 누락·부분 노출 | 240 | **3~4글자 이름 뒤에 조사가 없는** 경우(공백·쉼표·문장 끝·괄호·따옴표·`씨`/`님` 앞·가족 호칭 앞). `랑`·`도`·`야`로 끝나는 이름은 피함 |
| B2 | 호격·조사가 붙은 이름 | 80 | `~아/야`, `~이가`, `~이한테` 처럼 호격·조사가 붙은 이름 |
| C1 | 이름 뒤 조사 과확장 위험 | 100 | 이름 뒤 이/가/은/는/을/를이 붙어 조사까지 이름으로 착각하기 쉬운 경우, 구간에는 이름만 |
| C2 | 이름 구간 경계 오류(인접한 두 이름) | 200 | 공백 없이 붙임, 쉼표·중점 나열, `랑/하고` 접속, 이름+별명, 세 명 나열을 고루 |
| D3 | 한 문장에 여러 사람 | 100 | 2~3명(서로 다른 관계), 모두 태그 |
| **D1P** | **이름·일반명사 중의성에 따른 PERSON 미탐** | 300 | 일반 명사와 같은 문자열이 **사람 이름으로** 쓰인 문장. **대조쌍의 사람 문장**(§7) |
| **D1** | **일반명사 PERSON 오탐** | 300 | 같은 문자열이 **일반 명사로** 쓰인 개인정보 없는 문장. **대조쌍의 명사 문장**(§7). 태그 없음 |
| D2 | 이름처럼 보이는 어구·활용형이 든 음성 | 100 | 사람이 아닌 어구·활용형. 태그 없음 |
| A3N | 지명·기관명이 이름처럼 보이는 음성 | 60 | `[[LOCATION|…]]`·`[[ORGANIZATION|…]]` 로만 표시, 사람 이름 없음 |
| GENERIC | 그 밖의 어려운 음성 | 40 | 개인정보 없는 어려운 문장 |
| OTHER | 주소·전화·이메일·계좌만 | 50 | 이름 없음 |
| **NEWNAME** | **신규 이름 일반화** | 310 | 이름이 낯선(드문·새로운 조합) 사람 이름 중심 문장. 문장 구조는 자유, 별명·`이름+호칭` 일부 포함 |
| **LONGNAME** | **긴 이름** | 120 | PERSON(또는 PERSON_ALIAS) 구간 값이 **4글자 이상**(복성+2글자, 외래식·순우리말 긴 이름, 4글자 별명). **구간 뒤에 조사가 있는 문장과 없는 문장 각 40개 이상** |
| **ORGLOC_MIX** | **기관·지명 혼합** | 100 | 같은 문장에 기관·지명(`[[LOCATION|…]]`/`[[ORGANIZATION|…]]`)과 사람 이름(PERSON)이 함께 나옴. `mix_kind` 필수, **`name_looks_place` 30개 이상, `place_looks_name` 30개 이상** |
| 합계 | | **2,350** | 사람 포함 1,800 / 기타만 50 / 개인정보 없음 500 |

- 같은 이름을 여러 유형에 반복하지 말고 유형마다 서로 다른 이름과 문장 구조를 쓰세요. 특정 문형에 편중되지 않게 하세요.
- 한 문장이 여러 유형에 해당하면 `stress_types` 에 모두 쓰고 `primary_stress_type` 은 하나만.

## 7. D1P/D1 대조쌍 규칙 (최소 300쌍, 필수)

한 쌍은 **같은 단어**(일반 명사와 같은 문자열)가 한 문장에서는 사람 이름으로(`role: person`, D1P), 다른 문장에서는 일반 명사로(`role: noun`, D1) 쓰인 두 문장입니다.

| 필드 | 값 |
|---|---|
| `pair_id` | 쌍마다 고유(예: `ev-p-001`), 두 문장이 같은 값 |
| `role` | `person` 또는 `noun` |
| `pair_word` | 두 문장에서 같은 단어 문자열(2글자 이상) |
| `primary_stress_type` | `person` 이면 D1P, `noun` 이면 D1 |

1. `pair_id` 하나에 `person` 문장 1개, `noun` 문장 1개.
2. 두 문장 안에 `pair_word` 가 들어 있어야 합니다.
3. 사람 문장에서는 `pair_word` 가 PERSON(또는 PERSON_ALIAS) 구간(값이 단어와 같거나 성+단어)으로 태그됩니다.
4. 명사 문장에는 `pair_word` 를 포함하는 PERSON 계열 태그가 **없어야** 하고, 다른 PERSON 도 없어야 합니다(개인정보 없는 문장).
5. 두 문장이 같은 문장이면 안 됩니다. **문장 구조(틀)도 서로 달라야** 하고 단어만 바꾼 같은 틀은 안 됩니다.
6. **같은 단어는 최대 4쌍**, **서로 다른 단어는 75개 이상**.
7. 문맥으로 사람/사물을 분명히 가를 수 있는 문장만 쓰세요(당신도 가르지 못하면 만들지 마세요).
8. 1글자 단어는 쓰지 마세요.
9. 사람 문장과 명사 문장의 장면·말투·길이·문장 위치를 다양하게 하세요. 사람 문장이 항상 문두 주어가 되지 않게 하세요.

## 8. 스스로 점검(제출 전)

1. 변환기 → 검증기를 돌려 보고서의 **오류가 0** 이 되게 하세요(경고는 가능한 줄이기).
2. 모든 사람 이름·보호 정보가 태그됐는지, 음성 문장에 숨은 개인정보가 없는지 표본으로 다시 읽으세요.
3. 1글자 이름·반려동물 이름·모호 사례가 없는지 확인하세요.
4. 작성 방법(생성 규칙, 배치 수, 프롬프트 요약)을 `NOTES.md` 로 남기세요.
