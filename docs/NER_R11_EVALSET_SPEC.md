## 4. D1P/D1 대조쌍 규칙 (스트레스 세트, 300쌍 이상)

쌍은 같은 단어(일반 명사와 같은 문자열의 이름)가 한 문장에서는 사람 이름으로, 다른 문장에서는 명사로 쓰이는 두 문장이다.

| 필드 | 값 |
|---|---|
| `pair_id` | 쌍마다 고유(예: `ev-p-001`), 사람·명사 문장이 같은 값 |
| `role` | `person`(D1P 문장) 또는 `noun`(D1 문장) |
| `pair_word` | 쌍의 단어 문자열(두 문장에서 같은 값) |
| `primary_stress_type` | `role=person` 이면 D1P, `role=noun` 이면 D1 |

**무결성 규칙(위반하면 검증 오류)**

| # | 규칙 |
|---|---|
| 1 | `pair_id` 하나에 `person` 문장 정확히 1개, `noun` 문장 정확히 1개 |
| 2 | 두 문장의 `pair_word` 가 같고, 두 문장 `text` 안에 그 단어가 들어 있다 |
| 3 | 사람 문장에서 `pair_word` 가 PERSON(또는 PERSON_ALIAS) 구간 값에 포함되어 그 단어를 중심으로 구간이 잡힌다(구간 값이 단어와 같거나 성+단어) |
| 4 | 명사 문장에는 `pair_word` 를 포함하는 PERSON 계열 구간이 **없다**(음성, 다른 PERSON 이 있으면 안 됨) |
| 5 | 두 문장 `text`(정규화 후)가 같으면 안 된다 |
| 6 | 두 문장의 틀(span 을 `§` 로 치환)이 서로 달라야 한다. 정규화 4-gram 유사도 0.7 미만 |
| 7 | 같은 `pair_word` 는 **최대 4쌍**, 서로 다른 `pair_word` 는 **75개 이상**(300쌍 기준) |
| 8 | 단서가 문맥으로 사람/사물을 가를 수 있는 문장만 쓴다(작성자도 정하지 못하면 제외) |
| 9 | 한 글자 단어(1글자 이름)는 쓰지 않는다 |

쌍 문맥 정확률의 분모는 **정상 검수를 통과한 쌍 수**이며 검수에서 한 문장이 제외되면 그 쌍 전체를 제외한다(제외 뒤에도 300쌍 이상 유지하도록 제작 시 5% 여분을 둔다). 대표 세트에는 쌍 요구를 두지 않는다.

## 5. 신규 이름의 정의와 이름 풀 분리

- **이름 부분(given)**: 성(1글자 또는 복성 `남궁·황보·선우·제갈·사공·독고`)을 뗀 부분. 성이 없는 이름과 별명은 값 전체.
- **참조 집합 R**: R9 학습·검증·개발, R10 학습·개발, **R11 학습 D′·Validation(`r11_val`)·Development(`r11_dev`)** 의 PERSON·PERSON_ALIAS 구간 값과 그 이름 부분(2글자 접미 포함).
- **신규 이름**: 이름 부분이 R 에 없고, R 의 어떤 값과도 길이 3 이상 부분 문자열 포함 관계가 아닌 이름. 검증기가 모든 PERSON 구간에 `name_seen_in_reference` 를 표시한다. **신규 이름 층** = false 인 구간, **기존 이름 층** = true 인 구간.
- **이름 해시 클래스**: 사전 등록 §5-2 의 이름 부분 해시 mod 10 에서 클래스 2 가 독립 테스트 후보 풀이다. 제작자에게 **해시 규칙을 공개하지 않고**, 제작자는 이름을 직접 지어 쓴다. 봉인 후 검증기가 이름 부분의 클래스 분포를 건수로만 보고한다(클래스 2 가 아닌 이름은 다른 역할 풀과 겹쳤을 가능성이 있는 이름으로 R 대조를 따로 본다).
- **제작 세션 지침**: (1) 흔한 이름 상위권을 피한 낯선 이름을 중심으로 하되, 대표 세트의 일상 문맥은 자연스러운 이름 분포로 쓴다(기존 이름 층 300개 확보가 사후에야 확인되므로 대표 세트는 과도하게 희귀한 이름만 쓰지 않는다), (2) 이름 값당 재사용 4회 이하, 서로 다른 PERSON 값 비율 60% 이상, (3) 2글자 25~35%, 3글자, 4글자 이상 고루, (4) 옛스러운 이름·순우리말·외래식 이름·가족 별명 포함.
- **층 크기 기준**: 신규 이름 층(NEWNAME 외 유형 포함, 구간 기준)이 150개 미만이면 NEWNAME 지표는 "표본 부족", 보고 전용. 기존 이름 층이 300개 미만이면 기존 이름 정상 문맥 확인을 "표본 부족" 으로 보고하고 해당 조건을 보고 전용으로 낮춘다(사전 고정). LONGNAME 층이 120문장 미만이어도 같다.

## 6. 라벨 정책 (r9-1.1 유지)

- 한 글자 PERSON 이름 문장은 넣지 않는다(쓰면 `exclude: one_char_name`). 이 한계는 최종 보고서에 명시한다.
- PERSON_ALIAS 는 별명 자체만, `이름+가족호칭` 은 이름 부분만 PERSON(호칭·조사 제외). 별명·명사 동형은 사람 지칭 문맥에서만 PERSON_ALIAS. 호칭만 있는 문장은 음성. 구간 값에 가족 호칭이 들어 있으면 검증 오류. 그 밖의 정의는 `NER_R9_COMMON_SPEC.md` §3 과 같다.
- LOCATION·ORGANIZATION 은 보호 대상이 아니며 `context_entities` 로만 표시한다(ORGLOC_MIX 는 `context_entities` 필수).
- 층화 정의: **기존 이름 정상 문맥 층** = `name_seen_in_reference=true` 인 PERSON 구간(참조 집합에 있는 이름이 일반 문장에서 쓰인 경우). 대표 세트에서 300개 이상을 목표로 하며, 스트레스 세트 구간은 별도 층으로 따로 보고한다.

## 7. 학습·Validation·Development 와의 분리

| 항목 | 규칙 |
|---|---|
| 제작자 접근 | 학습·`r11_val`·`r11_dev` 데이터·틀·단어 목록·이름 풀·해시 규칙을 보지 못한다. 제작 지시서에 이들의 예시 문장·이름을 쓰지 않는다 |
| 학습 쪽 접근 | 학습 세션은 평가셋 문장·이름·틀을 보지 못한다. 후보 선정에 평가셋 접근 금지 |
| 문장 겹침 | 학습·Validation·Development·R9·R10 데이터와의 대조는 **프로그램 안에서만**, 해시 n-gram 으로 건수만 보고. 문장·정규화 문장 일치는 **0**(허용 안 함) |
| 틀·유사도 | 문장 틀 겹침 2% 이하, 4-gram(0.7 이상) 유사 3% 이하(건수 비율). 세트 내부 같은 틀 최대 2회 |
| 쌍 단어 겹침 | `pair_word` 가 학습·Validation·Development 의 단어 목록과 정확 일치 또는 부분 문자열 포함이면 해당 쌍을 "겹침 쌍" 으로 센다. 겹침 쌍이 전체 쌍의 **10% 이하**면 쌍 전체를 쓰고 겹침 쌍은 별도 보고, **10% 초과**면 겹침 쌍을 지표에서 빼고 쌍 문맥 정확률을 "보고 전용" 으로 전환(300쌍 미달) |
| 이름 겹침 | 오류가 아니고 `name_seen_in_reference` 로 층화. 신규 이름 층 150 미만 → 보고 전용(§5) |
| 겹침 초과 시 처리 | 문장 일치가 1건이라도 있으면 해당 문장(쌍이면 쌍 전체)을 제거하고 제작자에게 대체 작성을 요청한다. 틀·4-gram 기준을 넘는 **층**은 지표를 낼 수 없게 되므로 해당 층을 보고 전용으로 전환(교체 적격 판정 조건에서 제외하지 않고, "보고 전용으로 전환됨" 이 사전 등록 규칙 §5-2 에 따라 기록된다) |
| 열람 | 겹침 측정 중에도 문장 원문을 열람하지 않는다(id·건수만) |

## 9. 검수와 라벨 합의

1. **검수량**: 전체(대표+스트레스)의 15% 이상. A 안 기준 3,950 × 15% = 593 → **600문장 이상**(B 안 약 580, C 안 약 560 으로 환산). 층화 무작위(유형·세트별 최소 15문장)에 **고위험 전수 확인**을 더한다: 쌍·별명·C2·다인물에서 150문장(R10 은 100).
2. **유형별 최소 검수 문장 수**: D1P/D1 쌍은 **60쌍(120문장, 쌍 단위로 두 문장 모두 검수)**, LONGNAME **30문장**, ORGLOC_MIX **30문장**(이름이 기관·지명처럼 보이는 경우 10 이상), NEWNAME 30, B1·C2 각 30, 그 밖 유형 각 15 이상. 검증기가 표본 id 만 뽑는다(`--make-review-sample`).
3. **검수자**: 사람 2명이 서로의 판정을 보지 않고 독립 검수(정상/수정/제외, 오류 유형). 한 명은 제작 세션과 무관해야 한다.
4. **합의**: 이견은 제3자 또는 협의로 확정하고 건수·유형을 기록, 구간 단위 일치율(또는 Cohen's κ)을 보고한다. 이견률 5% 초과 유형은 제작자가 해당 배치를 다시 만든다.
5. **봉인 기준**: 표본 구간 오류율 2% 이하면 봉인, 2~5% 면 수정 후 150문장 추가 검수, 5% 초과면 해당 배치 재작성. D1P·D1·B1·C2·**LONGNAME·ORGLOC_MIX**·쌍 무결성은 유형별 오류율 3% 초과 시 해당 유형 재작성.

- `mix_kind`(ORGLOC_MIX 문장 필수): `name_looks_place`(사람 이름이 지명·기관명처럼 보임), `place_looks_name`(지명·기관명이 사람 이름처럼 보임), `plain`(그 밖). 사양 §3 의 "30문장 이상" 두 조건을 검증기가 이 필드로 센다. 변환기 `tag_to_r11_jsonl.py` 가 `pair_id`·`role`·`pair_word`·`mix_kind` 를 그대로 넘기고, 검증기 `validate_r11_evalset.py` 가 §11 의 확장 항목을 구현한다(시험 9건).
- 쌍·LONGNAME·ORGLOC_MIX 는 제작 시 10% 예비분을 더 만들고 봉인 전 정확한 수량으로 맞춘다(§15 말미, 절차 문서 8단계).
