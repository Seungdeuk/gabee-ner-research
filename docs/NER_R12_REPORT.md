## 1. 한 일

1. **독립 평가셋 제작 지시서**(`NER_R12_EVALSET_PRODUCER_INSTRUCTIONS.md`)와 별도 GPT 세션용 전달 패키지(`gabee-ner-evalset-r12-handoff\`)를 학습 전에 작성했다. 스트레스 2,350 + 대표 800, id 접두 R12S-/R12R-.
2. **사전 등록**(구성·게이트·채택 조건·결과 분류)을 학습 전에 커밋하고 `r12-prereg-1.0` 태그를 달았다. 이후 규칙을 바꾸지 않았다. 실제 수량 문단만 학습 전에 추가했다.
3. **데이터 풀 분리**(`build_r12_pools.py`): 대조 단어 train 280 / val 60 / dev 60, 전체 이름 700/150/150, 성 없는 2자 이름 600/150/150을 서로 겹치지 않게 배정. R11 데이터와 겹치는 단어(214개)는 val·dev에서 제외.
4. **데이터 작성**: 31개 배치(대조쌍·성 없는 이름·별명·인접 다인물·경계 취약·가족 채팅)를 서브에이전트(Sonnet)가 문장별로 직접 작성. 규칙 검사기(`check_r12_marked.py`: 태그 문법, 1글자 이름, 풀 밖 이름, 쌍 구조, 단어별 수량, 같은 틀 반복, 직접 단서 없는 사람 문장 ≥30%)를 전 배치가 오류 0으로 통과했고, 보고만 믿지 않고 제가 31개 전부 재실행했다.
5. **조립·독립성 점검**(`assemble_r12.py`): 세트 간 같은 문장 0, 틀(앞 3어절+끝 어절) 겹침 0, 대조 단어 겹침 0. 별명(꼬맹이·복덩이 등 흔한 애칭)이 세트 간·R11 정답과 겹쳐 **쌍 단위로 학습 58행·dev 9행을 제거**한 뒤 PERSON 값 겹침 0(세트 간, R11 개발·검증·baseline 정답과 모두). 최종 수량: 학습 `r12_extra` 2,742 / `r12_val` 485 / `r12_dev` 476.
6. **학습**(`run_r12.py`): R11 B군과 같은 하이퍼파라미터(max_len 128, batch 32, lr 5e-5, ≤8에폭, patience 2, warmup 0.1, wd 0.01), 데이터는 R11 B군 그대로 + `r12_extra`(총 12,657행), 선택 기준 `r12_val` 겹침 F1, 시드 7·13·21·42·99 전부.
7. **개발 평가**(`evaluate_r12_dev.py`, `r12_gate.py`): R11 평가 코드(R9 회귀·r11_dev·KLUE)를 그대로 재사용하고 `r12_dev`·`r12_val`을 추가. R11 기준선은 `R11-B-s21-ep5`(ONNX sha256 `3831601b7ffb6093…`, 보존 확인).

## 3. 오류 분석 (r11_dev 유형별 노출, R11 → R12 5시드 평균)

| 유형 | R11 | R12 평균 | 비고 |
|---|---:|---:|---|
| D1P(일반명사 모양 이름) | 14.26 | 14.41 | **변화 없음** (최소 12.22, 최대 15.93) |
| C2(인접 이름) | 12.35 | 13.55 | 오히려 악화 |
| B1(조사 없는 위치) | 4.00 | 4.40 | 변화 없음 |
| NEWNAME / LONGNAME | 3.91 / 3.08 | 3.46 / 3.54 | 변화 없음 |
| D1 오탐 | 25.48 | 28.90 | **악화**(+3.4%p) |
| NEG_D2 오탐 | 7.50 | 2.00 | 개선 |
| 쌍 문맥정확도 | 39.5 | 37.6 | 변화 없음 |

`r12_dev`에서는 D1P 33.6 → 11.1, 쌍 정확도 57.1 → 84.7, 성 없는 이름(A1)·전체 이름(B2) 노출 0, 인접 이름(C2) 8.0 → 1.2로 좋아졌다. 반면 가족 채팅 양성(FAM_POS) 노출은 0 → 3.4로 악화됐고 별명(ALIAS)은 23 → 20으로 거의 그대로다.

**원인 해석(추정, 실험으로 확인하지 못함):**
1. `r12_extra`·`r12_val`·`r12_dev`가 같은 작성 과정(같은 모델, 같은 브리프)에서 나왔다. 단어·이름·문장·틀은 겹치지 않게 막았지만 **문체와 사람/명사 구분 단서의 분포는 같다.** `r12_dev` 개선은 이 분포에 대한 적응으로 볼 수 있고, 다른 방식으로 만든 `r11_dev`에서는 전이되지 않았다.
2. 일반명사 문장 오탐이 늘어난 것은 "사람으로 쓰인 단어를 더 많이 잡으라"는 학습 신호가 명사 문장에도 번진 결과로 보인다. 일반명사 쪽 학습 문장이 사람 문장과 같은 수라서 균형은 맞췄지만, 다른 분포의 명사 문장에서는 부족했다.
3. 단일 작성자(모델) 데이터의 다양성 한계. 사전 등록에서 "사람 문장 30% 이상 직접 단서 없음"을 지켜(학습 95.5%) 쉬운 단서 의존은 줄였지만, 그 약한 단서 자체가 작성 방식에 고유할 수 있다.

## 4. 한계

- 개발셋(`r12_dev`)은 학습 데이터와 같은 작성 과정이라 **독립이 아니다.** 이 결과로 5% 달성이나 일반화를 주장할 수 없다. 독립 평가셋(별도 GPT 세션 제작)은 아직 없다.
- `r11_dev`는 R11 개발 과정에서 이미 여러 번 쓰인 세트라 선택에 쓰는 것은 과적합 위험이 있으나, 이번에는 게이트 기준으로만 썼다.
- 데이터는 합성이며 사람 검수는 하지 않았다. 별명은 흔한 애칭이 많아 세트 간 겹침을 제거해야 했다(학습 58행·dev 9행 제거).
- 시드 5개만 사용, 구간 추정(부트스트랩)은 독립 평가에서만 한다.
- p50 지연·RSS는 확정 시드가 없어 측정하지 않았다.
