# NER 2차 개선 라운드(R8) 결과

작성일 2026-11-19. 사전 등록: `NER_R8_PREREGISTRATION.md`(평가 전 커밋). 연구 브랜치 `feature/seungdeuk-ner-improve2`(로컬, 푸시 없음). 운영 모델·서비스 코드·배포 환경은 바꾸지 않았다.

## 결론

- **권고: 서비스 모델 유지.** 사전 등록 규칙으로 선정한 후보 s21 은 봉인 평가셋 new180 에서 세 목표(전체 노출 5% 미만, 비PERSON 오탐 5% 이하, Exact F1 90% 이상)를 모두 달성하지 못했고, 노출률은 서비스 모델과 같은 수준(13.6% → 14.6%, 차이는 신뢰구간 안)이었다.
- 개발 평가셋(소비된 세트 5개)에서는 5개 시드 모두 서비스 모델보다 노출률이 크게 낮았다(매크로 6.53% → 시드 평균 2.89%). 이 개선이 새 평가셋 new180 으로 이어지지 않았고, 이유는 확인하지 못했다.

## 5. 학습·데이터

- 레시피: 서비스 모델과 같은 KoELECTRA-small-v3 사전학습 체크포인트에서 시작, KLUE 10%, max_len 128, batch 32, lr 5e-5, 최대 8에폭, patience 2, 에폭 선택은 baseline_val. 시드 7·13·21·42·99, 실패한 실행 없음(후보 5 + 대조군 5 + 파일럿 1).
- 학습 문장 7,140개(기존 4,220 + 신규 2,206 + KLUE 714). 신규 데이터는 전체 2,609행(학습 2,206 / 검증 403), 이름 없는 문장 379, 둘 이상의 구간이 있는 문장 385, 규칙 몫(전화·이메일·계좌) 기록 문장 포함. 유형: A1 이름(2글자·3글자·단어 모양), B1 끝 글자(3·4글자), A3 지명·기관 모양 이름과 실제 지명·기관 대조, D 자연어·어구 부정과 이름 단어 대조, 호칭 부정, 다중 개인정보.
- 검증: 구간 일치·겹침 없음·중복 없음·정답 누락 0건, train/val 이름 겹침 0, new180 과 문장·정규화 문장·문장 틀·4-gram 유사 틀·구간 값 겹침 0, 개발 평가셋 문장 겹침 0.
- 한계: 신규 데이터는 자체 작성 합성 문장이고 문형이 55개 안팎이라 이름 다양성은 넓지만 문맥 다양성은 제한적이다. 개발 평가셋도 같은 종류의 합성 문장이라 개발셋 개선이 실제 대화로 이어진다고 볼 근거는 없다. 처음 열람한 new180 앞 12행의 이름은 학습에서 제외했다. 하나의 문장에 개인정보가 여러 개인 경우는 NER 대상 5개 라벨을 모두 표시했고 전화·이메일·계좌는 `rule_spans` 에만 기록했다.
- 라이선스: 서비스 모델과 같은 조건(KLUE-NER CC BY-SA 4.0, KoELECTRA 가중치 표기 없음)이며 기존 미확정 상태 그대로다. AI Hub 데이터는 쓰지 않았다.
- 내보내기: ONNX fp32 만 만들었다. 토치 대비 일치성 검증과 모델 카드는 만들지 않았다(개발 평가용 최소 카드).

## 6. 이번 라운드에서 바로잡은 점

- 이전 채점 코드가 정답이 여러 개인 문장에서 첫 구간만 채점했다. 이번 라운드는 모든 구간을 채점했고, 기존 방식으로도 돌려 §70 수치가 재현되는 것을 확인했다(realistic_family 노출 12.50% → 모든 구간 13.08%, 정밀도 64.59% → 84.44%).
- new180 채점의 ACCOUNT 집계 버그를 고쳤다(결과 영향: ACCOUNT 노출 2 → 1, 전체 정답 177 → 176).

## 7. 미해결

- 개발셋 개선이 new180 에서 확인되지 않은 이유. new180 의 개별 실패를 열어 보면 원인 분석은 가능하지만 그 순간 new180 은 blind 평가셋이 아니게 되므로 사용자가 정할 일이다.
- 실제 가족 대화로는 평가한 적이 없다.
- 1~2글자 이름의 일반화는 개발셋(합성)에서만 개선이 보였다.
