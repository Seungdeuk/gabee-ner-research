# [제작 세션 전달용] R11 독립 평가셋 — 운영 교체 평가 부록 (ops-1.0)

2026-11-23 작성. **전달 대상: 평가셋 제작 세션.** 본문 지시서 `NER_R11_EVALSET_PRODUCER_INSTRUCTIONS.md` 와 함께 전달하는 부록이다. 학습 세션의 어떤 데이터·모델·결과·해시 규칙도 이 부록에 없으며 제작자에게 주지 않는다.
표시: **자동 검증 기반 연구용 · 사람 검수 미완료.** 이 부록은 제작 승인이 아니다 — 실제 제작·봉인은 사용자의 별도 승인 후에만 시작한다.

## 1. 이번 단계에서 필요한 산출물
- **필수**: `r11_stress_v1.jsonl`(스트레스 2,350문장) — 운영 교체 판정에 쓰는 유일한 세트.
- 대표 세트(`r11_representative_v1.jsonl`, 1,600문장)는 **이번 단계에서 요청하지 않는다**(판정에 쓰지 않음). 본문 지시서의 대표 세트 항목은 건너뛴다.

## 2. 스트레스 세트 구성(사양 `NER_R11_EVALSET_SPEC.md` r11-1.0 §3, 변경 없음)
사람 이름 포함 1,800 / 기타 개인정보만 50 / 개인정보 없음 500. 유형(문장당 `primary_stress_type` 1개): A1 150, A3 100, B1 240, B2 80, C1 100, C2 200, D3 100, **D1P 300 + D1 300(300쌍)**, D2 100, A3N 60, GENERIC 40, OTHER 50, NEWNAME 310, LONGNAME 120, ORGLOC_MIX 100.

## 3. 판정에 직접 쓰이는 규칙(제작자가 알아야 하는 것)
1. **분모 최소**: 유형 D1P·B1·C2·NEWNAME·LONGNAME·ORGLOC_MIX 는 각각 **정답 PERSON 구간이 100개 이상**, D1 명사 문장은 **250개 이상**이어야 한다. 회귀 유형 A1·A3·B2·C1·D3 도 정답 PERSON 구간이 0개이면 평가가 시작되지 않는다(사양 수량이면 문제없음). **허용된 16개 유형 코드(A1·A3·B1·B2·C1·C2·D1·D1P·D2·D3·A3N·GENERIC·OTHER·NEWNAME·LONGNAME·ORGLOC_MIX) 밖의 `primary_stress_type` 은 쓰지 않으며, 16개 유형 모두에 문장이 있어야 한다.** 제외 처리 후에도 이 수를 지키도록 **유형마다 5~10% 예비분**을 더 만든다(쌍·LONGNAME·ORGLOC_MIX 는 10%). 최종 수량은 봉인 전에 정확히 맞춘다.
2. **쌍(D1P/D1)**: `pair_id` 하나에 `role=person` 정확히 1, `role=noun` 정확히 1. 같은 `pair_word`, 서로 다른 틀(4-gram 유사도 0.7 미만), 명사 문장에는 PERSON 계열 구간이 없다(다른 사람 이름도 금지). 서로 다른 단어 75개 이상, 단어당 최대 4쌍. 한 문장이 제외되면 쌍 전체가 제외되므로 예비분을 쌍 단위로 만든다.
3. **음성 유형**(정답 PERSON 이 없는 문장): D1(명사 문장), D2, A3N, GENERIC, OTHER. 오탐 판정이 이 유형들에서 이뤄지므로 **숨은 PERSON(라벨 누락)이 없어야** 한다. 사람 이름처럼 보이지만 사람이 아닌 문장은 라벨하지 말고, 작성자도 사람 여부를 확정하지 못하는 문장은 쓰지 않는다.
4. **ORGLOC_MIX**: 한 문장에 LOCATION/ORGANIZATION 과 PERSON 이 함께 있고 `mix_kind`(`name_looks_place`·`place_looks_name`·`plain`) 필수, 각 30문장 이상.
5. **기존 서비스 회귀 유형**(A1, A3, B2, C1, D3)은 운영 회귀 위험을 보는 유형이므로 실제 가족 메신저 말투(띄어쓰기 오류, 줄임말, 이모티콘 없이 문자 위주)를 고루 쓴다. 한 유형 안에서 틀·이름·말투를 반복하지 않는다.
6. **독립성**: 문장·이름·틀은 이 부록과 본문 지시서의 예시를 그대로 쓰지 않는다. 학습 세션이 가진 학습·Validation·Development 문장과 겹치지 않아야 하지만(문장 일치 0, 틀 겹침 2% 이하, 4-gram 유사 3% 이하) 제작자는 그 데이터를 볼 수 없다. 겹침 측정은 학습 세션이 해시 기반 개수만 산출하고, 겹친 문장 **id 만** 제작자에게 알려 대체 작성을 요청한다(원문 미전달).

## 4. 형식
본문 지시서 §2·§4 의 인라인 태그 `[[라벨|값]]` 와 JSONL 필드를 그대로 쓴다. 추가 필드: 쌍 문장 `pair_id`·`role`·`pair_word`, ORGLOC_MIX `mix_kind`, 제외 문장 `exclude`·`exclude_reason`. 오프셋은 변환기가 계산한다. 파일명 `r11_stress_v1.jsonl`.

## 5. 제작자가 함께 제출할 자기 보고(NOTES.md)
유형별 최종 수량과 예비분 수, 라벨이 불확실했던 유형·패턴, 이름 풀 출처 설명(실제 인물 아님), 쌍 단어 목록의 개수. **사람 검수를 했다고 쓰지 않는다**(검수는 별도 절차).

## 6. 학습 세션이 하는 일(제작자 책임 아님)
`tag_to_r11_jsonl.py` 변환 → `validate_r11_evalset.py --strict`(스키마·span·중복·쌍 무결성·유형별 수량·겹침) → 수정 요청(id 만) → 수량 확정 → 사용자 봉인 승인 → `seal_r11_evalset.py`. 모델 평가는 봉인과 사전 등록 태그 이후에만, 모델당 1회.
