# [ChatGPT 전달용] GaBee 한국어 개인정보(이름) 탐지 독립 평가셋 작성 지시서 (정책 r9-1.1)

> 정책 r9-1.1 변경: `이름+가족호칭`은 **이름 부분만 PERSON**, 호칭은 태그 밖. `PERSON_ALIAS` 는 실제 별명 자체만이고 `이름+호칭`을 별칭으로 쓰지 않는다. 호칭만 있는 문장은 음성이다.

이 문서만 읽고 작업하세요. 당신은 한국어 **가족 메신저 대화**에서 개인정보(특히 사람 이름)를 탐지하는 모델을 평가할 **독립 평가셋**을 만듭니다. 당신이 쓴 문장은 모델 학습에 쓰이지 않으며 최종 평가에서 한 번만 열립니다. 모든 문장은 합성이어야 합니다(실제 가족 대화·실제 개인정보·유명인 이름 금지).

## 1. 만들 것

| 파일 | 문장 수 | 사람 이름 포함 | 기타 개인정보만 | 개인정보 없음 |
|---|---:|---:|---:|---:|
| `r9_representative_v1.jsonl` (가족 메신저 대표) | 1,600 | 950 | 250 | 400 |
| `r9_stress_v1.jsonl` (취약 유형 스트레스) | 800 | 550 | 50 | 200 |

한 번에 한 파일을 통째로 만들지 말고 **배치 200문장씩** 나눠 만드세요. 배치마다 주제·말투·이름 풀을 바꾸고, 이전 배치 문장을 보지 않아도 겹치지 않도록 다양하게 쓰세요. 일부러 비슷한 문장을 반복해 수를 채우면 안 됩니다.

## 2. 문장 표기: 인라인 태그

정답 구간을 `[[라벨|값]]` 으로 감싸 쓰세요. 오프셋은 직접 계산하지 마세요(변환 스크립트가 계산합니다).

```
[[PERSON|서아]]가 방금 학원 끝났대
[[PERSON|지우]] 엄마한테 내가 말해 놨어
[[PERSON_ALIAS|콩이]]한테 간식 좀 챙겨 줘
[[PERSON|도윤]]이랑 [[PERSON|하린]]은 같은 반이야
[[PERSON|세인]]아 집에 가는 길에 [[LOCATION|강남역]]에서 내려
```

- 보호 대상 라벨: `PERSON`(이름), `PERSON_ALIAS`(사람을 지칭하는 실제 별명·애칭의 **별명 자체만**, `이름+호칭`은 쓰지 않음), `ADDRESS`(번지·도로명+번호·동·호수), `PHONE`(개인 전화), `EMAIL`, `ACCOUNT`(계좌 숫자열만).
- 보호 대상이 아닌 `[[LOCATION|…]]`, `[[ORGANIZATION|…]]` 은 지명·기관명이 있을 때 표시합니다(정답에는 포함되지 않음).
- 구간은 값 자체만: 조사(이/가/은/는/을/를/한테/랑/아/야 …), 호칭(씨·님·선생님), 따옴표, 공백은 태그 밖에 둡니다.
- 호칭만 있는 `엄마`, `아빠`, `큰아들`, `시어머니`는 태그하지 않습니다. 이름 뒤에 가족 호칭이 붙으면 이름만 태그하고 호칭과 조사는 태그 밖에 둡니다. 날짜·금액·주문번호는 태그하지 않습니다.
- 별명이 일반 명사와 같은 문자열이면 실제 사람을 가리키는 문맥에서만 `PERSON_ALIAS` 로 태그하고, 명사로 쓰였으면 태그하지 않습니다.
- **한 문장에 보호 대상이 여러 개면 전부 태그하세요.** 하나라도 빠뜨리면 평가가 틀어집니다.
- 개인정보가 없는 문장은 태그 없이 씁니다(그 문장에 이름·전화·이메일·계좌·주소가 숨어 있으면 안 됩니다).
- 전화번호·이메일·계좌·주소는 가상 값으로 쓰세요(이메일은 example.com 류, 전화는 존재하지 않을 법한 값). 실제 값과 우연히 같을 수 있어도 의도적으로 실제 값을 쓰지 마세요.

## 3. 쓰면 안 되는 것(해당 문장은 만들지 않기)

- **1글자 이름이 들어간 문장.** `봄`, `솔`, `별`, `율`, `결`, `담`, `온`, `겸`, `찬`, `휘`처럼 1글자 이름일 수 있는 글자가 이름으로 쓰인 문장은 쓰지 않습니다. 이런 글자가 이름이 아닌 명사로 쓰인 문장도 모호하면 쓰지 마세요. 어쩔 수 없이 들어갔다면 그 줄에 `"exclude": true, "exclude_reason": "one_char_name"` 을 넣으세요(음성 문장으로 바꾸지 마세요).
- 반려동물 이름, 사람 별명인지 구분이 안 되는 사례, 당신도 라벨을 확정하지 못하는 모호 사례.
- 이 문서의 예시 문장·예시 이름을 평가셋에 그대로 넣는 것.
- 실제 인물(연예인·정치인 등) 이름, 실제 가족 대화 원문.

## 4. 입력 파일(JSONL, 한 줄 = 한 문장) 필드

```json
{"id": "R9R-0001", "category": "일정", "marked": "[[PERSON|서아]]가 방금 학원 끝났대",
 "style": "반말대화", "scenario": "학원 픽업", "batch": "B01", "split_set": "representative"}
```

- `id`: 세트 안에서 고유(`R9R-0001`.., 스트레스는 `R9S-0001`..), `category`: 문장 유형, `marked`: 태그 문장.
- 스트레스 세트는 `primary_stress_type`(문장당 1개)과 `stress_types`(해당 유형 모두, 배열)를 반드시 넣고 `split_set` 은 `stress`.
- 틀을 반복해 쓰는 방식이면 `template_id` 를 넣으세요(없으면 생략).
- 위 입력을 변환 스크립트(`tag_to_r9_jsonl.py`)에 넣으면 공통 JSONL 이 나옵니다. 변환기가 오프셋·`mapped_kind`·`is_negative` 를 만듭니다. 변환 결과를 검증기(`validate_r9_evalset.py`)에 돌려 보고서(오류 코드, 건수, 문장 id)를 확인해 고치세요. 변환기·검증기는 사용자가 제공합니다.

## 5. 대표 평가셋(`representative`) 작성 방법

실제 가족 메신저에서 나올 법한 다양한 상황을 고루 담으세요. 어려운 문장만 모으지 마세요.

- 시나리오(대략 비율): 일정·약속 15%, 학교·학원·가정통신문 20%, 가족 안부·심부름 15%, 정산·돈·구매 12%, 사진·영상 공유 8%, 병원·건강 8%, 여행·이동·집 방문 8%, 잡담·감정 표현 14%.
- 말투(대략): 짧은 반말·불완전 문장 55%, 존댓말 대화 10%, 안내문·공지를 복사해 붙인 문어체 15%, 메모·일정 정리 10%, 아주 짧은 단답 10%.
- 메신저 표현: `ㅋㅋ`, `ㅎㅎ`, `ㅠㅠ`, 이모티콘 문자, 줄임말, 띄어쓰기 오류와 오타, 조사 생략, 한 메시지에 여러 정보.
- 길이: 8~150자, 60자 이상이 10% 이상. 질문·명령·평서·감탄을 섞고 화자 관점도 다양하게.
- 사람 이름(PERSON 계열 포함 문장 950개): 2글자 이름만(성 없음)이 25~35%, 3글자 45~55%, 4~5글자(복성, 긴 이름, 별명)가 8% 이상, 실제 별명(`PERSON_ALIAS`) 8% 이상, 다인물 문장 15% 이상. 2글자 이름 비율은 반드시 35% 이하로 맞추세요. 이름은 평범한 이름과 드문 이름을 섞고, 서로 다른 이름이 900개 이상, 같은 이름은 4회 이하로 쓰세요. 이름 뒤 조사(이/가/은/는/을/를/한테/랑/아/야), 조사 없음, 호격, 붙여 쓴 경우를 고루.
- 기타 개인정보만(250): 주소, 전화, 이메일, 계좌를 각각 비슷하게(사람 이름 없이).
- 개인정보 없는 문장(400): **가족 호칭(엄마·아빠·할머니·이모 등)만 나오고 이름이 없는 자연스러운 메시지 30~50개를 반드시 포함**하고, 일상 대화, 날짜·금액·주문번호가 있는 문장, 지명·기관명, `엄마`·`아빠` 같은 호칭만 있는 문장, 일반 명사가 섞인 문장 등. 사람 이름처럼 보이지만 이름이 아닌 단어(자연물, 일반 명사)도 일부 포함.

## 6. 스트레스 평가셋(`stress`) 유형별 작성 방법

각 문장의 `primary_stress_type` 은 아래 코드 중 하나입니다. 문장 수는 최소 목표입니다.

| 코드 | 문장 수 | 작성 방법 |
|---|---:|---|
| A1 | 110 | **성 없는 2글자 이름**이나 낯선(드문, 조합이 새로운) 이름. 조사 있음·없음·호격·붙여쓰기를 섞음. PERSON 값은 2글자 |
| A3 | 90 | 사람 이름이 지명·기관명처럼 보이는 경우(이름이 도시·역·학교·병원·회사 이름과 비슷). **문맥상 사람으로 쓰임** |
| B1 | 90 | **3~4글자 이름 뒤에 조사가 없는** 경우(이름 뒤에 공백, 쉼표, 문장 끝). 마지막 글자가 은/이/애/인/일/한/남/니 등인 이름을 일부 포함. 마지막 글자가 조사로도 읽히는 `랑`·`도`·`야`로 끝나는 이름은 피함 |
| B2 | 50 | 이름 뒤에 **호격(아/야)이나 조사**가 붙은 경우(`서윤아`, `서윤이가`, `민준이한테`) |
| C1 | 60 | 이름 뒤에 **이/가/은/는/을/를** 등이 붙어 조사까지 이름으로 착각하기 쉬운 경우. 구간에는 이름만 |
| C2 | 40 | **인접한 두 이름**: 공백 없이 붙여 쓰기, 쉼표만으로 구분, 이름+별명 붙임 |
| D3 | 60 | **한 문장에 여러 사람**(2~3명, 서로 다른 관계). 모두 태그 |
| D1P | 50 | 일반 명사와 같은 문자열(자연물·계절·색 등)이 **사람 이름으로** 쓰인 문장. 아래 D1 문자열과 짝(각 D1 문자열마다 D1P 문장 1개 이상) |
| D1 | 90 | 같은 문자열이 **일반 명사로** 쓰인 개인정보 없는 문장(이름으로도 쓰는 순우리말 자연물·계절·색·사물). 태그 없음 |
| D2 | 50 | 이름처럼 보이는 **어구·활용형**이 든 개인정보 없는 문장(말줄임·구어체 활용, 붙여 쓴 동사구 등). 태그 없음 |
| A3N | 40 | 지명·기관명이 이름처럼 보이는 개인정보 없는 문장. `[[LOCATION|…]]`·`[[ORGANIZATION|…]]` 으로만 표시 |
| GENERIC | 20 | 그 밖의 어려운 개인정보 없는 문장 |
| OTHER | 50 | 주소·전화·이메일·계좌만 있는 문장(이름 없음) |

- 같은 이름을 여러 유형에 반복하지 말고, 유형마다 서로 다른 이름과 문장 구조를 쓰세요. 특정 문형(`~가 ~래`)에 편중되지 않게 하세요.
- D1/D1P 짝은 문자열이 같아야 하지만 문장은 완전히 달라야 합니다.

## 7. 스스로 점검(제출 전)

1. 변환기를 돌리고 검증기 보고서의 **오류가 0** 이 되게 하세요. 경고(UNLABELED_*, NEAR_DUPLICATE_*, TYPE_CONSISTENCY_*, COMPOSITION_*)는 가능한 줄이세요.
2. 모든 사람 이름·보호 정보가 태그됐는지, 음성 문장에 숨은 개인정보가 없는지 표본으로 다시 읽으세요.
3. 1글자 이름·반려동물 이름·모호 사례가 없는지 확인하세요.
4. 작성 방법(사용한 생성 규칙, 배치 수, 사용한 프롬프트 요약)을 `NOTES.md` 로 남기세요(평가셋 출처 기록용).

제출물: `r9_representative_v1.jsonl`, `r9_stress_v1.jsonl`, `NOTES.md`. 사용자가 일부를 표본 검수한 뒤 봉인합니다. 봉인 후에는 이 세트의 내용을 모델 개선에 쓰지 않습니다.
