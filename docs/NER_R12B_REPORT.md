## 1. R12 일반화 실패 원인 분석 (데이터 진단, 학습 없음)

- 해석: R12 데이터는 문맥이 아니라 낱말 뒤 형태·문체 단서로도 풀리는 구조였고, R12 개발셋 개선이 분포 밖에서 이어지지 않은 것과 일치한다. 인과를 실험으로 확정하지는 못했다(R12b 학습을 하지 않았으므로 "단서를 균형 잡으면 일반화가 좋아진다"는 반증·확증 모두 없다).

## 2. R12b 학습 데이터의 차별점 (작성·검증 결과)
- **작성**: 서브에이전트 31회 호출(29개 배치 + 이름 부족으로 중단·재작성 2회). 외부 유료 API 없음. 모델 4종 순환(Sonnet 8·Opus 7·Haiku 7·Fable 7 배치), 배치마다 장르 프로필(단체 채팅·메모·질문-답·공지·혼잣말·사진 캡션 등) 지정.
- **단서 균형 규칙을 검증기가 강제**(`check_r12b_marked.py`): 낱말 뒤 형태 묶음 한 종류가 한 역할의 60% 초과 금지, 쌍 k1의 사람·명사 형태 일치 ≥ 90%, 명사 문장의 10% 이상이 `한테/에게/아/야`, 사람 문장의 20% 이상이 조사 없음. `단어+이`(주격과 애칭이 겉모습이 같은 경우)를 허용·권장. 29개 배치 전부 오류 0으로 통과(작성자 보고 후 메인이 전 배치를 다시 검사해 확인).
- **수량**: 작성 후 학습 2,280·검증 440·개발 440 → 겹침 정리 후 학습 2,242·검증 440·개발 435.
- 형태 분포 변화(쌍 문장, 낱말 뒤 공백): R12 학습 사람 15.7% / 명사 42.9% → R12b 사람 31.7% / 명사 23.3%(쏠림 크게 완화). 한쪽 90% 이상 쏠린 단서 64종 → 28종(쌍 문장의 21.3% 덮음).

### 4.2 문맥 단서 분류기가 정답을 맞힐 수 있었던 원인 분석
(원인 후보를 관측한 것이고, 실험으로 하나씩 확정하지는 못했다.)
- **남아 있던 한쪽 쏠림 단서(수정 전)**: 낱말 바로 뒤 단어 `오늘`(사람 35 : 명사 1), `같이`(26 : 2), `학원`(18 : 0), 낱말 뒤 `에 `(0 : 13), 낱말 뒤 단어 `한`(1 : 16). 사람 문장은 "행동·동행·일정(오늘 학원 같이)" 틀, 명사 문장은 "관형어·장소 조사" 틀로 쓰였다. 이 중 일부는 실제 문맥 의미지만 일부는 작성 틀의 차이로 보인다(구분 못 함).
- **형태 단서가 완전히 균형 잡히지 않음**: 낱말 뒤 공백은 사람 31.7% / 명사 23.3%로 R12(15.7 / 42.9)보다 좁아졌으나 남았고, 주격 `이`는 명사 9.6% 대 사람 2.6%로 여전히 명사 쪽으로 기울었다(`단어+이` 사람 문장을 "허용·권장"했으나 작성자들이 거의 쓰지 않았다). `한테`·`한`은 사람 쪽 5.6 / 2.9.
- **같은 작성 방식끼리의 일치**: `r12b_extra`로 학습한 분류기가 `r12_dev`(R12용으로 따로 쓴 문장)에서 80.6%, `r12b_dev`에서 80.0%를 맞혔고, 작성 방식이 다른 `r11_dev`(템플릿 기반 합성)에서는 55.0%에 그쳤다. 두 Claude 작성 세트(R12·R12b)가 같은 계열 작성자의 문체·구성을 공유해 서로 통했을 가능성이 있다(가설).
- **쌍을 한 작성자가 함께 쓰는 구조**: 한 단어의 사람·명사 문장을 같은 작성자가 연달아 쓰면서 두 역할의 문장 틀이 자연스럽게 갈라지는 경향(위 `오늘…같이` 대 `한…에`)이 생겼을 가능성이 있다(가설).
- 분류기 자체의 한계: 앞뒤 낱말·n-gram을 쓰므로 정답 문맥 단어(의미)도 단서로 계산한다. "단서 정확도 70%"가 형태·문체 편향만을 잰 값이 아니어서 기준이 거칠었다(§7).

### 4.3 R12와 R12b에서 확인한 일반화 문제의 공통점
1. 학습·검증·개발셋을 같은 방식(같은 작성자 계열·같은 브리프)으로 만들면 작성 방식 단서만으로도 분포 안 정확도가 높게 나온다(R12: 단서 분류기 r12_dev 89.9%, R12b: r12b_dev 80.0%·r12_dev 80.6%).
2. 분포 밖(`r11_dev`)에서는 같은 분류기가 R12 65.5%, R12b 55.0%로 떨어진다. 즉 새 분포 개선 여부는 개발셋이 학습과 다른 방식으로 쓰였는지에 달려 있다.
3. 단어·이름·문장 겹침 통제(0%)만으로는 부족하다. 겹치지 않아도 문장 틀·문체가 같으면 일반화 평가가 되지 않는다.
4. R12는 모델 평가에서 이 현상이 실제 성능 차(r12_dev 노출 3.65~5.73% vs r11_dev 7.68~9.95%)로 나타났고, R12b는 학습 전 데이터 진단 단계에서 같은 징후(분포 안 80% vs 밖 55%)가 먼저 확인됐다. R12b에서는 모델 성능으로 이 가설을 확인하지 못했다.
5. 두 번 모두 단서를 데이터 쪽에서 완전히 없애지는 못했다.

## 7. 실수·오류 기록
- release/1.4 병합에서 충돌 3건(ADR 목록·`billing/agent.py`·`family_chat/agent.py`). 앱 코드 2개는 release/1.4 쪽을 따랐고 ADR 목록은 합침. 이 연구 브랜치는 R11 연구 스택(앱 코드 포함 235개 파일)이 아직 release/1.4에 병합되지 않은 상태에서 만들어져, PR을 만들 경우 연구 파일만 따로 묶어야 한다.
- 데이터 작성 중 BND(끝글자가 조사처럼 보이는 이름) 배치가 배정 이름 부족(조건 맞는 이름 4개)으로 실패해, 풀에 BND용 이름을 추가하고 두 배치를 다시 작성했다(1회는 작성 중 중지).
- 품질 게이트 기준(70%·72%)은 보정 없이 정한 값이었다. 기준을 사후에 바꾸지 않고 중단을 선택했으므로 이 값이 적절했는지는 확인하지 못했다. 단서 분류기가 의미 있는 문맥 단어도 쓰므로 "단서 0%"는 목표가 될 수 없다는 점이 사전 등록의 약점이었다.
- 서브에이전트 호출 한도(동시 20)로 일부 배치를 나눠 투입했다.
