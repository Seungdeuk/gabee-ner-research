# R9 GPU 파일럿 계획 (실행 전 보고용, 미실행)

대상: RTX 3050 6GB, 서비스 모델과 같은 KoELECTRA-small. 승인 전에는 아무것도 실행하지 않는다.

## 목적
GPU 메모리·배치 크기·속도·OOM 여유, 체크포인트 저장과 불러오기(런 단위 재개), 군별 데이터 로딩(CP/F-full/C0)이 실제로 동작하는지 확인.

## 계획 (3개 런, 총 약 6~8분 예상)
| 런 | 군 | 에폭 | 에폭당 스텝 | 총 스텝 | 확인 항목 |
|---|---|---|---|---|---|
| pilot-r9-CP-s7 | CP | 2 | 147 | 294 | 데이터 로딩, 저장, 개발셋 평가 |
| pilot-r9-F-full-s7 | F-full | 2 | 245 | 490 | 가장 큰 군의 VRAM·속도, 신규 파일 로딩 |
| pilot-r9-C0-s7 | C0 | 2 | 245 | 490 | c0_extra 파일 로딩 |

- 명령: `python ml/ner/train/run_r9_arm.py --arms CP F-full C0 --seeds 7 --pilot --execute` (런 폴더 `pilot-*`, 전체 학습과 분리, 실패 시 자동 재시작 없음)
- 배치 32, max_len 128, fp16, lr 5e-5 (R8 대조군과 동일). 체크포인트는 개발셋(baseline_val)만으로 선택.
- OOM 여유: 같은 조건에서 배치 64 한 스텝 시험을 추가로 1회(저장 없음)하여 한계 확인. 실패해도 본 학습 설정(32)은 그대로.
- 체크포인트 점검: 저장된 `best/`를 `from_pretrained`로 다시 읽어 개발셋 일부 예측 해시가 학습 중 평가와 같은지 확인, ONNX 내보내기 1회(`export_onnx.py`).
- 재개: 학습 중간 재개는 지원하지 않음(`train_ner.py` 무수정). 런 단위로 `train_log.json` 유무로 완료를 판정하고 미완료 런만 처음부터 다시 돈다.

## 예상 자원 (R8 대조군 실측 기반 추정)
- VRAM 최대 약 0.8~1.0GB (6GB 중), RAM 약 3GB, 디스크 런당 약 50MB(best 저장).
- 속도: 대형 군(7,815행) 한 런 약 100~120초(8에폭 기준) → 파일럿은 2에폭이라 런당 약 30초 이내.
- 전체 45런(5시드×9군, C1은 R8 체크포인트 재사용이라 실제 학습 40런+) 예상: 약 65~70분 + ONNX 내보내기. 조기 종료로 더 짧을 수 있음.

## 하지 않는 것
봉인 평가셋 사용, 서비스 모델 교체, 전체 학습. 파일럿 결과는 모델 선택에 쓰지 않는다(개발셋 기록만).
