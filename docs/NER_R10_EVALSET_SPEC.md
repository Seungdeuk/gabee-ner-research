# NER R10 독립 평가셋 사전 설계 (학습 데이터 생성 전에 고정, 제작은 별도 세션의 GPT)

버전 r10-1.0, 2026-11-20. 공통 데이터 규격은 `NER_R9_COMMON_SPEC.md`(r9-1.1: 스키마, 라벨 정책, 1글자 이름 제외, 검증기 `validate_r9_evalset.py` 의 검사)를 **그대로** 따르며 이 문서는 R10 에서 달라지는 구성·표본 수·신규 이름 정의·검수·합의·교체 안전성 기준만 정한다. 이 문서는 평가셋 제작 세션과 사용자에게 공유하고, **학습 데이터·학습 틀·이름 풀·R9 봉인 평가셋은 제작 세션에 공유하지 않는다.**

## 1. 역할과 격리

| 주체 | 하는 일 | 하지 않는 일 |
|---|---|---|
| GPT(별도 세션) | 평가셋 제작(대표·스트레스) | 학습 데이터·틀·이름 풀·R9 봉인셋 열람, 기존 문장 복사 |
| Claude Code(학습 세션) | 학습 데이터 제작, 학습, 검증기 실행(코드·건수·id 만 열람) | 평가셋 문장·이름·정답·틀 열람, 평가셋으로 학습·튜닝·후보 선정 |
| 사용자·팀원 | 표본 검수, 합의, 봉인 승인 | |

- 평가셋은 학습·개발 평가·후보 선정에 쓰지 않는다. **최종 후보가 사전 등록 규칙으로 확정된 뒤 한 번만** 평가한다.
- R9 봉인 평가셋(소비됨)은 R10 의 개발셋·독립셋 어느 쪽으로도 쓰지 않는다. R9 의 문장·이름·정답을 복제하지 않고, R9 에서 확인된 문제 **유형**만 설계에 쓴다.
- 평가셋 제작 지시서(GPT 에게 줄 문서)는 별도 작성하며 이 문서 §2~§5 와 `NER_R9_COMMON_SPEC.md` 만 포함한다. 학습 쪽 예시 문장·이름은 담지 않는다.

## 2. 세트 구성

| 세트 | 문장 | PERSON 계열 포함 | 기타 개인정보만 | 개인정보 없음 |
|---|---:|---:|---:|---:|
| 대표(`representative`) | 1,600 | 950 | 250 | 400 |
| 스트레스(`stress`) | 2,000 | 1,400 | 100 | 500 |
| 합계 | 3,600 | 2,350 | 350 | 900 |

- 대표: R9 와 같은 구성(가족 호칭만 있는 음성 30~50개, 2글자 이름 구간 25~35%, 별명 8% 이상, PERSON 구간 합 1,500 이상). 가족 메신저 분포의 대표성을 주장하지 않는다(합성).
- 스트레스는 **유형별 목표 문장 수(대표 유형 기준, 문장당 `primary_stress_type` 1개)** 를 아래로 한다. 개선 목표 유형(굵게)은 R9 보다 3~5배로 늘려 유형 단위 판단이 가능하게 한다.

| 코드 | 정의 | R9 | **R10 목표** |
|---|---|---:|---:|
| A1 | 성 없는 2글자 이름, 낯선 이름 | 110 | 150 |
| A3 | 사람 이름이 지명·기관명처럼 보이는 문맥(사람으로 쓰임) | 90 | 100 |
| **B1** | 3~4글자 이름 뒤에 조사가 없어 마지막 글자 누락 위험 | 90 | **240** |
| B2 | 호격·조사가 붙은 이름(앞 글자 누락 위험) | 50 | 80 |
| C1 | 이름 뒤 조사 과확장 위험 | 60 | 100 |
| **C2** | 인접한 두 이름(공백 없음·쉼표·별명 붙임·접속) | 40 | **200** |
| D3 | 한 문장에 여러 사람 | 60 | 100 |
| **D1P** | 일반 명사와 같은 문자열이 **사람 이름으로** 쓰인 문장 | 50 | **250** |
| **D1** | D1P 와 짝인, 같은 문자열이 명사로 쓰인 음성 문장 | 90 | **250** |
| D2 | 이름처럼 보이는 어구·활용형이 든 음성 | 50 | 100 |
| A3N | 지명·기관명이 이름처럼 보이는 음성 | 40 | 60 |
| GENERIC | 일반 어려운 음성 | 20 | 40 |
| OTHER | 주소·전화·이메일·계좌만 있는 문장 | 50 | 50 |
| **NEWNAME** | 아래 §3 의 신규 이름이 중심인 PERSON 문장(문장 구조는 자유) | - | **280** |
| 합계 | | 800 | **2,000** |

- **D1P/D1 짝 규칙**: D1P 250문장과 D1 250문장은 가능한 한 같은 문자열(명사형 이름 단어)을 양쪽에 쓰고, 문장 틀은 서로 달라도 되지만 한 문자열의 문장 수 상한은 5개다. 단서가 사람/사물을 문맥으로 가를 수 있는 문장만 쓴다(작성자도 라벨을 못 정하면 제외).
- **B1**: 조사 없는 3~4글자 이름을 문말·쉼표·괄호·`씨`/`님` 앞·가족 호칭 앞 등에 고루. **C2**: 공백 없이 붙은 쌍, 쉼표·중점 나열, `랑/하고` 접속, 이름+별명, 세 명 나열을 고루.
- 문장이 여러 유형에 해당하면 `stress_types` 에 모두 쓰고 집계는 `primary_stress_type` 으로 한다.

## 3. 신규 이름(unseen name)의 정의와 이름 풀 분리

- **이름 부분(given)**: 성(1글자 또는 복성 `남궁·황보·선우·제갈·사공·독고`)을 뗀 부분. 성이 없는 이름은 값 전체. 별명은 값 전체.
- **참조 집합 R**: R9 학습·검증·개발 데이터와 R10 학습·R10 개발 데이터의 PERSON·PERSON_ALIAS 구간 값과 그 이름 부분(2글자 접미 포함).
- **신규 이름 정의**: PERSON 구간의 이름 부분이 R 에 **없고**, 이름 부분이 R 의 어떤 값과도 포함 관계(길이 3 이상 부분 문자열)가 아닌 이름. 모든 PERSON 문장에 검증기가 `name_seen_in_reference` 를 표시하고, **신규 이름 층**은 그 값이 false 인 구간이다. 이 층은 최종 평가에서 별도 보고한다(대표·스트레스 모두).
- **제작 세션 지침(이름 풀)**: 제작자는 학습 데이터를 모르므로 이름을 겹침 없이 만들 수 없다. 대신 (1) 흔한 이름 상위권(예: 연도별 인기 이름)을 피하고, (2) 이름 값당 재사용 4회 이하, 서로 다른 PERSON 값 비율 60% 이상, (3) 성·이름 조합을 다양하게(2글자 이름 25~35%, 3글자, 4글자), (4) 옛스러운 이름·순우리말·외래식 이름·가족 별명을 포함하도록 한다. **학습 쪽은 R10 개발셋 전용 예약 이름 구간을 학습에서 영구 제외하고 R9 에서 쓴 이름 부분도 R10 학습에 쓰지 않는다.** 그래도 독립셋의 신규 이름 비율은 사후에야 알 수 있으므로 NEWNAME 층의 구간 수가 150 미만이면 신규 이름 결과를 "표본 부족"으로 표기하고 교체 기준의 신규 이름 조건은 **보고 전용**으로 낮춘다(사전 고정).
- 평가 때 이름 겹침은 오류가 아니다. `name_seen_in_reference` 로 층화한다.

## 4. 라벨 정책 (r9-1.1 유지)

- 한 글자 PERSON 이름 문장은 평가셋에 넣지 않는다(쓰면 `exclude: one_char_name`). 이 한계는 최종 보고서에 명시한다.
- PERSON_ALIAS: 별명 자체만. `이름+가족호칭`은 이름 부분만 PERSON(호칭·조사 제외). 별명/명사 동형은 사람 지칭 문맥에서만 PERSON_ALIAS. 호칭만 있는 문장은 음성. PERSON·PERSON_ALIAS 구간 값에 가족 호칭이 들어 있으면 검증 오류.
- 이 외 정의는 `NER_R9_COMMON_SPEC.md` §3 과 같다.

## 5. 검수와 라벨 합의

1. **검수량**: 전체의 15% 이상(540문장 이상). 층화 무작위(유형·세트별 최소 15문장) 표본 + 고위험 사례 전수 확인 100문장(D1P/D1 짝, 별명, C2, 다인물). 표본 id 는 검증기가 뽑는다(id 만 출력).
2. **검수자**: 사람 2명이 서로의 판정을 보지 않고 독립 검수한다(정상/수정/제외, 오류 유형). 한 명은 제작 세션과 무관한 사람이어야 한다.
3. **합의**: 두 검수자가 다르면 제3자(또는 두 사람 협의)가 확정하고 이견 건수·유형을 기록한다. 검수자 간 구간 일치율(Cohen's κ 또는 구간 단위 일치율)을 보고한다. 이견률이 5%를 넘는 유형은 제작자가 해당 배치를 다시 만든다.
4. **봉인 기준**: 표본 구간 오류율 2% 이하면 봉인, 2~5% 면 수정 후 150문장 추가 검수, 5% 초과면 해당 배치 재작성. 유형별로 따로 본다(D1P·D1·B1·C2 는 각 오류율이 3%를 넘으면 해당 유형 재작성).
5. 봉인 후 수정은 새 버전으로만 하고, 결과를 본 뒤의 수정은 해당 세트를 개발용으로 분류한다. 읽기 전용 + SHA256 매니페스트(버전, 검증 결과 요약).

## 6. 중복·문형 유사도 검사 기준 (검증기, 원문 미출력)

- id·문장·정규화 문장 중복 0, `text[start:end]==value`, 라벨·매핑·겹침·음성 일관성 오류 0(R9 와 같음).
- 문장 틀(span 을 `§` 로 치환) 같은 틀은 세트 안에서 최대 2회. 4-gram 유사도 0.7 이상 근접 중복이 세트 안에서 3% 초과면 오류. **D1P/D1 의 같은 단어 문장 수 5개 초과, PERSON 값 재사용 4회 초과는 오류.**
- 학습·R10 개발·R9 학습·개발·R9 봉인 데이터와의 대조(프로그램 안에서만, 건수만 보고): 문장·정규화 문장 일치는 오류, 문장 틀 일치 2%·4-gram 유사 3% 초과는 오류. **단 R9 봉인셋과의 대조는 독립셋 제작·검증 세션(학습 세션이 아님)이 수행하며 학습 세션은 R9 봉인셋을 열지 않는다.**
- 이름 겹침은 오류가 아니고 `name_seen_in_reference` 로 표시한다.

## 7. 모델 선정 및 서비스 교체 안전성 기준

별도 문서 `NER_R10_PREREGISTRATION.md` §7·§8 이 정한다(개발셋 선정 규칙, 독립셋 최종 교체 권고 조건). 요지: 노출률이 가장 중요한 지표이고 F1 만 오르거나 특정 고위험 유형이 악화되면 교체를 권고하지 않는다. 독립셋은 결과를 본 뒤 기준·후보·시드를 바꾸지 않는다.
