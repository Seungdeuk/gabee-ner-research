# NER R9 공통 데이터 규격 (학습 데이터 작성자와 평가셋 작성자가 공유하는 유일한 문서)

버전 **r9-1.1**(정책 변경 반영, 변경 이력은 §3-1), 2026-11-19. 양측이 공유하는 것은 이 규격(스키마, 엔티티 정의, 분할·평가 지표)뿐이다. 평가셋 작성자(ChatGPT)는 학습 데이터를, 학습 데이터 작성자(Claude Code)는 평가셋의 문장·이름·정답·생성 틀을 서로 보거나 참고하지 않는다. 작성자가 다르다는 사실만으로 독립이 보장되지 않으므로 중복·유사도·누수 검사는 반드시 한다.

## 1. 역할

| 역할 | 담당 | 하지 않는 것 |
|---|---|---|
| 학습 데이터 작성 | Claude Code | 평가셋 문장·이름·정답·템플릿 열람, 평가셋 내용으로 학습 데이터 조정 |
| 독립 평가셋 작성(대표·스트레스) | ChatGPT | 학습 데이터 열람, 기존 학습·평가 문장 복사 |
| 표본 검수, 최종 승인 | 사용자·팀원 | |
| 자동 검증·매니페스트 | `validate_r9_evalset.py` | 원문 출력(id·코드·건수만 출력) |

## 2. 공통 원본 형식(JSONL, 한 줄 = 한 문장, UTF-8)

기존 new180 과 같은 형식이다. 오프셋은 Python 유니코드 문자열 기준, 0 부터, `end` 미포함이다.

필수 필드: `id`(고유), `category`(문장 유형·도메인), `text`, `spans`(보호 대상 정답 목록), `is_negative`(보호 대상이 없는 문장이면 true), `source`(출처).
span 필수 필드: `start`, `end`, `label`(원본 라벨), `mapped_kind`(서비스 평가용 매핑 라벨), `value`(= `text[start:end]`).

선택 필드(기존 평가 코드는 모르는 키를 무시하므로 호환된다):

| 필드 | 뜻 |
|---|---|
| `split_set` | `representative` 또는 `stress` |
| `primary_stress_type` | 스트레스 세트의 대표 유형 코드(문장당 1개, 표본 수 집계 기준) |
| `stress_types` | 해당하는 모든 유형 코드(복수 가능, 2차 보고용) |
| `template_id` | 작성자가 틀을 썼다면 틀 번호(없으면 생략) |
| `style`, `scenario`, `batch` | 문체, 시나리오, 생성 배치 |
| `context_entities` | 보호 대상이 아닌 LOCATION·ORGANIZATION 구간 `{start,end,label,value}` |
| `exclude`, `exclude_reason` | 제외 대상 표시(예: 1글자 이름 문장). 제외 행은 모든 집계에서 빠지고 사유별로 보고만 한다 |

추가 메타데이터가 더 필요하면 별도 manifest 로 둔다. 학습 쪽 BIO 변환은 `ml/ner/data/convert_common_to_train.py` 가 한다(공통 원본은 바꾸지 않는다).

## 3. 라벨과 서비스 정책(기존 `LABELING_GUIDE.md`, `policy.py` 기준)

| label | mapped_kind | 서비스 정책 | 설명 |
|---|---|---|---|
| PERSON | PERSON | MASK | 성+이름, 또는 이름만 불리는 경우의 이름 부분. 호칭(씨·님)과 조사는 제외. **이름 뒤에 가족 호칭(엄마·아빠·언니·할머니·고모·이모·삼촌 등)이 붙어도 호칭은 구간 밖**(일반 텍스트) |
| PERSON_ALIAS | PERSON | MASK | 사람을 지칭하는 실제 별명·애칭의 **별명 자체만**. 단순 호칭이나 `이름+호칭`은 별칭이 아니다(이름 부분은 PERSON). 별명이 일반 명사와 같은 문자열이면 실제 사람을 지칭하는 문맥에서만 PERSON_ALIAS, 명사 문맥에서는 라벨 없음. 원본 라벨은 보존하고 평가에서만 PERSON 계열로 접는다 |
| ADDRESS | ADDRESS | MASK | 번지·도로명+번호·동·호수처럼 상세 위치 |
| PHONE | PHONE | MASK | 개인 전화번호(기관 대표번호 1588 등은 보호 대상이 아니므로 span 으로 라벨하지 않는다) |
| EMAIL | EMAIL | MASK | 이메일 주소 전체 |
| ACCOUNT | ACCOUNT | BLOCK | 계좌 숫자열만(은행명·`계좌` 단어 제외). 일반 가명화(MASK) 점수와 분리 평가한다 |

- 위 6개만 `spans` 에 쓴다. RRN·CARD·SECRET 등은 이번 연구 범위가 아니다(쓰면 검증 오류).
- LOCATION(`강남역`)과 ORGANIZATION(`새봄병원`)은 보호 대상이 아니다. 필요하면 `context_entities` 로만 표시한다. 금융기관명은 라벨 없음.
- 호칭만 있는 `엄마`·`큰아들`·`시어머니`는 라벨 없음이고, 호칭만 있는 문장은 보호 대상 이름이 없으면 음성이다. 날짜·금액·주문번호·운송장은 라벨 없음.
- 이름과 가족 호칭이 붙어 있으면(공백 없음 포함) **이름 부분만** 구간으로 잡고 호칭과 접미 `이`·조사는 구간 밖에 둔다. 경계는 문맥과 정답 구간을 확인해 정하며 마지막 글자를 기계적으로 자르지 않는다.
- PERSON 과 일반 단어가 같은 문자열이면 문맥으로 정확히 구분한다(사람으로 쓰인 경우만 PERSON).
- 구간은 값 자체만 잡는다. 앞뒤 조사·호칭·따옴표·공백은 제외하고, 구간끼리 겹치지 않는다.
- 한 문장에 보호 대상이 여러 개면 **모두** 라벨한다. 정답 누락은 평가셋에서 가장 흔한 품질 문제다.

### 3-1. 정책 버전과 변경 이력

| 버전 | 날짜 | 변경 | 영향 |
|---|---|---|---|
| r9-1.0 | 2026-11-19 | PERSON_ALIAS = 별명, 그리고 `이름+가족호칭` 전체 | |
| r9-1.1 | 2026-11-19 | `이름+가족호칭`은 PERSON(이름 부분)+호칭은 구간 밖, PERSON_ALIAS 는 별명 자체만, 별명/명사 동형은 문맥으로, 호칭만 있는 문장은 음성 | 서비스 규칙 계층·게이트웨이는 이미 일치(코드 변경 없음). 기존 학습 데이터 416구간 재라벨(원본 보존, 변경 로그), 개발 게이트 주 5세트에는 해당 정답 0건이라 영향 없음. 서비스 모델은 구정책으로 학습되어 `이름 호칭`을 한 구간으로 가릴 수 있고 이는 정책 차이이므로 최종 평가에서 정책 효과와 보호 효과를 분리 보고 |

정책 변경만으로 성능이 좋아진 것처럼 주장하지 않는다. 서로 다른 정책 버전의 정답을 가진 평가 결과끼리 비교하지 않는다.

## 4. 이번 연구에서 제외하는 문장

- **1글자 PERSON 이름이 들어간 문장**: 평가셋·학습·검증 어디에도 넣지 않는다. 쓰이게 되면 `exclude: true`, `exclude_reason: "one_char_name"` 로 표시한다. **개인정보 없는 음성 문장으로 바꾸지 않는다.** `봄`, `솔`, `별`, `율`, `결`, `담`, `온`, `겸`, `찬`, `휘`처럼 1글자 이름으로 쓰이는 글자가 이름일 수 있는 문장은 쓰지 않는다.
- 반려동물 이름, 사람 별명인지 구분이 안 되는 사례, 작성자도 라벨을 못 정하는 모호 사례: 쓰지 않는다(쓰면 제외 표시).
- 이 제외는 연구 범위를 좁히는 결정이며 1글자 이름의 노출 위험이 해결됐다는 뜻이 아니다. 최종 보고서에 한계로 명시한다.

## 6. 품질·다양성 기준(검증기가 확인)

- 문장 id·문장 중복, 정규화(공백·구두점 제거) 중복 없음. `text[start:end] == value`, 라벨·매핑 적합, 구간 겹침 없음, 음성 문장 일관성(`is_negative` 와 span 유무 일치).
- 이름만 바꿔 문장 수를 채우지 않는다: 같은 문장 틀(span 을 `§` 로 바꾼 것)은 최대 2회, 4-gram 유사도 0.7 이상인 근접 중복이 세트 안에서 3%를 넘으면 오류. 서로 다른 PERSON 값 비율과 값당 최대 재사용(4회 이하)을 보고한다.
- 정책 r9-1.1: PERSON_ALIAS·PERSON 구간 값에 가족 호칭이 들어 있으면 오류(`ALIAS_CONTAINS_KIN_TERM`, `PERSON_CONTAINS_KIN_TERM`). 이름 뒤에 가족 호칭이 이어지는 문장(`kin_adjacent`)의 수와 id 를 남기고, 대표 세트에서 호칭이 든 음성 문장이 30개 미만이거나 2글자 이름 비율이 25~35%를 벗어나면 경고한다.
- 보호 대상이 아닌 문장에 숨은 전화·이메일·계좌·주소 패턴이 있는지, 세트 안에서 사람으로 라벨된 문자열이 다른 문장에 라벨 없이 나오는지 경고한다.
- 학습·개발·이미 소비된 평가셋과의 문장·정규화 문장 일치는 오류, 문장 틀 일치 2%·4-gram 유사 3% 초과는 오류. 이름 겹침은 오류가 아니라 문장별로 `name_seen_in_reference` 표시를 남겨 최종 평가에서 층화한다.
- 모든 검사는 원문을 출력하지 않는다(코드·건수·id 만).

## 7. 인계·봉인

1. 작성자는 `tag_to_r9_jsonl.py` 로 태그 문장에서 오프셋을 자동 계산해 JSONL 을 만든다(`[[PERSON|서아]]` 형식, 손으로 오프셋 계산 금지).
2. 파일 두 개를 `C:\Users\<user>\Documents\gabee-ner-sealed-r9\incoming\` 에 둔다: `r9_representative_v1.jsonl`, `r9_stress_v1.jsonl`.
3. 학습 데이터 작성 쪽은 검증기를 돌려 집계·id 만 받고 작성자에게 전달한다(수정은 작성자가).
4. 검증 오류 0, 표본 검수 완료 후 `sealed\` 로 복사해 읽기 전용으로 두고 SHA256 매니페스트(데이터셋 버전, 생성·검증 시각, 검증 결과 요약)를 만든다.
5. 봉인 후 수정이 필요하면 새 버전(v1.1)과 변경 이력으로 남기고, 결과를 본 뒤의 수정은 해당 세트를 개발용으로 분류한다.

## 8. 표본 검수

- 전체의 10% 이상(약 240문장), 가능하면 300문장. 층화 무작위 표본과 고위험 사례(다인물, PERSON/LOC/ORG 중의성, 일반 명사와 이름의 경계, 별칭, 인접 이름)를 별도로 추가 검수한다. 표본 id 는 검증기가 `--make-review-sample` 로 뽑는다(id 만 출력).
- 검수 결과: 정상/수정/제외, 오류 유형, 수정 건수를 기록하고 검수한 수량만 보고한다. 표본 오류율(구간 단위)이 2% 이하면 봉인, 2~5%면 수정 후 100문장을 추가 검수, 5%를 넘으면 해당 배치를 다시 만든다.
- 자동 검증은 의미적 라벨 정확성을 보장하지 않는다. 남은 검수 한계를 기록한다.

## 9. 평가 지표(요약, 정의는 `NER_R9_PREREGISTRATION.md`)

Exact Span Precision/Recall/F1, 보호 대상 Recall, 완전·부분·전체 이름 노출률, 비PERSON 오탐률, 과잉 병합, 유형별 오류, 지연. 분자·분모·건수·95% 신뢰구간을 함께 표기하고, 서비스 모델과 후보를 같은 문장에 적용해 개선·악화 건수를 짝지어 비교한다. 반복되는 이름·틀 때문에 표본이 독립이 아니므로 이름·틀 단위 군집 부트스트랩을 쓴다. 정책 r9-1.1 때문에 **전체 / `kin_adjacent` / 그 밖(정책 중립)** 세 층으로 나눠 보고한다. 노출률·오탐률·과잉 병합은 정책과 무관한 보호 지표이고, `kin_adjacent` 문장의 Exact 지표는 정책 차이의 영향을 받는다.
