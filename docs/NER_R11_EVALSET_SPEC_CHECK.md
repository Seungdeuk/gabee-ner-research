# R11 독립 평가셋 사양 점검: `NER_R10_EVALSET_SPEC.md` 와 R11 요구사항의 일치 여부

2026-11-20. 점검만 했고 **평가셋 생성·봉인은 하지 않았다**(사용자 별도 확인 후). 제작 지시서 수정안은 "5. 제안"에 있으며 승인 전에는 적용하지 않는다.

## 1. 확인 방법과 현재 상태
- 대조 문서: `NER_R10_EVALSET_SPEC.md`(§2 세트 구성, §3 신규 이름, §5 검수), `NER_R11_PREREGISTRATION.md`(§5-1 독립 테스트, §7-1 지표, §9 비교).
- 저장소에서 R10·R11 독립 평가셋 파일·봉인 매니페스트는 확인되지 않았다(사양 문서만 존재). 제작·봉인 상태는 사용자 확인이 필요하다.

## 3. 부족하거나 불일치하는 항목
| # | R11 요구 | 사양의 현재 내용 | 부족 |
|---|---|---|---|
| 1 | **D1P/D1 쌍 300개 이상**(쌍 문맥 정확률의 불확실성 때문, `NER_R11_PREREGISTRATION.md` §5-3) | 스트레스 D1P 250문장, D1 250문장, "가능한 한 같은 문자열"을 양쪽에 쓰되 문자열당 문장 수 상한 5개. 대표 세트의 D1P/D1 문장 수는 유형별로 정해져 있지 않음 | **반영되지 않음.** 쌍이 많아야 250개(<300), 짝 정의가 느슨해 실제 완전한 쌍 수는 더 적을 수 있음 |
| 2 | 쌍을 정확히 짝지어 채점(같은 단어, 사람 문장 + 명사 문장) | `pair_id`·`role` 필드 없음. 짝은 "가능한 한"이라는 권고 | **쌍 식별자와 역할 필드가 없어 쌍 문맥 정확률을 계산할 수 없음** |
| 3 | 긴 이름(LONGNAME: PERSON 구간 4글자 이상) 별도 층 | B1 정의에 "3~4글자"가 있을 뿐 긴 이름 층 없음 | **층 없음**(Recall·노출을 따로 못 냄) |
| 4 | ORG/LOC 와 이름이 섞인 문장(기관·지명이 이름처럼 보이는 문맥에서 이름 탐지) | A3(사람 이름이 지명·기관처럼 보임, 100), A3N(음성 60)만 있음. 이름 + 기관·지명 혼합 문장 층 없음 | **혼합 층 없음** |
| 5 | 기존 이름(학습에 나온 이름) 정상 문맥 유지 확인 | `name_seen_in_reference` 로 사후 층화만 가능, 목표 문장 수 없음 | 층 크기 미보장 |
| 6 | 참조 집합 R | R9 학습·검증·개발 + R10 학습·개발 | **R11 학습(D′)·Validation·Development 의 이름 추가** 필요(제작자는 모르므로 사후 계산) |
| 7 | Exact Recall(최우선), 가림률, 경계만 틀림 | 평가 코드의 문제이고 사양은 지표를 정하지 않음 | 사양 수정 불필요, 평가 코드 `r11_eval_lib.py` 로 처리. 단 **PERSON 구간 수**가 Recall 의 신뢰구간을 정하므로 목표 구간 수를 정할 필요 |
| 8 | 검증기가 `pair_id`·`LONGNAME` 유형을 확인 | `validate_r9_evalset.py` 는 쌍·긴 이름을 모름 | 검증기 확장 필요 |
| 9 | 유형별 표(코드+한글명) | 코드만 있고 한글 유형명 일부 누락 | 표기 규칙 추가 |
| 10 | 쌍 문맥에서 어휘 의존 제한 | 문자열당 최대 5문장(쌍이 아니라 문장 기준) | 문자열당 **최대 4쌍**으로 바꿔야 서로 다른 단어 ≥75개 보장 |

## 4. 영향 요약
- **필수 수정 2건(#1, #2)**: 이대로 제작하면 R11 의 쌍 문맥 정확률 게이트(R11-G7)와 최종 비교 지표를 독립 평가셋에서 산출할 수 없다.
- **권장 3건(#3, #4, #10)**: 긴 이름·ORG/LOC 혼합 층이 없으면 KLUE 에서 본 긴 이름 약화를 독립 평가에서 확인하지 못한다.
- 나머지(#5~#9)는 평가 코드·검증기·표기 보완으로 처리 가능.

## 5. 제안(사용자 승인 후 사양 개정본 `NER_R11_EVALSET_SPEC.md` 로 작성, 아직 적용 안 함)
1. 스트레스 세트 D1P·D1 을 **각 300문장 이상, 정확한 쌍(300쌍 이상)**으로 한다. 쌍마다 `pair_id`(예: `ev-p-001`), `role`(`person`/`noun`), `pair_word` 필드를 필수로 하고, 한 단어는 최대 4쌍. 대표 세트 D1P/D1 쌍은 별도(선택)로 두고 쌍 문맥 정확률은 스트레스 300쌍으로 산출한다.
2. **LONGNAME** 유형 신설: PERSON 구간 4글자 이상, 120문장 이상(조사 있음·없음 혼합).
3. **ORG/LOC 혼합** 유형 신설: 같은 문장에 기관·지명과 사람 이름이 함께 나오는 문장 100문장 이상(이름이 기관·지명처럼 보이는 경우 포함).
4. 기존 이름(참조 집합에 있는 이름)의 정상 문맥은 대표 세트에서 사후 층화로 확인하고 **PERSON 구간 최소 300개**를 목표로 한다.
5. 총 문장 수는 스트레스 2,000 → **2,350 내외**로 늘리거나 OTHER·GENERIC·A1 중 일부를 줄인다(사용자 결정). 늘릴 경우 이중 검수 비율 15% 이상을 유지(540 → 약 600문장).
6. 검증기 확장: `pair_id`·`role` 무결성(쌍마다 사람 1·명사 1, 같은 단어, 사람 문장에 단어가 PERSON 구간, 명사 문장에는 아님), LONGNAME 구간 길이, ORG/LOC 혼합 유형 확인.
7. 유형 표기는 영문 코드 + 한글 유형명(D1P 이름·일반명사 중의성에 따른 PERSON 미탐, D1 일반명사 PERSON 오탐, B1 이름 뒷부분 누락·부분 노출, C2 이름 구간 경계 오류, LONGNAME 긴 이름, NEWNAME 신규 이름).
8. 참조 집합 R 에 R11 데이터를 더하고 `name_seen_in_reference` 는 봉인 후 건수만 계산(문장 원문 미열람).

## 6. 필요한 결정
- 사양 개정(위 1~8)을 적용해도 되는지, 총 문장 수를 늘릴지 일부 유형을 줄일지.
- 독립 평가셋 제작·봉인 세션을 언제 여는지(별도 승인).
