# NER R11 사전 등록 r11-2.0 — 자동 검증 기반 연구용 프로토콜 (B 학습 전에 기록, 이후 결과를 보고 바꾸지 않는다)

버전 r11-2.0, 2026-11-20. 사용자 조건부 승인(2026-11-20)에 따라 `NER_R11_AUTOQA_TRANSITION_PROPOSAL.md` 의 전환안을 적용한다. **이 문서는 기존 사전 등록 `NER_R11_PREREGISTRATION.md` r11-1.4(태그 `r11-prereg-1.4`)를 대체하거나 고쳐 쓰지 않고, 품질 검수 절차의 변경만 따로 기록한다.** r11-1.4 의 모든 규칙(게이트 G1~G12, R11-R1~R4, R11-S, 종합 후보 선정 규칙, G12, 평가셋·기준선·Recall 게이트 수치)은 아래 §3 의 항목만 제외하고 그대로 유효하다.

## 1. 현재 상태 구분 (모든 보고서에 이 표현을 그대로 쓴다)

| 구분 | 상태 |
|---|---|
| 확정 구조 오류 | **0건** (학습 D′ 800 · Validation 600 · Development 1,920 전체, 자동 검증 `r11_auto_qa.py`) |
| 확정 표면 오류 | **Development 3행**(이름 뒤 조사 받침 불일치, 라벨·구간 경계는 정확, §4 한계 참조) |
| 사람 의미 검수 | **519건 미완료**(판정 파일 없음, 미판정은 통과가 아니며 정상으로 간주하지 않는다. 선택 사항이던 우선 22행 부분 검수도 하지 않았다) |
| 해결되지 않은 의미 품질 위험 | 별도 기록(§4): 외래어 의심 대조쌍 7쌍, 별명 충돌 2행, 사람/명사 단서가 약해 보이는 대조쌍 45쌍, 기계적 접두·접미 반복 12행(학습), C2 접속 간격 1행(구조 정상), 전체 자연스러움·합성 분포 균질성 |
| 연구용 학습 | **가능**(조건부: §5·§7 점검 통과) |
| 정식 검증 및 운영 교체 자격 | **없음** (사람 의미 검수 미완료, 독립 테스트 미실행) |

요약 선언: 확정 구조 오류 0건, 확정 표면 오류 Development 3행, 사람 의미 검수: 519건 미완료, 연구용 학습 가능, 정식 검증 및 운영 교체 자격 없음.

**소급 금지**: r11-1.4 §4-4 가 요구한 사람 표본 검수 통과는 **충족되지 않았다.** r11-2.0 은 이 사실을 소급해 충족한 것으로 취급하지 않는다. 자동 검증 결과는 사람 검수 결과를 대체하지 않으며, "정식 검증 완료"로 표현하지 않는다. 사람 검수 결과는 생성하거나 대신 입력하지 않는다.

## 2. r11-1.4 대비 변경 사항과 이유

| # | 항목 | r11-1.4 | **r11-2.0** | 변경 이유 |
|---|---|---|---|---|
| 1 | B 학습 전 품질 요건(§4-4) | 사람 표본 검수 519건 통과 필수 | **연구용 학습**: 자동 검증에서 확정 구조 오류 0, 확정 표면 오류는 알려진 Development 3행 이하, 의미 경고 문서화, 데이터 변경 없음, 해시 고정으로 학습 허용. 사람 검수는 **요건이 아니라 미완료 상태로 기록** | 일정상 사람 검수를 할 수 없고, 마지막 라운드의 연구를 정직한 한계 표시와 함께 완료하기 위해 |
| 2 | 결과의 지위 | 사람 검수 통과가 교체 권고의 전제 | 모든 결과는 **"자동 검증 기반 연구용 · 사람 의미 검수 미완료"** 로 표기. 후보가 게이트를 통과해도 **연구상 최우수 후보**일 뿐 **운영 교체 후보 자격이 없다** | 품질 불확실성이 남은 결과로 운영을 바꾸지 않기 위해 |
| 3 | 교체 자격 | 독립 테스트 통과 + 사람 검수 통과 | (가) 사람 의미 검수 완료·통과 **그리고** (나) 독립 테스트 통과가 모두 있을 때만 가능. 없으면 결론은 **S0 유지 + 연구 결과 보고** | 위와 같음 |
| 4 | 의심 행 민감도 | 규정 없음 | Development 의심 12행 제외 시나리오를 결과에 **항상 병기**(§6, 보조 분석, 공식 판정의 대체 아님) | 의심 행이 판정에 주는 영향을 숨기지 않기 위해 |
| 5 | 학습 직전 점검 | 사람 검수 집계 verdict==pass 요구 | `r11_pretrain_check.py --mode research`(기본): 자동 검증 재실행 + 상태 문구 확인. `--mode strict` 는 r11-1.4 요건 그대로 | 연구용 학습 가능 여부를 점검하되 strict 요건 미충족 사실은 남기기 위해 |
| 6 | 자동 검증의 C2 간격 휴리스틱 | (규정 없음; 검수 보조 도구에 임의의 "간격 3 이하" 기준) | **간격 8 이하**로 조정, 간격 4~8 의 1행은 의미 경고(M)로 기록 | 임의 기준이 사양의 C2 정의(접속·쉼표·중점 나열 포함)보다 엄격해 구조가 정상인 1행을 오류로 오분류했다. 데이터·라벨은 바꾸지 않았다 |
| 7 | 후보 선정 출력 | 후보 이름과 근거 | 출력에 **연구 후보 지위·교체 자격 없음·품질 민감 여부**를 항상 포함(`select_r11.py classify`) | 두 자격의 혼동 방지 |

**변경하지 않는 것**: 학습·Validation·Development **원본 데이터**(삭제·라벨 수정 없음, 매니페스트 해시 동일), R11-G1~G12, R11-R1~R4, R11-S, 종합 성능 선정 규칙(우위 제거 → 동일 비중 순위합 → 결정적 동률), 고정 기준선(`r11_reference_baselines.json`)·Recall 게이트 수치(`r11_recall_gate_fixed.json`), G12, 평가 코드의 판정 로직. Recall·Precision·F1·전체 노출률을 함께 평가한다. **게이트를 사후 완화하지 않는다.**

## 4. 한계와 해결되지 않은 의미 품질 위험 (결과 보고서에 그대로 옮긴다)

1. **확정 표면 오류 3행**: Development C2 3행의 `와/과` 조사가 받침과 어긋난다(틀 작성자가 조사를 직접 쓴 형태로 추정, 미확인). 라벨 구간·경계는 정확하지만 **입력 문장이 부자연스러워 모델 예측(토큰 분절·확률)에 영향을 줄 수 있다.** 이 3행은 수정·삭제하지 않았다(수정하면 기준선·게이트 전체 재계산 필요). 영향은 §6 의 민감도로 병기한다.
2. **사람/명사 단서가 약해 보이는 대조쌍 45쌍**(학습 20·Validation 16·Development 9): 쌍 문맥 정확률(G7)·D1P/D1 게이트가 모델 능력이 아니라 데이터의 모호함을 반영할 수 있다.
3. **외래어 의심 대조쌍 단어 7쌍**(Validation 4·Development 3)과 **별명 충돌 2행**: 의미 판단 미완료.
4. **기계적 접두·접미 반복 12행**(학습 1.5%, `train/pairs_b`)과 틀 작성 에이전트의 스크립트 결합: 문장 구조 다양성이 계획보다 낮을 수 있다.
5. **전체 자연스러움·가족 메신저 분포의 대표성**: 합성 데이터와 같은 계열 LLM 틀의 균질성. 사람이 읽고 확인하지 않았다.
6. **게이트 경계 민감도**: Development 의 작은 유형 표본(C2 120행 등)에서는 몇 행 차이로 임계값 근처 모델의 판정이 달라질 수 있다.
7. 개발 평가가 독립 평가에서 더 나쁘게 나올 수 있다(R9: 개발 3.56% 대 독립 11.29%).

## 5. 학습 진행 조건 (연구용, 모두 충족해야 B 학습 시작)

1. 자동 품질 검사에서 확정 구조 오류 0(`r11_pretrain_check.py --mode research`가 자동 검증을 다시 실행해 확인), 확정 표면 오류 ≤ 3행(알려진 Development 3행), 기록된 보고와 같음.
2. 해결되지 않은 경고와 한계를 §4 에 문서화(완료).
3. 데이터 변경 없음. 변경이 필요해지면 임의로 진행하지 않고 보고하며 기준선·게이트 재고정 후 새 승인을 받는다.
4. 이 문서(r11-2.0)를 로컬 커밋하고 태그 `r11-prereg-2.0` 생성.
5. 데이터·평가 코드·사전 등록 문서·기준선·Recall 게이트 해시를 `r11_code_pin.json` 으로 고정(`--write-pin`, 전체 점검 통과 시에만). 고정 후 변경이 발견되면 임의로 수정하거나 학습하지 않고 보고한다.
6. B군 설정: **신규 학습 5회**(시드 7·13·21·42·99, 순차), 학습 데이터 **9,915행**(R9F 7,815 + 신규 대조쌍 800 + R10 기존 900 + R9F 보호 400), **하이퍼파라미터 변경 없음**(max_len 128, batch 32, lr 5e-5, 최대 8에폭, patience 2, baseline_val 선택, warmup 10%, weight decay 0.01, fp16), B-old·B-new·C-SWA 는 **같은 런에서 파생**, 첫 GPU 실행에서 `best/` 와 `epoch_{best}/` 가중치 해시 일치 확인(불일치 시 중단), 런 단위 완료 기록(`pipeline_done.json`), 단계 실패·메모리 부족 시 자동 재시작 없이 중단, **A군 C10 재학습 금지**(재추론만).
7. 실제 GPU 학습은 위 고정 결과를 사용자에게 보고한 뒤 별도 최종 승인으로 시작한다.

## 6. 보조 민감도 분석 규칙 (공식 평가의 대체 기준이 아니다)

- **공식 게이트 판정은 고정된 원본 Development(`r11_dev` 1,920행) 기준**이다.
- 모든 연구 결과(기준선·B-old·B-new·C-SWA)에 **의심 Development 12행을 제외한 지표·게이트 판정을 보조로 항상 병기**한다(`r11_flagged_sensitivity.py`, 두 시나리오: 의심 12행 전부 제외, 확정 표면 오류 3행만 제외).
- 보고 항목: 제외 전후 Recall·F1·전체 노출률·쌍 문맥 정확률·표적 매크로 노출률 변화(%p)와 **게이트 판정 변화**(어느 게이트가 어떻게 바뀌었는지).
- **게이트 판정이 하나라도 달라지는 모델은 "품질 민감 후보(quality_sensitive)"로 표시**하고 선정 결과에도 표시한다(`select_r11.py` 의 `quality_sensitive`).
- **결과를 보고 유리한 평가셋(원본 대 제외본)을 선택하지 않는다.** 선정·게이트·순위는 항상 원본 기준이다. 민감도 결과는 선정을 바꾸지 않으며 "경계 판정" 해석에만 쓴다.
- 기록된 기준선 민감도(`r11_flagged_sensitivity.json`): 지표 변화는 최대 Recall 0.16%p·전체 노출 0.10%p·쌍 정확률 0.35%p·F1 0.21%p, 게이트가 달라진 모델은 4개(S0 G8, R9F 시드 13 G5, R10-full 시드 13 R3, R9F 시드 99 R3).

## 7. 연구용 모델 선정과 두 자격의 구분

- 비교(동일 평가셋 `r11_dev`·R9dev 5세트·KLUE val, 평가셋 이름을 모든 표에 명시): S0 서비스 v2b, R9F(5시드), C10(5시드), R10-full(5시드), R11 B-old·B-new·C-SWA(각 5시드). 공식 Exact Precision·Recall·F1(전체 Precision 별도), 전체·완전·부분 노출률, D1P·D1·B1·C2 유형별, 신규 이름·긴 이름, 5시드 평균·표준편차·최악값.
- 선정은 r11-1.3 규칙 그대로(게이트·R11-S 통과 후보 → 우위 제거 → 순위합 → 결정적 동률). B-old 는 분석 전용이며 후보 자격이 없다.
- **연구상 최우수 후보**: 게이트와 R11-S 를 통과한 후보 중 위 규칙으로 선정된 모델에만 붙이는 명칭. **운영 교체 후보 자격과 다르다.** 사람 검수와 독립 테스트가 완료되지 않았으므로 어느 후보도 운영 교체 후보가 될 수 없고, 독립 평가는 실행하지 않는다.
- 통과 후보가 없으면 연구 결과(표·그래프)만 보고하고 S0 유지로 마무리한다.

## 8. 보고서 필수 문구

모든 R11 성능표·그래프·요약 첫머리에: **"자동 검증 기반 연구용 결과입니다. 사람 의미 검수(519건) 미완료, 독립 테스트 미실행. 정식 검증이 완료되지 않았으며 운영 모델 교체 근거가 아닙니다."** 와 평가셋 이름(`r11_dev` 등)을 명시한다. 해결되지 않은 의미 품질 위험(§4)과 민감도 병기(§6)를 결과와 함께 싣는다.

## 9. 금지 사항(이 단계 이후에도 유지)

사람 검수 결과 허위 생성·대리 입력, 평가셋 임의 삭제·수정, 게이트 사후 완화, 독립 최종 평가 실행, 운영 NER 교체·공용 서비스 코드 수정, 다른 에이전트 수정, PR 병합·푸시·배포, R12 이후 추가 학습 계획.
