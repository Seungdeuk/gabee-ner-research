# R11 비운영 이미지 검증 및 required 결정 반영 (2026-11-23)

표시: 자동 검증 기반 · 사람 검수 미실시 · **비운영(이 PC 로컬 Docker)** 결과. 운영 모델 교체·배포는 실행하지 않았다. 사전 등록 P1~P3 FAIL 과 `KEEP_S0` 는 변경하지 않는다. 증거: `r11_validation/ops_replacement/evidence/nonprod/`, 도구: `…/nonprod_tools/`.

## 1. 결정 반영(`PRIVACY_NER_MODE=required`)
| 결정 | 반영 상태 |
|---|---|
| 1. 이미지 기본값 `required` | **반영(패치 준비, 저장소 Dockerfile 미적용)** — `dockerfile_r11_ops.patch`. 검증용 R11 이미지는 이 패치 내용으로 빌드했고 이미지 안 `PRIVACY_NER_MODE=required` 를 확인 |
| 2. 운영 환경 변수 명시 | **담당자 작업 필요** — 운영은 Docker Compose 가 아니라 Cloud Run 서비스 `gabee`(2026-11-18 준비 자료 기준, 당시 `auto`). 새 리비전에 `--update-env-vars PRIVACY_NER_MODE=required`(**`--set-env-vars` 금지**, 기존 환경변수를 지운다). 명령은 `NER_R11_OPS_OPERATOR_COMMANDS.md` |
| 3. 실행 환경에서 required 적용 검증 | **추가함** — 컨테이너 안 `ner_status()` 확인 + 배포 전 게이트 |
| 4. `auto`·잘못된 값이면 배포 중단 | **추가함** — `apps/api/scripts/check_ner_deploy_mode.py`(시험 13개 통과). 설정에 `PRIVACY_NER_MODE` 가 `required` 가 아니면(`auto`·`off`·오타·빈 값·비밀 참조) 종료 코드 1. 모델 폴더·파일 덮어쓰기, 이미지 지문 불일치, 엔진 비활성도 차단. Cloud Run 설정에서 `PRIVACY_NER_*` 값만 읽고 다른 환경변수·시크릿은 읽지도 출력하지도 않는다 |
| 5. 실패 시 외부 전송 없음(실제 운영 조건) | **비운영 이미지에서 확인, 운영에서는 미확인(S4-3)** — 3절 |
`.env` 는 운영에서 쓰이지 않는다(로컬 개발 전용). 운영에 남아 있는 `auto` 환경변수가 이미지 기본값보다 우선하므로 게이트가 막는다.

## 3. 실패 차단(R11 이미지, `--network none`, 합성 이름·번호만, 소켓 연결 시도 횟수 측정)
| 시험 | 결과 | 외부 연결 시도 |
|---|---|---|
| 정상 | 가명화 통과, 지문 `3831601b7ffb` | 0 |
| 모델 폴더 비움 + required | **차단** `PrivacyUnavailable`(`privacy_unavailable`) | 0 |

마지막 줄이 `auto` 를 운영에서 막아야 하는 이유다. 연결 시도 0 은 이 시험의 진입점(가명화)이 막히거나 규칙으로 통과한 결과이며, **운영 Cloud Run 에서의 외부 호출 0건은 미검증(S4-3)**. 앱 레벨 입구별 503·호출 수 검증은 이전 보고(eval_workflows)의 비운영 결과와 같다.

## 4. 기동·롤백(비운영)
R11 이미지 기동 → `/health` 200(약 6.4초), 이미지 안 `MODE=required`, 해시·지문 일치. R11 컨테이너를 내리고 S0 이미지로 교체 → `/health` 200(교체 약 7.2초), S0 해시 `46210943…`·지문 `46210943c45f` 복귀. 시험 컨테이너는 모두 정리했다.

## 5. S2b(운영 환경 성능) — **여전히 UNVERIFIED**
컨테이너 측정 도구(`s2b_container.sh`, 이미지 안에서 g12 와 같은 방법·교차 순서)를 만들어 동작을 확인했다. 운영 CPU·메모리 제한, 스레드, 동시성 값을 아직 받지 못했으므로 **임의 제한(2CPU/2GB, 스레드 2, 동시 2)으로 한 점검은 `PLUMBING-ONLY` 이며 S2b 로 인정하지 않는다**(참고: p50 S0 ≈6.1 ms, R11 ≈6.1 ms, RSS ≈180 MB 로 같은 수준). 운영 값을 받으면 같은 스크립트를 그 값으로 실행한다.

## 7. 정책별 경로 구분과 위험
| 구분 | 경로 | 모델 교체 영향 | required 에서 NER 실패 시 |
|---|---|---|---|
| A NER 적용 | 가족채팅 분석·답장·주제·미리보기, 일정 에이전트 채팅, @가비 맥락, 주간 뉴스, quiz, 가계 질문·history | **효과 있음**(R11) | 503, 외부 호출 0 |

## 8. 배포 가능 여부
**배포 불가(추가 조치 필요).** 남은 것: ① 운영 담당자가 S4-1·S4-2·S4-6 값과 S2b 조건을 회신, ② 같은 조건 S2b 측정 통과, ③ 위험 수용 서명(운영 담당자·승인 책임자·보안 검토자), ④ 운영에 `required` 명시 후 게이트 통과, ⑤ Dockerfile 패치를 병합 대상 브랜치에 반영하는 PR(`release` 기준), ⑥ 사용자 최종 승인. 위 비운영 검증은 ①~⑥을 대체하지 않는다.
